# Changes and review

Change review lets users inspect the current workspace or recorded chat edits before taking an explicit repository action. These are different views: a workspace diff can include human, shell and other-chat changes, while a recorded edit is evidence captured from a particular provider operation. Neither view alone proves who authored every file modification. Keep the selected chat, workspace, host and comparison baseline visible and stable across refreshes.

[Checkpoints and rollback](../workspaces/checkpoints.md).

A new chat can capture its initial Git working-tree contents, including untracked files, before provider launch without changing the source index or branch. Chat changes compare current contents with that durable, workspace-and-host-bound baseline; an isolated Git worktree retains its explicit base comparison. Existing conversations without a valid original baseline report it as unavailable rather than inventing one. This comparison can include human or other-process edits made after capture and does not replace recorded provider edit receipts. The companion exposes only read-only saved-chat Git comparisons, without desktop commit or baseline-capture authority. The end-of-transcript **Changes from this chat** summary lists every file whose content or mode differs from that baseline, including files with no net line change, and each file opens its baseline patch in the [diff viewer](diffs.md). When the baseline is missing the summary says so rather than listing workspace changes; other read failures show the error with Retry. A read that fails outright, including an SSH host that drops or times out before or while its repository is detected, is such a failure: it keeps the summary visible with the error and Retry instead of reading as a workspace with no repository, no changes or another system's working-copy rows; a dropped or timed-out detection shows one fixed sentence and logs only the host and failure kind. A read refused only because the chat's workspace or host changed while it ran is stale rather than failed: the summary reads once more, and if that read is refused too it clears the earlier result instead of showing the race as an error. A chat whose remote host no longer exists is not such a race and shows its error with Retry. Capturing a baseline writes Git objects and one ref per chat under `refs/uam/chat-baselines/` in the user's repository (the index, branch and working tree are untouched). Remove them with `git for-each-ref --format='%(refname)' refs/uam/chat-baselines/ | xargs -n1 git update-ref -d`; the affected chats then report their baseline as unavailable. **Implementation note:** SVN workspaces have no chat baseline yet, so their summary is labelled **Working copy changes** and reflects the whole working copy. Touch review of the summary and diff viewer has not been verified on a device.
