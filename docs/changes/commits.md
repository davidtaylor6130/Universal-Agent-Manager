# Commit panel

The existing commit panel operates on the selected chat's workspace and chosen Git/SVN backend. Users inspect changes, explicitly select files and supply a commit message; generated message suggestions remain editable and do not commit anything by themselves. Validate current workspace and selected paths before mutation, preserve unselected changes and report uncertain or failed publication honestly. A Git commit, push, SVN commit and UAM checkpoint are distinct operations; the panel must not imply one authorizes another. Changing chats while work completes must not publish the old result into the new panel.

The panel's views are tabs with an icon each (Workspace, Recorded chat edits, History); a view gets no heading of its own, because its tab already names it. Inside Workspace one **Commit** heading band sets the commit form apart from the changed files above it, for Git and SVN alike. The changed-file list sizes to its rows and scrolls once full, with the Commit section directly below it; the description grows into spare height up to a capped size, and any remaining space falls below the form rather than between the list and the form. Commit is disabled until a file is selected and a summary is entered, and the selected count stays visible. Command output from the last commit stays in a collapsed native disclosure.

## History and update

When the active system declares them, the panel adds a **History** tab and an **Update** action; today only SVN does ([SVN](../settings/version-control/svn.md)), and Git shows neither. History is a list on a rail, newest first: revision, first message line, author and age, with text tags for the working copy's revision, revisions not updated yet and the copy that created a branch or tag. A main line is one rail. For a branch or tag, one line above the search field says where it was copied from (`Copied from trunk@r2870 · r2871`) and holds a List or Graph icon switch. Graph draws its origin on a left rail and itself on a right rail, their revisions interleaved by number down to the copy, where the rails join and the shared history continues on one rail; List is the working copy's own line. It opens on Graph, unless the user has already started reading the list or the origin is more than a page of revisions ahead. Nothing else about the origin is shown: no ahead or behind counts and no diff against it. Searching shows the working copy's own line as a plain list. The copy point loads on its own, so when it is slow or cannot be read History is simply the list. Opening a revision shows its full message and changed paths, and a changed file opens that revision's patch in the [diff viewer](diffs.md) without the current-file Inspect action. It loads 50 revisions at a time with **Load older revisions**, searches author, message and path on Enter, and never blocks the interface: a load shows a moving indicator with **Stop**, and leaving the tab, a new search or closing a patch stops the request in flight. A failed load shows the system's own error with Retry and keeps the revisions already listed. Update is refused while this chat, or any other chat whose workspace is or overlaps the same working copy, has a runtime working or another operation in progress, and those chats cannot start working until the update ends. It disables Commit and Refresh while it runs and offers **Stop**; a stopped update can be run again, after `svn cleanup` if the working copy was left locked. It then reports the revision reached, or that conflicts were left, and refreshes the changed files and history. The working-copy tag sits on the newest listed revision the working copy already has. It is not available to the phone companion.
