# GitHub Copilot CLI

GitHub Copilot structured Chat uses the native SDK server JSON-RPC protocol over framed stdio; CLI View retains the interactive Copilot CLI. Common behaviour is defined once in the [provider agreements](../providers.md); this checklist only records delivery and known limits. Native capabilities depend on the installed CLI, selected model and execution environment; shared UAM routes do not imply that every native variant is supported.

On Windows the Copilot CLI itself requires PowerShell 6 or newer (`pwsh`) and starts it for shell tools; stock Windows PowerShell 5.1 is not accepted upstream, so UAM's version check reports a missing `pwsh` as a Copilot prerequisite regardless of the [Editors](../../settings/editors.md) Terminal shell choice.

**Assessment:** source routes and retained verification evidence, 2026-10-17. Implemented is not live verification or David’s acceptance. Consult the [status definitions](../../documentation-rules.md#agreements-and-implementation) and [V5 log](<../../../V5 Improvement Change log.md>).

## Managed continuation

Within the current controller lifetime, an owned local read-only UserRoot child with an explicitly named model can continue its exact native conversation. The same running process must report SDK protocol 3 and a stable CLI version of at least 1.0.98. Both create and exact saved-session resume supply source-qualified built-in view/grep/glob filters, exclude MCP and custom tools, disable permission bypass and apply managed shell/write denies. Fresh native readback must confirm adopted managed permissions, the bounded tool surface and the exact session, workspace, model and Plan mode; Plan/model labels alone grant no authority. An initial binding additionally requires actual input, saved observations, completed result and confirmed process reaping. Resume needs fresh proof before input preparation and final delivery; ownership, configuration or policy drift permanently rejects that attempt even if earlier values return. Unsupported initial policy preserves a truthful unbound one-shot, while unsupported resume refuses input. The request policy targets native tool dispatch; operating-system filesystem isolation remains a separate boundary. Scoped source review covers this narrow tranche and its early-drift correction without a supported P0–P2 finding. Delivery remains Partial: broader provider/principal coverage, nesting, restarted execution ownership and SSH continuation remain incomplete, and live-provider, Windows and David’s user acceptance remain pending.

Native enforcement remains an unresolved assumption: the compatible CLI must enforce source-qualified built-in tools, MCP/custom exclusions and broad shell/write denies at dispatch, including servers that connect after metadata initialization. Readback corroborates tool names and managed-policy provenance, but does not attest each tool’s origin, inspect the opaque deny serialization or prove that late MCP tools remain excluded. Source approval and private protocol verification do not establish that native behavior. The exact bare shell/write deny pair follows the shared managed-rule vocabulary by inference; source-qualified built-in filters independently express the intended model-tool boundary. Fresh model/session or invalid policy events revoke the corresponding accepted current readback even while other required replies remain pending. Optional follow-ups on missing-scope resume handling, additional refusal coverage and worktree/path-alias acceptance remain pending. Those follow-ups are not resolved by this approval.
