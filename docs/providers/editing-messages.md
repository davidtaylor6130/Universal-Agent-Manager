# Editing messages

Editing an already delivered user message creates a branch from that point, preserving the original conversation and using the revised message in the new path. Editing a definitely unsent input changes that local input without claiming to retract a provider turn. Attachments and selected context must follow the edited input, and uncertain delivery must not be treated as definitely unsent.

Native local-edit eligibility is separate from the known-unsent delivery classification. The recovery Edit control stays unavailable when native save, runtime, recovery or dependent-branch state forbids changing that input; saving rechecks the same decision. If native history or edit eligibility changes while the editor is open, Save edit pauses and keeps the edit and selected context alongside the independent follow-up draft. An explicitly matching authored input can be selected again when local editing becomes available; when it is no longer classified as unsent, the user can explicitly move the edit into the existing branch flow, preserving the original. The recovered branch edit retains its selected input and owner through Save; native admission also checks the captured input identity and displayed history digest. A later source change refuses the branch and keeps the edit. No history refresh automatically saves, branches or retries input. A refused save keeps the edit and context. This does not confirm delivery or grant Retry, and ordinary follow-up sending keeps its own continuation checks.

While editing, the composer tab row shows an **Editing message** tab on the right (left of any side-chat tab) with a pencil and a Cancel edit button; Escape also cancels and restores the previous draft. The composer send button shows a pencil and reads **Save edit**; it and Enter save the edit under the same rules as sending. While editing, the edited message carries an accent outline and the messages below it dim; cancelling fades both away, and saving folds the messages below up into the edited message before the new reply arrives. Switching message branches with the counter swipes only the messages below the fork in the chosen direction ([Motion](../ui/motion.md)).

Files and skills are selected independently. Retained skills use their original captured prompt text and order; removing a skill removes its file reference and prompt snapshot together. Earlier conversation context stays intact. Explicitly removing all selected context differs from leaving the selection unchanged; a blank revised message needs a retained file or explicitly retained skill context. A selected skill whose captured prompt text is unavailable must be refused without changing the original chat. Saved history keeps a missing snapshot in its own slot, so a message with any missing snapshot refuses every explicit skill retention.

**Implementation: Partial** across providers: Implemented for Codex, Claude Code, OpenCode and Copilot, where unsupported recorded-source delivery refuses explicitly; Partial for Gemini and Antigravity, where native-original input delivery and provider continuation of a delivered edit are not yet established. Guarded local saves keep definitely-unsent input and its retained file and skill snapshots in the original chat. Delivered edits now retain independently selected files and captured skill context in the new branch, including explicit removal of all target skills when older snapshots are missing. Retaining unavailable skill snapshots refuses. Native-original input delivery, provider continuation and visual/platform acceptance still need verification. See the [archived V5 change log](https://github.com/davidtaylor6130/Universal-Agent-Manager/blob/1d4865fcb/V5%20Improvement%20Change%20log.md).

[Sending and recovery](../chat/sending.md).

When restored history or native edit permission changes during an unsent edit, retain the edit and selected context and pause Save. Report the change through the [shared warning notification](../ui/notifications.md), with authorized recovery actions in the bell panel and a paused explanation on Save, without a composer bar. Recovering, saving or cancelling resolves that notice; saving still rechecks native authority, and Cancel restores the independent follow-up draft.
