# Save and resume

UAM saves its normalised conversation and the provider’s native session identity when one exists. Resuming must reconnect the intended conversation without silently creating a different native session or replaying an already delivered prompt. A native limitation requires an explicit UAM continuation path or an honest unsupported result. Persisted chat history alone does not prove native resume, and multiple concurrent terminals must not guess each other’s session IDs.

Switching an existing chat to another provider keeps the saved UAM transcript and carries a bounded, newest-first projection of prior user and assistant text and compaction summaries (never tool actions) to the new provider once, on its first delivered turn in a fresh native session. In structured Chat that context is bound to the native session that received it, so later turns, reopening the chat or resuming that session must not resend it, and the previous provider's session is never resumed as the new provider's; switching again rebuilds it from the complete saved history. Held queued input is never dropped by a switch: a loaded held queue refuses the switch as active work, and a held queue not yet loaded stays held under the new provider. A queue-storage problem fails the switch and a pending Send makes it wait. A hold with no input and no uncertain remote delivery is released with the switch so the next Send is admitted, and removing the only unsent row ends its hold. Other holds stay. Removing the unsent row ends its hold. Once a runtime settlement clears uncertain remote delivery and nothing else is held, the next Send during a pending reset ends the hold; if no runtime remains to settle it, Send stays refused. At the next app start the hold is recomputed from queued prompts, so a hold kept only by an unsent row or uncertain delivery ends then. CLI View receives the same context through native context files rather than a synthetic prompt.

**Implementation note:** structured handoff is implemented for all six providers through the shared prompt builder. Stream-JSON routes that learn their native identity only after the first input (Claude Code, Antigravity) bind the delivered context when that identity arrives, and a first turn that ends before any identity leaves it unbound for the next session. A switch also marks the native session as reset so legacy chats whose UAM ID doubled as a native ID do not resume the previous provider's session after reload; the switch and remote workspace moves release a hold with no input with that reset and keep any other hold, and any native identity link completes the reset. Rules for refusing a switch while unsent or uncertain input remains are an open decision. Focused native regressions cover these routes and a Gemini-to-Codex switch. CLI View is Partial: it rewrites the context file on every launch for every provider except Codex, including when resuming a session that already received it, and Antigravity CLI View refuses any switched chat because its saved context is never cleared. Live provider-pair recall, every pair permutation and SSH acceptance remain unverified ([#376](https://github.com/davidtaylor6130/Universal-Agent-Manager/issues/376)).
