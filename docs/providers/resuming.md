# Save and resume

UAM saves its normalised conversation and the provider’s native session identity when one exists. Resuming must reconnect the intended conversation without silently creating a different native session or replaying an already delivered prompt. A native limitation requires an explicit UAM continuation path or an honest unsupported result. Persisted chat history alone does not prove native resume, and multiple concurrent terminals must not guess each other’s session IDs.

Switching an existing chat to another provider keeps the saved UAM transcript, the chat's [permission level](permissions/permissions.md#a-chats-permission-level) and memory setting, takes model, reviewer model, reasoning, speed and small model mode from the new provider's defaults, turns Computer Use off, and carries a bounded, newest-first projection of prior user and assistant text and compaction summaries (never tool actions) to the new provider once, on its first delivered turn in a fresh native session. In structured Chat that context is bound to the native session that received it, so later turns, reopening the chat or resuming that session must not resend it, and the previous provider's session is never resumed as the new provider's; switching again rebuilds it from the complete saved history. A state the user can clear refuses the switch and a state the user cannot clear warns instead. A CLI confirmed not installed refuses the switch and says so; a version check that failed or timed out does not refuse it, and the dialog notes the failed check neutrally. Input with a reachable Resume, Retry or Remove control refuses the switch: the provider rail names the reason while it is locked, and the dialog shows any refusal the native side returns. A pending Send makes the switch wait, and ordinary active work stays locked until it is stopped. A message whose delivery is uncertain warns instead, including a remote turn whose host cannot be reached and held input with no reachable control; an unsent row counts only while delivery is uncertain or a turn is active, because that is when it has no Remove control. The dialog says the prompt may run twice and offers Switch anyway, while Cancel leaves everything unchanged. Only that explicit choice lets the switch through, and a refusal above still wins. Accepting gives up the unconfirmed turn: its rows are settled as interrupted and an active goal is blocked, which the warning says. Held input with no control is not sent, and its text stays in the chat as an unsent message unless it already has a row. If a helper process may still be running on the host, whether or not there was a warning, UAM attaches only to stop it when the host answers and retries if the stop goes unconfirmed. That attach does not depend on the new provider being enabled, the old provider's output is discarded, input still queued behind it stays held for Resume or Remove, and a further switch needs no second warning. The chosen model still applies during that stop, and a chat move continues it because the runner slot follows the chat. Automatic routing does not gate the stop, and the assignment is updated for the new provider; the first Send after it reaches the new provider on the routed computer. Limits remain. A host that never returns leaves Send refused, because the old process still owns that chat's slot there, although the provider can still be changed once any held queued message is removed; Resume waits for that stop. Deleting the chat also stays refused until the host answers. A queue-storage problem stays refused, and with no repair control the reason says to restart UAM so the saved queue is read again. The iOS client has no Switch anyway control: it shows the reason where it can reach the request, and shows no reason during a disconnected recovery because its controls are disabled while the chat is processing. A switch releases a hold with no held input, so the next Send is admitted. Removing the only unsent row ends its hold. A chat move or remote folder directory change is refused on held or unsent input and on an uncertain not-sent row, and otherwise keeps a hold while delivery is uncertain; once a runtime settlement clears that uncertainty and nothing else is held, the next Send during a pending reset ends the hold; if no runtime remains to settle it, Send stays refused until the next app start recomputes the hold from queued prompts or a provider switch gives the turn up. CLI View receives the same context through native context files rather than a synthetic prompt.

**Implementation note:** structured handoff is implemented for all six providers through the shared prompt builder. Stream-JSON routes that learn their native identity only after the first input (Claude Code, Antigravity) bind the delivered context when that identity arrives, and a first turn that ends before any identity leaves it unbound for the next session. A switch also marks the native session as reset so legacy chats whose UAM ID doubled as a native ID do not resume the previous provider's session after reload; the switch and remote workspace moves release an empty queue hold with that reset and refuse while held input remains, an accepted uncertain-delivery switch clears the saved remote turn markers, every switch away from a helper with no attached transport retires it through the existing confirmed-stop cleanup before a new launch, and any native identity link completes the reset. While the retry transport of a disconnected recovery is connecting, the switch is briefly ordinary active work. Focused native regressions cover these routes and a Gemini-to-Codex switch. CLI View is Partial: it rewrites the context file on every launch for every provider except Codex, including when resuming a session that already received it, and Antigravity CLI View refuses any switched chat because its saved context is never cleared. Live provider-pair recall, every pair permutation and SSH acceptance remain unverified ([#376](https://github.com/davidtaylor6130/Universal-Agent-Manager/issues/376)).
