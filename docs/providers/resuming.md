# Save and resume

UAM saves its normalised conversation and the provider’s native session identity when one exists. Resuming must reconnect the intended conversation without silently creating a different native session or replaying an already delivered prompt. A native limitation requires an explicit UAM continuation path or an honest unsupported result. Persisted chat history alone does not prove native resume, and multiple concurrent terminals must not guess each other’s session IDs.

Switching an existing chat to another provider keeps the saved UAM transcript and carries a bounded, newest-first projection of prior user and assistant text and compaction summaries (never tool actions) to the new provider once, on its first delivered turn in a fresh native session. In structured Chat that context is bound to the native session that received it, so later turns, reopening the chat or resuming that session must not resend it, and the previous provider's session is never resumed as the new provider's; switching again rebuilds it from the complete saved history. CLI View receives the same context through native context files rather than a synthetic prompt.

**Implementation note:** structured handoff is implemented for all six providers through the shared prompt builder. Stream-JSON routes that learn their native identity only after the first input (Claude Code, Antigravity) bind the delivered context when that identity arrives, and a first turn that ends before any identity leaves it unbound for the next session. A switch also marks the native session as reset so legacy chats whose UAM ID doubled as a native ID do not resume the previous provider's session after reload; any native identity link completes the reset. Focused native regressions cover these routes and a Gemini-to-Codex switch. CLI View is Partial: it rewrites the context file on every launch for every provider except Codex, including when resuming a session that already received it, and Antigravity CLI View refuses any switched chat because its saved context is never cleared. Live provider-pair recall, every pair permutation and SSH acceptance remain unverified ([#376](https://github.com/davidtaylor6130/Universal-Agent-Manager/issues/376)).
