# Provider subagent history

Provider-created subagents appear as related activity with their original tool details. Where a native child session is addressable, UAM should open its conversation and refresh it without overwriting active work or resurrecting deleted children. If only tool-call details are available, show those honestly rather than inventing a complete transcript. Recognition alone does not establish that spawning, approvals and child history are fully implemented.

The expected parent/child interaction follows the [T3 alpha 0.1.0 reference](../chat/subagents.md), using UAM’s design language; transcript recognition alone does not satisfy that full workflow.

Launch activity follows the [ordered subagent placement agreement](../chat/subagents.md#launch-placement); exact accepted managed-run correlation is presentation evidence, and unavailable/deferred launch results remain explicit rather than guessed. Shared inline presentation remains pending source integration, review and runtime acceptance.

[Current provider evidence](../reference/provider-runtime-parity.md#structured-interaction).

A parent-owned agent journal can be opened as a read-only UAM transcript even when the native agent has no resumable session ID. Its reference must retain the exact provider, parent, agent and execution host, and must never be stored as a provider resume identity. Missing native tool-to-child correlation remains explicit rather than inferred from names or timestamps.

When a refresh refuses a shorter native child history, the child conversation must explain that saved history was retained and remains readable. A refresh can succeed when the complete native history for that same child is available and the existing identity, ownership and save checks pass; repeating a refresh against the same shorter source cannot replace the saved transcript. If the pane has no loaded messages after a refused refresh, it must attempt a bounded saved-history read in place, keep the refusal visible and adopt a page only while the same child, parent and read request remain current. Explicit Refresh must show its current failure even if an earlier error notice was dismissed. Count-only saved-history reads must retain the same native-refusal explanation. If saved-only recovery also fails, say that retained history could not be read this time rather than claiming the provider supplied no transcript; native-refusal feedback must not inherit diagnostics from that separate saved read. A known passive child refresh must reject a different returned chat before recording lineage or reading that other chat. This passive read does not refresh the provider, retry input or grant execution authority. A normal saved-history reopen also remains available without repairing or reconstructing the native source. Unknown native or transport errors use plain-language primary copy with bounded, secondary technical details.

**Current scope:** Gemini passive child history, controller-local or on an SSH host, explicitly refuses a shorter source and supplies this guidance. The existing generic non-Gemini routes and remote saved-owner refresh routes silently retain fuller saved history and report success; this task preserves that contract and adds no general six-provider refusal or new refresh authority.

Gemini child opening and explicit refresh, controller-local or through the executing SSH host's helper, must retain inline image originals under the exact passive transcript owner and origin host, preserving user-message and tool-result associations. Saved UAM organisation remains intact while an explicit refresh imports the actual native conversation; organisation timestamps do not authorize replacing it with older saved messages. A saved non-refresh reopen must remain readable after native source retention removes the original journal. Saved recency follows the shared [refresh metadata rule](../chat/native-imports.md#refresh-metadata-recency). Read-only history gains no resume, message, approval or process-control authority; failed or stale publication retains prior content, and a shorter readable native snapshot must not discard fuller saved child history. If final save confirmation is uncertain after commit, retain the conversation and originals and show a shared application warning. Cancelling an open or refresh follows the shared [delivery-only cancellation rule](../chat/native-imports.md#refresh-query-cancellation).

A Gemini parent's sidebar menu offers Subagent conversations, a read-only list of the child journals stored under that exact parent session, locally or on its SSH host through that host's helper. Gemini's live ACP stream omits child IDs, so the user chooses a row rather than UAM linking a tool call to a child: titles and times label and order rows and never select a child. A row appears only when its journal is filed under the attested parent, names itself as the file's session, records kind subagent and lists the parent's workspace; journals that fail these checks, or exceed the single-read limit, are counted as unreadable rather than shown. Opening a row uses the exact child reader and its existing checks. A reference this app run listed also records the display link to its parent, because no tool call can name the child; that link grants no resume or control authority. The list is bounded, newest first, and says when not every saved conversation is shown. Reads use the directory the parent actually ran in, including its worktree. An older SSH helper without this request asks for a helper update. Deleting a child's saved copy leaves its native journal listed, so a later explicit open imports it again.

Codex child threads use their returned native thread ID. Local history reads the matching active or archived rollout; SSH history uses the executing host's native thread reader and validates the returned thread and workspace. Both retain rich conversation content. A collaboration tool with several native receivers retains every validated child and its reported state in live and saved history, and the grouped child view offers each conversation separately. Child state is not inferred from the parent tool’s completion. An authoritative parsed receiver list, including an empty or rejected list, must not be repopulated from older saved child links; detail reconciliation under unknown chronology requires the same native conversation, unchanged message fields, an unambiguous invocation and a matching recorded operation without replacing conflicting tool input, output or UAM task facts.

UAM-authored initial-launch annotations survive retained local history. Native history reconciliation, including row regrouping, preserves them only when authored content and a nonempty created-at value identify exactly one user row in each history. Native parsers do not synthesize them, and ambiguous or replaced row identities remain unbound with Sidebar navigation available. Portable message metadata does not grant execution or control authority; all managed cards and actions still require the current root-scoped native list.
