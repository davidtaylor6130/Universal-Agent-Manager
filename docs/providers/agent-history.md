# Provider subagent history

Provider-created subagents appear as related activity with their original tool details. Where a native child session is addressable, UAM should open its conversation and refresh it without overwriting active work or resurrecting deleted children. If only tool-call details are available, show those honestly rather than inventing a complete transcript. Recognition alone does not establish that spawning, approvals and child history are fully implemented.

The expected parent/child interaction follows the [T3 alpha 0.1.0 reference](../chat/subagents.md), using UAM’s design language; transcript recognition alone does not satisfy that full workflow.

Launch activity follows the [ordered subagent placement agreement](../chat/subagents.md#launch-placement); exact accepted managed-run correlation is presentation evidence, and unavailable/deferred launch results remain explicit rather than guessed. Shared inline presentation remains pending source integration, review and runtime acceptance.

[Current provider evidence](../reference/provider-runtime-parity.md#structured-interaction).

A parent-owned agent journal can be opened as a read-only UAM transcript even when the native agent has no resumable session ID. Its reference must retain the exact provider, parent, agent and execution host, and must never be stored as a provider resume identity. Missing native tool-to-child correlation remains explicit rather than inferred from names or timestamps.

Controller-local Gemini child opening and explicit refresh must retain inline image originals under the exact passive transcript owner, preserving user-message and tool-result associations. Saved UAM organisation remains intact while an explicit refresh imports the actual native conversation; organisation timestamps do not authorize replacing it with older saved messages. A saved non-refresh reopen must remain readable after native source retention removes the original journal. Saved recency follows the shared [refresh metadata rule](../chat/native-imports.md#refresh-metadata-recency). Read-only history gains no resume, message, approval or process-control authority; failed or stale publication retains prior content, and a shorter readable native snapshot must not discard fuller saved child history. If final save confirmation is uncertain after commit, retain the conversation and originals and show a shared application warning.

Codex child threads use their returned native thread ID. Local history reads the matching active or archived rollout; SSH history uses the executing host's native thread reader and validates the returned thread and workspace. Both retain rich conversation content. A collaboration tool with several native receivers retains every validated child and its reported state in live and saved history, and the grouped child view offers each conversation separately. Child state is not inferred from the parent tool’s completion. An authoritative parsed receiver list, including an empty or rejected list, must not be repopulated from older saved child links; detail reconciliation under unknown chronology requires the same native conversation, unchanged message fields, an unambiguous invocation and a matching recorded operation without replacing conflicting tool input, output or UAM task facts.

UAM-authored initial-launch annotations survive retained local history. Native history reconciliation, including row regrouping, preserves them only when authored content and a nonempty created-at value identify exactly one user row in each history. Native parsers do not synthesize them, and ambiguous or replaced row identities remain unbound with Sidebar navigation available. Portable message metadata does not grant execution or control authority; all managed cards and actions still require the current root-scoped native list.
