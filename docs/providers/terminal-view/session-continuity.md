# Terminal session continuity

A terminal binding identifies the exact native conversation owned by that UAM chat across terminal close, reconnect and application restart. Do not discover ownership by taking an arbitrary recent session from the same workspace, especially when terminals run concurrently. Retained terminal snapshots must not prevent unrelated native refresh, branching or managed preparation, and closing the last terminal using a history directory must release its unconsumed results. A failed binding save must not launch a replacement conversation under the old identity. Native transcript import and UAM history preservation are separate from proving that subsequent terminal input reaches the same native session.

Closing a terminal can leave a background history import pending. Final reconciliation must read the source after confirmed process exit, retain the exact chat and launch ownership through publication, and preserve newer UAM work. Pending preparation is not a saved-history acknowledgement; failure must retain the native source and prior saved content for retry. Settings and organisation changes must survive reconciliation; an unloaded chat without an original content witness defers its metadata save with a retry message until final history settles. A workspace move must settle the captured history under its original workspace before changing that ownership. Application shutdown must settle or cancel this work before releasing publication authority, promptly cancelling a final import whose process stop remains unconfirmed.

Native reconciliation follows the [shared history recency policy](../../chat/native-imports.md#history-recency), with legacy timezone assumptions and verification limits retained.

**Implementation: Partial.** OpenCode has explicit native session creation, and Codex uses exact native status replies for first-terminal identity. Bound Gemini, Claude and Copilot transcripts have exact local and SSH refresh routes; Antigravity native history export remains unavailable, and live continuation across providers still needs acceptance. See the [recorded evidence](../../reference/provider-runtime-parity.md#chats-and-persistence).
