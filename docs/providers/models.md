# Models

Model discovery and selection belong to the chosen provider and execution environment. Show real advertised or explicitly configured models, retain the selected model during refresh, and distinguish cached choices from confirmed availability. A selection must reach the running or next-started session as appropriate; unavailable models produce an actionable error instead of silently selecting another. Provider/model changes must not leak another chat’s selection. In an existing chat’s model picker, Refresh or Retry requests models for the provider and environment being viewed while retaining cached choices, the current selection and the search. Request acceptance does not establish a completed catalogue refresh. Older discovery replies must not replace the selector state of a changed chat or environment; retiring a selector does not cancel a request or authorize retrying input.

Model picker rows show separate Context and Output token-capacity badges from the model's reported context-window and maximum-output limits, including an explicit reported zero. Missing or invalid limits say unknown; defaults, configured choices and unavailable favourites must not borrow another model's limits. Favourites use the same provider, execution-host and workspace scope as ordinary rows. Compact counts retain exact token values in the row's tooltip and accessible text without repeating capacities in the focused tooltip's accessible description; disabled choices retain descriptions and exact limits in their accessible label and native hover label, with no simultaneous shared Tooltip, when narrow rows hide descriptions. Token capacity is separate from physical model size or parameter count: physical size stays not reported unless a supported source supplies it, and UAM never infers it from capacity, model names or identifiers.
