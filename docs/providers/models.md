# Models

Model discovery and selection belong to the chosen provider and execution environment. Show real advertised or explicitly configured models, retain the selected model during refresh, and distinguish cached choices from confirmed availability. A selection must reach the running or next-started session as appropriate; unavailable models produce an actionable error instead of silently selecting another. Provider/model changes must not leak another chat’s selection. In an existing chat’s model picker, Refresh or Retry requests models for the provider and environment being viewed while retaining cached choices, the current selection and the search. Request acceptance does not establish a completed catalogue refresh. Older discovery replies must not replace the selector state of a changed chat or environment; retiring a selector does not cancel a request or authorize retrying input.

## Queued setting preparation

Before dispatch, UAM prepares the admitted input’s effective model and mode in that input’s own idle runtime. Its matching raw queue must not make that preparation reject itself; saved choices may be deferred, but manual mutation of a busy native session remains blocked. Foreign queues, active native turns, permission waits and pending setting negotiations remain barriers, and captured read-only policy continues to limit the turn. Reasoning still follows the provider’s existing per-turn or restart requirement. For launch-configured native models, selecting Default removes an earlier explicit launch override at the next idle admission; a reported resolved default model is not an explicit launch selection. If a reattached launch choice cannot be confirmed, queued input remains retained through an owned idle restart. Local and remote settings restarts retain both runtime and durable raw input throughout teardown; a preparation or replacement-launch refusal restores the raw head and holds the queue for recovery. Native streams that obtain their session identity from the first input retain that supported startup route. Existing internal continuation controls retain their separate invocation ownership and future user queue; they do not acquire ordinary raw-queue admission.
