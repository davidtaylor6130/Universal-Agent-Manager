# Provider attachments

Explicit [file, branch and worktree snapshots](../chat/composer/attachments.md) are UAM-supplied quoted text with authored composer messages for all six structured providers, rather than native attachment blocks or permission-bearing paths. Their capture metadata remains historical context; native input identity and delivery observations still come from the existing send service. This shared source-implemented text route does not resolve native attachment limitations or substitute for verification of [David's goal/plan action-send contract](../documentation-review.md#referenced-context-action-sends); native/runtime verification and acceptance remain separate.

Files and images attached to a message must reach the intended provider session in a representation it can use, with their names and relationship to the message preserved. Remote execution requires delivery to the remote environment rather than a controller-only path. UAM should supply an equivalent where possible; if an image or file cannot be consumed, report that limitation without silently dropping it or claiming visual understanding from its filename.

[Composer attachments](../chat/composer/attachments.md).

Native image delivery uses only the current dispatched user-message range, including merged input; it never reattaches earlier images. Image preparation is bounded and cancellable, and remote bytes come from a scoped binary helper reader rather than opening the remote path on the controller. Unsupported provider vision or an older helper reports an explicit outcome.

Native history must retain inline originals and their message/tool association through save and refresh. Provider URIs remain opaque references unless separately authorized bytes are available; a URI is never treated as a local path. Unsupported previews or bounded preparation failures must be explicit without turning attachment-only history into an empty chat or overwriting prior saved content.

Reusing recorded history as new input must preserve its source identity: send validated original bytes through a supported route for the selected provider and host, or reject the request explicitly before sending its remaining text. Preview metadata, opaque URIs and native asset keys do not grant file-path authority, and must not be silently converted into ordinary attachments.

Controller-local Claude and Codex saved-history Retry can deliver retained PNG, JPEG, GIF and WebP originals from the selected user message, including originals retained by a branch, through native image blocks or data URLs. The complete attachment selection must remain unchanged through preparation and delivery; other recorded-source or host combinations require an explicit supported route or refusal. Ordinary Send does not inherit this saved-message authority.

Claude, Codex and negotiated-image Gemini saved-history Retry over SSH may deliver only the selected owner’s retained PNG, JPEG, GIF and WebP originals on the same existing ready native process; these adapter routes have focused private matching-helper verification. The complete image-only row, selected host connection, native session, process, delivery token and execution settings must remain unchanged through preparation and durable admission; legacy paths, opaque references, missing originals and changed authority refuse the whole request. Benign display or health metadata must not invalidate an otherwise unchanged invocation, and captured skill instructions remain captured. Cold or replacement-process remote Retry remains an explicit implementation gap; an unavailable saved-image route must refuse before creating a goal or acquiring runtime ownership and preserve held input, workspace and native identity. An SSH queue containing retained originals stays held unless its exact saved row, queue receipt and current Retry invocation are revalidated; generic Resume does not recreate that invocation. Ordinary Send gains no saved-message authority.

Controller-local Gemini saved-history Retry and fresh edited-branch regeneration deliver retained PNG, JPEG, GIF and WebP originals through ACP image blocks only after the current native session negotiates image support. A known unsupported running session refuses before admission; a new process negotiates before preparing delivery, and changed session, process, model or mode evidence invalidates prepared input. ACP capability establishes an input contract rather than backend visual understanding.

Copilot saved-history Retry on the controller or the same existing ready SSH process uses native image blobs only after the running SDK server and explicitly selected current model confirm vision support. PNG, JPEG and GIF form the baseline; WebP requires reported support, and any reported restrictions apply to the actual prepared images. Remote input additionally requires SDK protocol 3 and a stable server version of at least 1.0.98, with the captured connection, process and host workspace unchanged through delivery. Missing or contradictory evidence refuses the complete request; cold or replacement-process remote input remains unavailable, and native acceptance still does not establish visual understanding.

OpenCode saved-history Retry must confirm image support for the acknowledged current model through its owned native companion before reading originals. The same process, model, settings and saved-message authority must remain valid through delivery; failed image checks refuse the whole request without changing permission approvals. The current local route covers ordinary ACP prompts and retained PNG, JPEG, GIF and WebP originals; commands, remote originals and sessions without an admitted companion remain explicit gaps. Native configured support does not establish backend visual understanding.
