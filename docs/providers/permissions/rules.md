# Permission rules

Permission rules are the user's own allow, ask and deny list, checked locally and instantly for structured permission requests before any automatic approval or AI review. They run after the checks that already settle a request without UAM: provider-required decisions (including Plan exit and recognized non-action questions) and the Plan or captured read-ceiling rejection, and they never see approvals a provider answers itself, such as OpenCode V2's remembered “allow this exact action for this session” grants. Each rule names an action, what it applies to (a shell command matched by pattern, read-only work, file edits, web access, other tools or any request) and optionally one provider and one workspace folder given as a full path, which also covers everything inside it; a worktree chat matches rules for its source folder and the chat's own folder as well as the worktree. Deny wins over ask and ask over allow, whatever the list order. A deny answers once with the offered rejection (Cancel when none is offered). An ask leaves the request for the user under every permission level, YOLO included, and no AI review runs for it. A rule never grants a persistent or session-wide choice.

## Remote commits always ask

By default every non-local permanent committing action that reaches UAM as a typed shell command waits for the user's explicit approval under every permission level, YOLO included. A built-in ask rule, which is not stored in the rules list and cannot be removed or edited there, holds:

- **Git:** `git push` with any options or refspecs, which covers force pushes and creating or deleting remote branches and tags; command-line aliases (`git -c alias.…`); `send-pack`, `svn dcommit`, `p4 submit`, `subtree push` and `lfs push`; the same through `git-*` programs (`git-push`) and `hub`; and any Git subcommand UAM does not recognise as local, which may be an alias from the user's Git configuration.
- **GitHub CLI:** `gh pr merge` (also with flags before `merge`), `gh pr close --delete-branch`, `gh repo sync`, `gh repo create --push`, `gh release create` and `delete`, `gh api` calls that change something (any method other than GET, or fields or an input body without an explicit GET), and any `gh` command it does not ship, which may be an alias or extension.
- **Subversion:** `svn commit`/`ci` and `import`; `svn copy`/`move` to a repository URL or `^/` path; `svn mkdir`/`delete` on one; `svn propset`/`propdel`/`propedit` with `--revprop` or on a URL; any `svn` subcommand it does not recognise; every `svnmucc` operation; `svnrdump load`; and `svnsync`.

It looks through the same chains, wrappers (including `call` and `wsl`), shell strings and expansions as other rules, plus `git submodule foreach`, `git bisect run`, `git rebase --exec` and `git difftool --extcmd`; an expanded subcommand or URL, or `git` or `svn` fed arguments by `xargs`, asks too. Because the built-in rule is always on, a command whose program UAM cannot read (`$CC -o x x.c`) or that exceeds the analysis limits now waits for approval even with no rules of your own, with a notice that it cannot rule out a push. Local work is unaffected: `git commit`, local branches and tags, fetch and pull, `svn update`, `svn revert`, and working-copy `svn copy`/`move`/`mkdir`/`delete` (including copying from a URL into the working copy).

While such a request waits, the approval card shows one line, normally “Pushes, merges and other remote commits always wait for your approval.” A user deny rule still wins, and a user allow rule cannot approve these. A hidden advanced setting, the settings-file key `permission_remote_commits_without_approval=1` (off by default and not shown in Settings), turns the built-in rule off and restores the chat's permission level for these actions; the Settings page then still shows the locked row, but its tester reflects the override.

Limits: the rule sees only typed shell commands the provider asks UAM about. MCP tool calls that merge, push files or change branches, provider-native auto modes, sandboxed commands that need no approval, CLI View terminals, and pushes started indirectly (a Git hook the agent wrote, `core.sshCommand`, `git fetch --upload-pack`, a script file) are outside it. David set this rule on 2026-11-23; see the [recorded decision](../../documentation-review.md#remote-commits-always-ask).

## Allow rules and matching

Rules only narrow. An allow rule takes effect only under [AI Review](ai-review.md), where it stands in for the reviewer's one-time approval and skips the model; it can approve only what the reviewer itself could have approved, so high-risk requests, Plan and [captured read restrictions](permissions.md#captured-read-restrictions), provider-required decisions, native reviewers, edits outside [Accept Edits' scope](auto-accept.md) and incomplete or sensitive-looking input still go to the user. Under Default and Accept Edits an allow rule does nothing, and YOLO already approves. Allow rules can target only commands, read-only work and workspace file edits, and an allow command pattern must start with a program name. Read-only work admitted by the literal read filter never skips review through a rule when it names something credential-like, such as `.env`, `.ssh` or a key file.

A command pattern is shell-quoted words matched from the program name: `*` and `?` match inside a word, `[...]` is a character class and `**` spans any number of words, so `git ** push ** --force*` also covers `git -C repo push origin main --force-with-lease`. An allow pattern matches only one plain command from its first word: chaining, pipes, redirection, substitution (`$( )`, backticks), variables (`$X`, `%X%`), globs, leading assignments and paths such as `./npm` never match, so `npm test; rm -rf /` cannot ride an allowed `npm test`. Because a provider may run commands through cmd.exe or PowerShell, which do not share POSIX quoting or comments, a command containing `;`, `&`, `|`, `<`, `>`, parentheses, `$`, a backtick, `%` or `!` anywhere, even quoted, never matches an allow rule. Deny and ask patterns look everywhere a program can start: after `;`, `&&`, `||` and pipes, inside substitutions and `bash -c`, `cmd /c` or `eval` strings, and behind wrappers such as `sudo`, `env`, `xargs`, `timeout` and `find -exec` (after a wrapper every later word is treated as a possible program, so unknown wrapper options cannot hide one), inside command-line git aliases (`git -c alias.x=…`), comparing the program name without its path, case or `.exe`/`.cmd`/`.bat`/`.ps1`, comparing arguments without case and with `\` read as `/`, and also reading the command with its quotes and escapes removed so operators that only POSIX quoting hides still count. `cmd /c` (including `cmd /crm`), PowerShell `-Command`, `iex` and `Invoke-Expression` strings are checked like the commands they run, and vertical tabs, form feeds and no-break spaces count as separators. A literal argument matches definitely; an argument the shell expands (a glob, a variable such as `$E` or `%E%`, or a substitution) only possibly, when what it could become overlaps the pattern, and a possible match of a deny or ask rule holds the request for the user rather than denying it. So `cat /etc/*shadow`, `cat ~/.ss$E/id_rsa` and `git pus? --force` wait for the user, and under the defaults any command with a variable or glob argument that could reach a `.env` name (`cat *`, `echo $HOME`) does too. `~` and braces without a list (`{}`, `HEAD@{1}`) are literal text. A brace list such as `{a,b}`, a program whose name is only known at run time (`$TOOL`, `$(echo rm)`, `r* -rf`, `{rm,-rf,x}`), PowerShell `-EncodedCommand` and `Invoke-Command` script blocks, or a command that does not parse or exceeds UAM's analysis limits (64 KiB, 128 words per command, 4,096 words or 512 program positions in all), is left for the user whenever any deny or ask command rule applies. A request without a typed command gives command rules nothing to read: they neither hold nor deny it, while any-request rules still apply. Rules match the typed native command and the provider's structured tool kind, never display text.

New installations and settings files written before rules existed start with defaults: read-only work is allowed (it skips AI review); deletion (`rm`, `rmdir`, `unlink`, `shred`, `find -delete`, `del`, `erase`, `rd`, `Remove-Item`, `ri`) and `.env`, `.env.local`, `.env.production` and `.env.development` files always ask; and force pushes, SSH and AWS credential files, macOS keychain password reads, `git credential` and `gh auth token` are denied. Because ask outranks YOLO, a YOLO chat now asks for these commands, and for commands whose glob or variable arguments could reach a `.env` file, such as `cat *` or `echo $HOME`; see the [open decision](../../documentation-review.md#permission-rule-defaults-under-yolo). Users can edit, disable or remove any default; an emptied list stays empty. A saved list that cannot be read falls back to the defaults, and invalid entries are dropped; both are reported as a settings load warning.

Under AI Review, requests no rule decides go to the reviewer only while **Ask the AI reviewer** is on; turned off, they wait for the user. Within one app run, an approve or deny verdict for a typed shell command is reused for a later call with the same command, tool input (sandbox flags, working directory and other fields), title, reviewer provider and model, chat provider, ceiling and workspace; only per-call request and tool-call ids may differ; Codex requests, whose payload can carry grant roots or permission changes, and other tools are never reused. Uncertain and failed reviews are not reused, eligibility is checked again before every reuse and delivery, the cache is cleared when rules or the switch are saved and is never saved or logged, and a rule added while a review runs is applied instead of its verdict.

Rules apply on every structured route that delivers permission callbacks to UAM: Claude Code, Codex, Gemini, OpenCode V1 and V2, and Copilot. Antigravity's headless route answers its own prompts and gives UAM no callback, so rules cannot act on it; CLI View terminals remain provider-controlled.
