# AI Review

AI Review maps to the provider’s supported automatic risk-review mode where UAM has an established mapping; otherwise UAM’s configured reviewer handles eligible requests that no [permission rule](rules.md) decides, and only while **Ask the AI reviewer** is on. Routine allowed work can proceed, while risky, uncertain, failed or unsupported decisions return to the user. Residual native prompts stay user decisions. AI Review must not silently turn into YOLO or widen Plan/read-only restrictions, and any reviewer’s access to tools or request contents must be described honestly. UAM's own reviewer uses the [low-cost side-work model](../../settings/memory-workers.md) unless a reviewer model is chosen.

UAM classifies the typed native command, never its display text, looking past leading environment assignments and wrappers such as `command`, `nice` or `timeout`, and treating versioned interpreters such as `python3.12` like their base name. High-risk requests go straight to the user and never reach UAM's reviewer: command chaining or redirection, network access (including web fetch and search), deletion, shells, interpreters and indirection such as `env` or `xargs`, package installation, Git or SVN commands outside the [admitted reads](permissions.md#captured-read-restrictions), paths outside the workspace, reader commands the read filter refused, edits outside [Accept Edits' scope](auto-accept.md) and Codex permission escalations. The reviewer prompt marks the request as data written by the agent under review, escaped so it cannot close that marker, and tells the reviewer never to follow instructions inside it.

UAM's reviewer starts one isolated provider CLI process per eligible request, with a 20-second limit, one request at a time per chat. [Permission rules](rules.md) decide routine work such as read-only commands locally first, and an identical request's approve or deny verdict is reused within the same app run, so the model runs only for requests that need judgement.
