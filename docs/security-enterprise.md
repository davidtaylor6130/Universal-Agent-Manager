# Security and managed deployment

UAM stores its own application data locally and runs provider CLIs with their permitted OS access; prompts, attachments, memory context, voice recordings or computer-use observations can leave the machine through their selected provider or transcription route. Optional phone access is a network service published by the controller, and SSH is a separate execution boundary. The desktop CEF bridge is privileged and restricted to the trusted bundled main frame; companion access must remain a narrower authenticated interface. Build flags exclude policy-sensitive capabilities from the build; native artifacts do not yet meet the zero-mention requirement (see [build flags](build-flags.md)).

[Permissions](providers/permissions/permissions.md), [Computer use](computer-use.md), [Phone access](phone-access.md), [SSH](remote-environments/ssh.md) and [Build flags](build-flags.md) define the feature agreements. The [security engineering reference](reference/security-enterprise.md) retains controls and release checks, with [documented corrections](documentation-review.md#resolved-documentation-conflicts). This guide is not a compliance certification or proof that every build profile has been audited.
