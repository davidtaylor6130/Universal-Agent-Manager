| Automatic quota claim and settlement | Ready usable local or owned SSH transport, or absent/stopped runtime passing the scheduler's existing checks. `StageQuotaClaim` captures exact quota/native/agent/configuration, full active small-model goal scope even without a runtime, accepted input, live/raw FIFO, runtime identity, writer and pending controls before one full-save-authorized attempt; a missing goal scope cannot authorize claim or settlement. It retains the configured setup timeout and any earlier configuration-phase deadline; receipt completion does not renew the budget. Cancel, expiry, a missing or replaced private control directory, a disabled/read-only control root or changed authority revokes it before the launch attempt as well as during reservation polling. Ordinary cold launch reserves a remote channel before setup, so subsequent relay configuration consumes already acknowledged identity. |

## Remaining synchronous routes

These barriers keep their existing caller and recovery contracts. They are not silently removed or treated as asynchronous by changing a readiness/version predicate.

| Barrier | Disposition |
|---|---|
| Send restart with its own stop still in flight, or an existing non-directory local workspace | The send keeps the synchronous launch and immediate error: the in-flight stop would revoke a staged launch, and an unusable working directory fails process start at once. Other launch failures on deferred sends, such as a missing provider executable, surface after the save receipt with the input retained. |
| Shutdown `FlushPendingChatSaves(..., true)` | The only explicit production force callers are the two `Application::Shutdown` barriers after initial-work quiescence and around runtime teardown. They join/revoke work before the data-root owner disappears; ordinary Send does not use force mode. |
| Legacy/unnegotiated SSH input and automatic quota outside owned ready predicates | Keep the compatibility save/dispatch contract. V3 envelope and deduplication assumptions cannot be applied to unsupported transport. Cold ownership publication does not change later legacy input classification. |
| Saved-image cold Retry, referenced/legacy queue carriers and Copilot wire-stop migration | Keep exact source/predecessor and confirmed-stop ownership, early refusals and cleanup holds. These paths do not acquire launch permission from an ordinary full-save receipt. Fresh raw promotion does not absorb them, and this task grants no real-runner execution clearance. |
| Explicit cancel/Stop, restart cleanup and permission/question responses | These synchronous APIs promise durable success or refusal for a specific control, rather than ordinary Send admission. Keep their response/control identity and stop-confirmation boundaries. |
| New relay identity enabled on an already running session | Ordinary cold setup now reserves its identity before launch. A later settings/control transition without that identity keeps `ConfigureRemoteUamControlRelay`'s existing save-before-use contract; it is not permission to use an unacknowledged identity. |
| Invalid input/storage, missing exact goal owner, held/conflicted runtime or failed history preparation | Preserve refusal, captured raw intent and corrective held-state publication. In particular, an automatic quota continuation cannot enter ordinary pending-workspace raw admission and become replayable queue input. |
| `PublishRestoredQueuedAdmission` after definite write rejection | Exact restored FIFO publication still gates reconnect/resume. Failed correction holds the queue and stages its existing guarded retry; this corrective refusal contract is separate from successful promotion. |

Sources: [shutdown](../../src/app/application.cpp), [runtime recovery](../../src/common/runtime/acp/acp_session_runtime.cpp), [launch/control boundaries](../../src/common/runtime/acp/acp_session_lifecycle.cpp) and [quota cancellation](../../src/common/runtime/acp/claude_quota_continuation.cpp). The remaining writes are dispositioned ownership, compatibility or refusal boundaries; their existence is not a blanket missing quota/small-model/force implementation label.
