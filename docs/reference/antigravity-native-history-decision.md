# Antigravity native history sources and reader

Task-1630 initially found no documented non-executing CLI export and left Antigravity missing. Continued public-source investigation on 2026-10-23 established native SQLite and authenticated legacy routes, now source-integrated with the five existing readers, explicit workspace assignment and selected import. This supersedes the earlier upstream-only stopping point; it does not establish a vendor-stable storage API or six-provider acceptance. No provider login, CLI execution, real cache inspection or UI scraping was performed.

## Authoritative routes inspected

| Official reference | Established behavior | Import boundary |
|---|---|---|
| [CLI command reference](https://antigravity.google/docs/cli/reference/) | Documents interactive commands and launch flags. | No read-only session list plus full transcript export command is documented in the inspected reference. |
| [Resume and session cache](https://antigravity.google/docs/cli/commands/resume/) | Provides an interactive picker, specific-conversation resume, a last-conversation ID cache keyed by workspace and App-to-CLI cloning inside the picker. | The cache is metadata for the latest session, not a complete transcript or complete session inventory; interactive cloning is an import into Antigravity and is not a machine-readable UAM export contract. |
| [Headless mode](https://antigravity.google/docs/cli/headless/) | Produces text/JSON/streamed output for model turns and accepts a native conversation ID to continue a conversation. | Continuing with a prompt executes a turn; asking for a summary is not read-only discovery or faithful original history export. |
| [SDK lifecycle and persistence](https://antigravity.google/docs/sdk/lifecycle/) | Configures session persistence using conversation IDs and storage directories. | This does not document a supported read-only reader for arbitrary existing CLI histories or establish compatible CLI authentication, native IDs and transcript ownership. |
| [Hooks common input fields](https://www.antigravity.google/docs/hooks/#common-input-fields) | Documents CLI transcript path, conversation UUID and mounted workspace paths in hook input. | This is a supported observation schema, not evidence that an old store contains a complete transcript or an attested hook receipt; no hook is installed or invoked during discovery. |

The command references alone were insufficient evidence of storage incompatibility. The [official CLI changelog](https://github.com/google-antigravity/antigravity-cli/blob/fd851f1da40e4347f1d05d211dcb45f94aede4c4/CHANGELOG.md) records SQLite conversations, WAL-aware resume and fixes for truncated display logs. Those logs cannot establish complete original history. The [official Python SDK protocol](https://github.com/google-antigravity/antigravity-sdk-python/blob/91dc5f84565bb505577ac9524f107f453a6e8d1f/google/antigravity/proto/localharness.proto) exposes initialization history for its separate harness sessions, without proving a read-only CLI export or CLI authentication continuity; UAM does not start that harness during discovery.

## Implemented native route

The primary [txcript decoder](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/harness/antigravity.rs), [format report](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/docs/formats/antigravity.md) and [synthetic integration fixtures](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/tests/integration/antigravity.rs) publish firsthand CLI 1.0.16 descriptor/storage observations. This is an observed native-format contract, not an official supported SDK/export guarantee. UAM independently implements strict wire parsing rather than the upstream decoder's tolerant valid-prefix behavior.

The independent [1.1.16 interoperability report](https://github.com/xhluca/antigravity-session-interoperability/blob/b85c60a1eacd44808fa7b1cffc343e4af936df9d/docs/format.md) and [reader implementation](https://github.com/xhluca/session-migrate/blob/45351ff95ce79684c23377920b92026ecbe9759b/src/session_migrate/formats/antigravity.py) establish a newer minimal text shape and the `conversation_summaries.db` workspace index. UAM reads an isolated snapshot of that index by exact conversation UUID, cross-checks original workspace and complete step count, and refuses active/foreign/nested/conflicting index rows. A summary is scope/count evidence only, never transcript text or title/time ownership inference. Missing per-step input metadata remains unknown provenance, with no fabricated original input ID or write receipt. UAM does not use that migrator's position-based orphan-tool pairing, synthetic ID rewriting, native installation or credential-backed validation routes.

The [reader](../../src/common/provider/antigravity/cli/antigravity_native_history.cpp) inventories only `~/.gemini/antigravity-cli/conversations/` database and supported legacy files. Filename, cascade UUID and main metadata conversation UUID must agree; the trajectory UUID remains distinct. Original local file-URI workspaces must agree across recorded fields, and foreign drive URIs cannot become different POSIX paths. It never matches title/time, invents conversation IDs, uses the latest-session cache, scans the filesystem for private histories or replays prompts. The application retains shared ownership matching and the original source directory during assignment.

Bounded main/WAL byte copies go into an owner-protected ephemeral directory before SQLite opens them, preventing native shared-memory writes. Revision fences, schema/version and integrity checks, contiguous complete terminal steps, matching protobuf envelopes and exact native tool-call correlations are required. SQLite render-column presence must agree with the generic result’s redundant render field, including present-empty records; supported render fields are validated and must retain identical encoded bytes. Complex or unknown render content remains refused. The legacy memory view derives that column from the authenticated native payload with its original presence. Unknown formats, active/nested trajectories, malformed media, missing tool results, rollback journals, changed sources and foreign sources refuse the affected conversation with retryable issues. The index `source` column is empty on real CLI stores, so an empty value is accepted and only a non-empty value that is not `antigravity-cli` is foreign. Scans cap files, time, retained bytes and image originals. These limits remain explicit Partial coverage rather than success with a shortened transcript. Revision fences add SQLite's database change counter and WAL header to file identity, because Windows timestamps can stay unchanged across a same-size commit.

Text, native reasoning, tool calls/results and supported user/MCP inline images feed existing selected publication. MCP image originals retain the exact originating tool-call association on the assistant message, including image-only results; empty textual output stays empty, with raw native evidence retained only in canonical blocks rather than substituted into displayed tool text; unsupported media, result URI/structured payload and generic-result content variants refuse the complete conversation rather than importing text alone. Known structured native edits/listings retain original record evidence instead of inferred success, and context records remain passive. Stable event locators combine actual native conversation/trajectory IDs and row index; absent provider-issued input IDs remain absent. The reader never sets an original UAM input-write receipt, requested model strings or execution authority. Pending inline originals use existing worker-owned media preparation and uncertain-publication retention; discovery never publishes assets or chats. [Synthetic parser and application fixtures](../../tests/antigravity_native_import_tests.cpp) cover the new route; current execution evidence and remaining platform/review limits are recorded in the V5 log and ignored task notes.

## Authenticated legacy route and current primary schema

The primary [agy-reader completeness profile](https://github.com/mjacobs/agy-reader/blob/4c5f5e7a75819c6308ced8e346740ab87ec09019/docs/completeness.md#legacy-encrypted-protobuf-sources), [legacy decoder](https://github.com/mjacobs/agy-reader/blob/4c5f5e7a75819c6308ced8e346740ab87ec09019/internal/completeness/legacy.go) and [recovered native trajectory schema](https://github.com/mjacobs/agy-reader/blob/4c5f5e7a75819c6308ced8e346740ab87ec09019/artifacts/historical-schema-recovery/1.0.10-proto/third_party/gemini_coder/proto/trajectory.proto) establish an additional non-executing route. Its fixed format key was extracted from the pinned agy 1.4.4 binary; it is public format data, not a user credential. The 12-byte nonce, AES-256-GCM ciphertext and 16-byte tag must authenticate completely before any protobuf is decoded. Unknown keys/layouts, malformed envelopes and partial steps refuse the conversation. UAM uses the hash-pinned official [Mbed TLS 3.6.7 release](https://github.com/Mbed-TLS/mbedtls/releases/tag/mbedtls-3.6.7), building only the required AES/GCM support modules with no TLS/network services. Its notice is included only when this provider is built.

Legacy plaintext is decoded into a memory-only query view that reuses the SQLite reader's original identity, workspace, terminal-step, tool and provenance checks. Original generator/executor context is retained as inert source evidence, and the decrypted envelope buffer is cleared after decoding. No plaintext staging file, account-key discovery, provider process or daemon connection is used. SQLite wins when both native extensions exist; a newer SQLite source appearing during a legacy scan invalidates that result. Two platform-specific encrypted golden fixtures are generated independently with Python cryptography, with literal synthetic content and native-format identities; the tracked generator never accesses profiles.

The [primary 1.4.4 metadata schema](https://github.com/mjacobs/agy-reader/blob/4c5f5e7a75819c6308ced8e346740ab87ec09019/artifacts/proto-snapshots/agy-1.4.4-337dcde66844/proto/third_party/jetski/cortex_pb/cortex.proto) also establishes original parent/root identity, nesting and battle markers. UAM refuses inherited contexts even when the optional summary index is missing, and retains source-qualified planner message IDs, grounding and passback data without granting input-write or managed execution authority. The fixture file's outer provider guard covers its complete inventory, including reduced-provider compilation.

The same primary export tool has a native daemon sidecar contract, but requires persisted-source/full/default projection agreement for completeness. Its current profile explicitly refuses decomposed subtrajectories. UAM does not trust an adjacent sidecar, its timestamp or a reader-owned parent stamp as proof, discover daemon credentials or invoke that tool. The native parent-reference schema now names IDs, step index and reference type; it still does not establish complete inherited-prefix expansion/order for every reference kind. A bounded source/export qualification for those semantics remains necessary before publication can safely expand such histories.

## Focused application verification

The opt-in `uam_native_import_application_tests` target uses production backend sources and all six provider identity implementations, with the existing new import cases selected explicitly. The target requires all six release providers; restricted builds leave `UAM_BUILD_NATIVE_IMPORT_FIXTURES` off, and the shared all-six case is omitted from their ordinary inventory. Its test-only platform factory denies and counts process, terminal, dialog and dictation work; temporary data/home paths prevent ambient provider-store discovery. The Antigravity cases pass exact synthetic SQLite/legacy roots through the real discovery service, then exercise original publication/readback, duplicate exclusion, hidden ownership and late deletion. Shared cases cover immutable assignment, catalogue changes, failure/retry, an empty catalogue and all-six assignment/decline scope. Three explicitly selected existing data-only media cases exercise rejected and uncertain publication, including the real atomic replacement boundary and conservative retention of originals. The ordinary test inventory is preserved; this target builds no desktop or helper and runs no older process fixture. The private crypto target is excluded from direct default builds, and runner-only configurations do not fetch or configure it.

## Concrete upstream request

Request a supported **non-executing list/export interface for existing Antigravity CLI conversations**, using the user's existing provider identity only after explicit authorization. The contract must provide:

- A paginated inventory with stable provider-native conversation IDs, exact workspace/project and executing-host scope, parent/child relationships, timestamps and explicit errors.
- Export by an exact returned native ID with the original ordered user/assistant/reasoning/tool content, attachment references or original bytes and enough provenance to preserve native turn/input identity.
- A documented completeness/cursor or revision witness, explicit unsupported/incomplete results, bounded cancellation, and no conversation creation, model turn, fork, deletion or migration as a side effect.
- A documented relationship to CLI resume IDs and authentication; SDK storage options alone are insufficient evidence of CLI continuity.

**Remaining upstream dependency:** an official stable export contract would replace the version-specific storage dependency and resolve unsupported nested/unknown variants without guessing. The implementable settled-CLI route no longer waits for that request. Native child completeness, unobserved storage versions, Windows/live continuation, Claude review and David's acceptance remain outstanding. No upstream contact or real export collection has been performed here.

UAM ownership checks use exact native links actually retained by the application. Antigravity goal-worker identity retention is separate task-1014 runtime work; the history reader neither replaces that producer nor reconstructs lost links from titles, text or timestamps. That integration dependency remains for review without importing another thread's unfinished source.

UAM-created Antigravity chats already retain captured structured history in the canonical UAM chat repository. Discovery excludes those exact native owners instead of replacing or duplicating their captured history. That independent retained-history route does not supply missing original native parent context or recover a native identity that the runtime never saved. The hook's documented persistent log path likewise does not specify transcript record shape, parent expansion or a completeness witness; installing a hook or treating a display mirror as complete would not close the imported-native-history gap.
