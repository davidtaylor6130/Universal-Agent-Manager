## Admission and public guards

[`HandleSetChatModel` and `HandleSetChatApprovalMode`](../../src/cef/chat_config_handlers.cpp) use `AcpSessionBlocksModelChange` to defer applying a saved selection while raw input is pending. [`AcpSessionBlocksModelChange`](../../src/cef/uam_query_handler_internal.h) delegates to [`AcpSessionHasBlockingRuntimeWork`](../../src/common/runtime/acp/acp_session_state_helpers.h); raw `queued_user_prompts` counts as active work. The public `SetAcpSessionMode`, `SetAcpSessionModel` and `SetAcpSessionConfigOption` in [the runtime](../../src/common/runtime/acp/acp_session_runtime.cpp) retain their busy checks unchanged. The public reasoning/options handler also retains that boundary.

`DrainNextQueuedAcpUserPrompt` retains the exact raw head while `StartAcpUserPromptBatch` prepares it. Nongeneric admission now checks the registered chat/session, transport ownership through `ValidateAcpRestartOwnership`, equality of the saved/runtime FIFO and admitted prefix, and absence of active native work or background tasks, settings requests, permissions, cancellation, compaction and stop/recovery work. Only this internal preparation can disregard its matching raw FIFO; it does not remove the FIFO to fool a public guard. A separately claimed Claude quota instruction retains the existing invocation-only `DispatchScope` established by `PollClaudeQuotaContinuations`: [`IsCurrentClaudeQuotaContinuationInput`](../../src/common/runtime/acp/claude_quota_continuation.cpp) matches its current control ID, native session, context and captured agent policy, and its future saved/runtime FIFO must be equal and wholly unprepared. That control does not consume or replace a future user entry. Ordinary direct input still requires an empty FIFO; ordinary queued input still requires the exact admitted raw prefix. Captured read access still forces Plan, including with a blank chat mode and YOLO command tier. Delivery and durable-save gates remain separate.

Local settings/agent restart uses the existing queue-preserving Stop mode with both runtime and durable carriers present and held during teardown. A successful stop releases only the temporary hold so normal admission can continue; stop refusal restores the raw queued head and keeps recovery held. A later prompt-preparation refusal uses normal raw-head rollback. The old local path moved only the runtime FIFO aside, allowing Stop to erase the durable outbox; independent review R2 identified this defect. The local-host regression covers named model, mode, explicit-to-Default and captured-read restarts with two raw entries and deterministic preparation failure before replacement launch, asserting transcript, memory and saved FIFO retention without delivery. A second local control blocks storage during Stop and verifies exact raw-head rollback, retained original disk input, the save-pending hold and guarded save recovery without dispatch.

## Default and stream startup corrections

An empty model is a supported selection: [`IsAllowedModelId`](../../src/common/config/provider_chat_defaults.h) explicitly accepts it. The public model handler can save it while application to the running runtime is deferred. The old `settings_require_restart` predicate required `!turn_model_id.empty()`, and the later public-model call also skipped an empty model, leaving a previous explicit native launch model in place. The candidate uses the captured launch choice for this empty-selection branch and preserves the existing named-model comparison. The runtime-only `launch_model_options_captured` bit distinguishes a known empty Default choice from an unknown reattached launch; only a successful new provider launch sets it, both runtime reset/stop paths clear it, and no serializer restores it. An unknown launch choice requires an owned idle restart before applying Default. It does not mistake a provider-reported resolved default model for an explicit launch override. Restart selection and omitting an explicit launch model do not attest the provider's effective model after replacement or native resume; the restart fixture stops before replacement launch, and the no-restart fixture injects a known captured Default. Effective Default readback and resumed native model semantics remain live-provider verification limits.

Claude and Antigravity advertise `OnAcpCanSendPromptWithoutSessionId()`. Antigravity's initialize/setup builders return no RPC; shared `SendSessionSetupIfReady` can mark the stream ready before its first native init event establishes an identity. Claude similarly permits first input without an ID. The first task candidate accidentally required a nonempty ID in its new admission check; the continuation corrects that check using the adapter capability already respected by [`AcpSessionCanSendQueuedPrompt`](../../src/common/runtime/acp/acp_request_builders.cpp). Codex and Copilot retain the ID requirement. Transport/chat ownership and the other busy boundaries still apply.

A supported new stream with an empty native ID is distinct from a saved-session ownership mismatch. [`StartAcpProcessForChat` and `SendSessionSetupIfReady`](../../src/common/runtime/acp/acp_session_lifecycle.cpp) bind the validated/resolved resume identity before queued input can drain; Claude’s owned [`apply_flag_settings` result](../../src/common/provider/claude/cli/claude_cli_provider_runtime.cpp) likewise assigns the chat’s native identity before marking setup ready. `ValidateAcpRestartOwnership` still rejects a nonempty saved native ID that differs from the running session. This route already has internal setup ownership; it needs no new admission bypass. This is source evidence, not live resume or effective-model readback.

## Mode values and permission ceilings

The public mode action admits Default and Plan through `IsAgentMode`; Accept Edits, AI Review and YOLO belong to the separately validated command-safety action in [`HandleSetChatCommandSafetyTier`](../../src/cef/chat_config_handlers.cpp). That handler also defers native mode mutation while raw or active work blocks it; its existing pending-permission reevaluation remains subject to captured read restrictions. `EffectiveProviderMode` maps Plan first, then Accept Edits, otherwise Default. No new native mode or permission grant is introduced here.

Codex builds per-turn `sandboxPolicy` and `approvalsReviewer` under the captured read ceiling. Claude's `ClaudeStructuredPermissionMode` maps Plan, native `auto` for AI Review, Accept Edits and Default at launch; `AcpSessionMatchesPermissionMode` retains the existing native-auto equivalence. Copilot supplies Plan/interactive `agentMode` per input and keeps UAM permission response validation. Antigravity applies native Plan/Accept Edits launch flags while preserving its expert-flag Plan guard. These source mappings do not prove live parity of every permission mode; the [shared permission agreement](../providers/permissions/permissions.md) retains its existing partial status.

## Reasoning and variant boundaries

[`HandleSetChatCodexOptions`](../../src/cef/chat_config_handlers.cpp) serves the shared public reasoning/options action. It checks blocking runtime work before mutation and requires restart for Claude, Copilot, Antigravity and launch-only adapters. This remains unchanged. No raw queue dispatch calls this handler or the public config-option setter.

Copilot's `OnAcpReconcileModelOptions` is an internal metadata/reconciliation hook, not the public setting action. It can decline while raw input is pending; the `models.list` handler consumes the native response regardless and does not turn that false return into a queue failure. Create/resume already carries the selected effort. An admitted prepared prompt can negotiate a supported effort before `session.send`, while native request IDs and the shared delivery gate hold input. This audit does not establish that every ordering of metadata and effective native effort is verified; no new switch or broad raw-queue exception is inferred from a false reconciliation result. Existing `CopilotNativeUsesModelSpecificReasoningOptions` and `CopilotNativeRefreshesReasoningAcrossModelChangesAndResume` passed in the scoped native run; this does not establish every metadata ordering or live-provider compatibility.

Copilot Auto routing is a separate native session preference. `AutoRoutingBusy`, `AutoRoutingOwnerMatches` and `OnAcpRequestNativeModelOption` in [the native adapter](../../src/common/provider/copilot/cli/copilot_native_protocol.cpp) retain their raw/active-input guards. Admission does not replay a preference or call that public action. The existing silent-request expiry hook runs before ordinary queue admission; no relaxation is needed here.

Legacy Copilot ACP recovery is not another newly supported generic setting route: [native launch](../../src/common/runtime/acp/acp_session_lifecycle.cpp) explicitly attaches only to stop an owned old process before SDK migration and forbids legacy prompt replay. Existing rejected-migration holds remain. Native CLI View has a separate PTY lifecycle, not this structured raw FIFO; this patch grants no terminal-control or live-provider permission.
