## Supported transport and discovery

`opencode acp` is a usable newline-delimited JSON-RPC transport over stdin/stdout. Its only command-specific option is `--login`, which runs authentication instead of ACP; ordinary startup must not pass it. ACP unconditionally starts its own standalone service. That service generates a credential, starts a child `serve --stdio --port 0`, consumes its readiness internally and gives its authenticated HTTP client to ACP. No endpoint or credential is returned in the ACP initialize response. The ACP command does not take the `ServerParams` used by other commands, so `acp --server <owned-url>` is not an available attach route. See the pinned [command declaration](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/commands/commands.ts#L89-L98), [ACP handler](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/commands/handlers/acp.ts) and [standalone implementation](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/services/standalone.ts).

A different supported transport exists: UAM could directly own `opencode serve --stdio --hostname 127.0.0.1 --port 0`, supply a fresh private `OPENCODE_PASSWORD` through its child environment, validate the returned JSON readiness URL against loopback and the owned process, and keep stdin open as its lifetime lease. Stdio mode removes the credential from the environment before tools inherit it and ends its service lifetime on EOF; it does not register the persistent background service. HTTP authentication and event streaming would then belong to UAM's native adapter. This is the native HTTP/SSE route used by the authored UAM bridge, not an ACP attach option. See [server process ownership/readiness](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/server-process.ts#L80-L242), [HTTP event stream](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/server/src/handlers/event.ts) and [explicit-server client resolution](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/services/server-connection.ts).

## Configuration and the permission blocker

V2 still passes `OPENCODE_CONFIG` and `OPENCODE_CONFIG_CONTENT` to configuration loading. Its normalizer understands legacy inline `permission` and converts action names (`task` to `subagent`, `bash` to `shell`); native rules use `permissions` entries containing action/resource/effect. The V1 process-wide `OPENCODE_PERMISSION` setting is not consumed by the V2 server startup. Reusing UAM's current environment therefore does not install its V1 permission override. See [server configuration inputs](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/server-process.ts#L121-L133), [inline configuration loading](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/core/src/config.ts#L220-L246), [normalization](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/core/src/config/normalize.ts#L179-L183) and [action migration](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/core/src/v1/config/migrate.ts#L25-L31).

Replacing that environment with inline `ask` rules alone is insufficient. V2 merges agent rules followed by session rules, takes the last matching rule, checks configured denial, then appends saved project allowances before determining whether a permission request is necessary. A session allowance can override an agent denial; a saved allowance can override a configured ask. Unoverridden configured denial still wins over a saved grant. These are distinct cases: the assessment does not claim every denial is bypassed. See the exact [evaluation and precedence](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/core/src/permission.ts#L87-L96) and [configured/session/saved composition](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/core/src/permission.ts#L146-L188).

Consequently, a resumed native session with an existing allowance, or a new session in a project with saved grants, can execute an action without a `session/request_permission` message. UAM's [Default and captured-read agreement](../providers/permissions/permissions.md#captured-read-restrictions) cannot be enforced by filtering requests it never receives. This does not assert that David has such grants; it establishes a supported state the adapter must handle without deleting or rewriting his native account/project permissions.

V2 ACP new/load/resume do not expose session permission inspection/replacement or an enforceable force-ask setting. They attach sessions and select models/agents; changing the agent is not equivalent to replacing session rules. Native HTTP does expose session permission mutation and permission inventory, but ACP's own endpoint is private. Configuration policies have only allow/deny effects and the policy plugin can impose denial; they cannot request a forced UAM decision. A custom per-process permission-evaluation plugin could be a separate integration route, but it is additional executable policy code requiring its own ownership, loading and enforcement proof. See [ACP setup methods](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/acp/service.ts#L137-L239), [session selection](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/acp/sessions.ts), [native session update](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/server/src/handlers/session.ts#L235-L249), [policy schema](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/schema/src/config/policy.ts) and [policy hook](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/core/src/config/plugin/policy.ts#L54-L73).

## Session, history and cancellation contract

- ACP initializes at protocol 1, returns its exact agent version and supports new/load/resume. Load replays history; resume attaches without replay, and both validate the requested workspace against the stored native location. UAM must retain the exact native identity on failure rather than invoke its V1 invalid-load-to-new-session fallback. [ACP service](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/acp/service.ts#L97-L209).
- The version-aware history commands are `opencode session list --format json --max-count 200 --standalone` and `opencode session export <exact-session-id> --standalone`. `--standalone` selects a private service and avoids implicitly ensuring/replacing a persistent service; V1's `--pure` and top-level `export` are not V2 commands. These are specified commands, not commands run against David's CLI. [Declarations](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/commands/commands.ts#L417-L457), [list handler](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/commands/handlers/session/list.ts) and [export handler](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/commands/handlers/session/export.ts).
- V2 export contains `info.location.directory` and flat typed messages, rather than UAM's V1 `info.directory` and message `{info, parts}` representation. Its exporter emits settled messages. A changed command alone cannot supply a complete V2 history reader or authorize replacement of newer UAM history. [Transfer schema](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/schema/src/session-transfer.ts), [message schema](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/schema/src/session-message.ts) and [export implementation](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/core/src/session/transfer.ts#L57-L63).
- ACP has parent and child permission forwarding, so absence of all permission transport is not the blocker. Once/reject/cancel replies retain the relevant native session; UAM must validate actual tool input and ceilings before sending a decision. [Permission mapping](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/acp/permission.ts#L39-L80).
- `session/cancel` interrupts the turn and winds down native work, but descendants can outlive a cancelled turn and keep sending background permission requests. A cancelled prompt result does not establish process-tree cleanup. EOF/lease retirement, descendant settlement and existing recovery holds require separate fixtures. [Cancellation](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/cli/src/acp/turn.ts#L261-L311).

## Selected implementation route

The built-in V2.1.2 ACP route has usable chat transport but no supported control surface sufficient for UAM's mandatory permission boundary. Do not enable it by removing flags, switching Default to native automatic approval, clearing saved grants, changing accounts or treating an opaque private endpoint as discovered authority.

The recommended next route is a separately reviewed UAM-owned V2 integration using the leased native HTTP/SSE service **and an enforceable process-local permission boundary**; HTTP ownership alone does not override saved grants. A reviewed per-process native policy plugin is one candidate. This adds a new protocol/policy adapter, not just a launch-argument translation. If staying exclusively with upstream ACP is required, the external dependency is an upstream attach/discovery mechanism plus session-bound effective permission control/readback that cannot be widened by saved grants. Neither mechanism exists in the inspected built-in ACP route. David subsequently authorized the native adapter implementation using T3 as a reference. The source slice below implements that selected local route; V1 and existing owned remote recovery remain available without altering installed versions.

## Native adapter source contract

The new `src/common/provider/opencode/v2/` module provides an original C++ native-protocol engine with injected HTTP/policy/event callbacks, a headless transport command dispatched before CEF/app startup, and an original process-local JavaScript permission plugin. It adds no Node runtime dependency to UAM: OpenCode loads its own configured local plugin through its supported Promise API. UAM uses the existing system HTTP client with piped authentication/configuration, validates a loopback readiness URL from its owned child and checks `/api/info` version exactly `2.1.2`. Stdin EOF retires the private service; no background service is registered. A saved `opencode_v2_session_id` origin hint from owned setup or checked V2 discovery binds to the exact native ID and refuses legacy load after a CLI change; absent legacy hints retain V1 behavior, and malformed-present hints hold. This is UAM refusal data, not upstream metadata-schema support or a resume/input witness. The existing structured writer observes bytes to this owned bridge, while native prompt admission and completion remain separate observations.

The plugin registers `ctx.permission.hook("evaluate", ...)`, which upstream invokes after session/project grant composition. It installs an ask/deny-only property latch on the mutable event: subsequent hooks can deny but cannot restore allow. Existing native configured denials survive because UAM replaces session allowances with narrowing rules, without publishing a broad session ask/allow that could override agent denials. A private nonce-bound policy file binds the exact root and workspace; missing/malformed/unbound policy denies. The plugin service is resolved explicitly through its read-only inventory endpoint, and a matching load proof is required before native create/load readiness or prompt delivery. Native children are denied, and Plan/captured read adds edit denial while shell decisions still pass through UAM's existing typed-command ceiling. Session rules are replaced and read back on create, exact resume and each turn; native approvals are once/reject only. Approvals bind the root, assistant message ID and tool ID, so reused tool IDs cannot borrow another call’s command input; external-directory access retains a separate non-edit approval kind. Remembered grants match action/resources/native tool name/actual tool input and captured policy within this process; they are never native saved-project grants. See the pinned [Promise plugin API](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/plugin/src/promise/plugin.ts), [permission hook](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/plugin/src/promise/permission.ts), [local plugin resolution](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/plugin/src/host.ts) and [ordered mutable hook dispatch](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/core/src/plugin/hooks.ts).

`POST /api/session` creates with explicit location and narrowing rules; `GET`/`PATCH /api/session/<id>` loads, replaces and verifies the exact identity/policy. Exact load and turn preflight refuse pre-existing or malformed native inbox state without waking, discarding or replacing that work. Prompt HTTP success admits durable input but does not complete it: the returned inbox ID must match `session.inbox.delivered` before output/terminal events are accepted. Text, reasoning and tool events map to the existing normalized stream; step usage is counted once and returned with terminal completion, while context usage uses the last step and the observed model window. Stop requests deletion of the exact pending inbox item and waits for its owned cancelled/delivered event. An unavailable-item DELETE is a successful no-op in V2.1.2, so neither a successful nor failed DELETE proves delivery. Only exact owned delivery permits interruption; an already-owned terminal event can settle an idle or lost interrupt reply. Native control calls are bounded within the existing shared cancellation budget, and unresolved cancellation holds input without replay. SSE loss or policy reload invalidates the process lease and never replays an HTTP prompt. Model refs/variants come from the live native catalogue and changes require readback. Simple string/multiselect forms retain field/option identity through UAM questions; unsupported advanced fields are explicitly cancelled. See [native session endpoints](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/protocol/src/groups/session.ts), [permission replies](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/protocol/src/groups/permission.ts), [event volatility](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/protocol/src/groups/event.ts), [server identity](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/protocol/src/groups/server.ts) and [durable inbox events](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/schema/src/session-event.ts).

Captured MCP definitions are registered through location-scoped native `PUT /api/experimental/mcp/<name>` and remain independent of task-1084's saved next-launch preference. `opencode-progressive-mcp` is a UAM preference key, never a V2 server. Neither the V1 `openCodeCodeMode` manifest hint nor its exact version gate is broadened. The pinned [V2 MCP server schema](https://github.com/anomalyco/opencode/blob/a517687fde98a7329ada3ae644a01a9fc6c4e99e/packages/schema/src/mcp.ts#L22-L59) separately exposes optional per-server `codemode` (native default true). Task-1084 independently confirmed this as a Needs verification capability lead; this adapter does not set it, wire the saved preference to it or claim effective discovery/permission behavior from its declaration. Checked local V2 text workers also use this private bridge, retaining an inactive permission policy so every native permission is denied, including existing saved grants. They retain the selected model/variant, never resume a user session, cancel native questions, and publish only completed assistant text to the existing reviewer/memory worker contract; partial/error/tool/reasoning output is not returned as a successful text result. Route selection precedes isolation setup, so V2 workers do not inherit the V1 `opencode.json` or legacy flags. Ordinary local workers require a successful, supported checked local version; absent, failed or foreign observations hold with a Settings check/retry error. Application startup already queues those local checks; worker builders consume immutable snapshots and do not mutate app state or start competing probes. Confirmed V1/custom/remote worker routes retain their prior behavior.

Local list/export command dispatch probes the actual CLI with the same decorated-semver parser as the version manager, retains V1 streaming and command forms and uses V2 `--standalone` plus nested `session export`. The wrapper caller allows the separate 10-second probe, original complete 30-second native command and 5 seconds for dispatch/retirement; direct/custom command budgets are unchanged. V2 tool content consisting entirely of text parts is joined for readable history; non-text data retains its JSON fallback. V2 flat messages are normalized within a 64 MiB capture bound for the existing guarded importer; an oversized export fails without replacing history; completed compaction summary text is data, without invented V1 coverage metadata. Task-1098's V1 native compaction allowlist and cold Retry holds remain unchanged.

## R6 admission, finite input and cancelled usage

The authentic owner-launched Codex R6 full review returned **Changes required** with two P2s and one P3 on the frozen 36-path source. Potentially admitted prompt errors now use the same marked owned disconnect as event failures before clearing request correlation, so shared dispatch can retire the transport and persist held queued intent without automatic replay. Production-engine regressions carry lost, missing, malformed and wrong-session admission receipts into the actual shared response consumer. Native HTTP failure alone still establishes neither rejection nor delivery.

V2 text workers use an opt-in finite-input platform operation. The existing Windows worker launcher supplies a private synchronous regular file; the new reader checks disk-file type, non-directory attributes and bounded length, reads bounded chunks to EOF, and preserves nonblocking pipe behavior, stdin ownership and console rejection. Structured bridge input keeps the existing pipe-only Windows reader. Primary Win32 contracts are [GetFileType](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfiletype), [GetFileSizeEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfilesizeex) and [ReadFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfile). Injected transport checks exercise the worker's finite-input call; a Windows-only private-file/pipe/character-handle fixture is authored but cannot establish a Windows pass on macOS.
