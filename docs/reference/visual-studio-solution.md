# Visual Studio Solution Layout

> Engineering reference retained from the trial base (`3a7c8477`, 2026-10-16). This records implementation detail and historical verification, not full feature acceptance. Start with the [feature guide](../README.md); its agreements and [documented corrections](../documentation-review.md) take precedence over stale claims here.

This repository generates a single canonical Visual Studio solution:

- `Builds/universal_agent_manager.sln`

Open that solution when working on the app in Visual Studio. The main executable is the only project you normally need to run.

## What You Should Open

- `universal_agent_manager` is the startup project and desktop app.
- Use that project for day-to-day development, debugging, and running the app.
- `uam_core_tests` appears when CMake is configured with `-DUAM_BUILD_TESTS=ON`.

## Solution Folders

The solution is grouped to keep the project list readable:

| Folder | What it contains |
| --- | --- |
| `App` | The main executable project `universal_agent_manager` and its shared `uam_core_objects`/`uam_app_objects` libraries |
| `Tests` | Native test executable when `UAM_BUILD_TESTS=ON` |
| `ThirdParty/CEF` | CEF wrapper and generated CEF targets |
| `ThirdParty/nlohmann_json` | Header-only JSON dependency targets |
| `_CMake` | Utility targets generated by CMake and Visual Studio |

## Real Projects

These are the projects that represent application code:

- `universal_agent_manager`
- `uam_core_objects` and `uam_app_objects`, object libraries holding the app sources that tests link instead of recompiling
- `uam_core_tests` when tests are enabled

## Generated Dependency Targets

These come from CEF, nlohmann/json, and CMake FetchContent. Treat them as dependency internals, not app features. Exact target names can vary with dependency versions, but commonly include:

- `libcef_dll_wrapper`
- nlohmann/json CMake helper targets
- dependency `update`, `patch`, `configure`, or `download` helper targets under `Builds/_deps/`

## Generated Utility Targets

These are created by CMake or Visual Studio to support builds and testing:

- `ALL_BUILD`
- `ZERO_CHECK`
- `RUN_TESTS` when tests are enabled
- `uam_platform_ifdef_guard` is exposed through CTest rather than as an app project.
- `Continuous`
- `Experimental`
- `Nightly`
- `NightlyMemoryCheck`

## Folder And File Noise

You may also see additional `.sln` files under `Builds/_deps/`. Those belong to fetched dependencies and are not the main UAM solution.

If the workspace starts to feel crowded, focus on `Builds/universal_agent_manager.sln` and ignore the generated dependency solutions.
