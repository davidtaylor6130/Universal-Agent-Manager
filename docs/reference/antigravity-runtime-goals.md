# Antigravity runtime and UAM goals

This 2026-10-23 source assessment supports task-1014, not a claim of complete provider acceptance. The [provider checklist](../providers/antigravity/antigravity.md) owns delivery status; [Goals](../chat/goals.md) owns behaviour. Task-1630 owns native history import/export and task-0942 owns managed execution-binding producers; neither sibling's unmerged implementation is assumed here.

## Supported transport and authority

The [official headless contract](https://www.antigravity.google/docs/cli/headless/) defines cached CLI credentials, exact `--conversation` resume and `event:user` input with `init`, `step_update` and per-turn `result` output. Native `/goal` is an interactive autonomous mode with no iteration cap; command text and guessed RPCs cannot supply UAM lifecycle authority. The [pinned SDK protocol](https://github.com/google-antigravity/antigravity-sdk-python/blob/91dc5f84565bb505577ac9524f107f453a6e8d1f/google/antigravity/proto/localharness.proto) exposes SDK initialization, history and budget configuration, but does not attest compatibility with the CLI's login, conversation store or native Goal control. UAM therefore uses the existing CLI process and its authentication rather than replacing it with an SDK agent.

The [official hooks contract](https://www.antigravity.google/docs/hooks/) documents CLI conversation/model observations before invocation and termination after invocation. It does not provide token counts, pre-generation termination or a captured complete approval/read policy. Hook loading is documented for workspace/global/plugin configuration, without an attested private additional-directory hook route. Installing hooks into user configuration is therefore not part of this implementation; the documented hook model observation remains a possible input to task-0942, not a complete execution binding or native Goal receipt.

The [adapter](../../src/common/provider/antigravity/cli/antigravity_cli_provider_runtime.cpp) opts UAM worker turns into the saved chat conversation. Structured launch removes expert-command conversation selectors, including the [workspace-cache continuation flags](https://www.antigravity.google/docs/cli/commands/resume/), and places UAM's stream/resume arguments before positional data. The [shared launcher](../../src/common/runtime/acp/acp_session_lifecycle.cpp) still starts goal review in a fresh native conversation under Plan, clearing the worker's ID from launch arguments without changing its saved ID. Subsequent worker turns, explicit Resume/Restart and native CLI View retain that saved identity. Returned foreign IDs are rejected; private reviewer IDs never replace the worker's ID, including the single bounded malformed-JSON repair on that same private reviewer. No native Goal acknowledgement is synthesized.

The adapter binds each goal turn to the owner incarnation, host, saved native conversation, goal, control revision and turn serial. A changed owner stops the old owned turn without charging or changing the replacement goal. Before preparing input it saves a pending-usage marker. Each validated native DONE step contributes its observed usage once, including reviewer steps; cumulative conversation result totals and text estimates never become a goal-budget delta. Missing or invalid usage holds a budgeted goal, and interrupted pending usage remains unresolved after restart. A lost observed receipt, replacement error diagnostic or legacy inferred counter cannot authorize further budgeted input. Explicit Restart resets the UAM goal budget/progress under the existing saved-control boundary; ordinary Resume preserves counters and refuses an exhausted or unverified remaining budget. Saved native identity is retained in both cases.

Iteration checks run before Resume mutation and before input preparation. Restart refuses before resetting progress or counters while the metered turn is active or its stop remains unconfirmed; local active metered stops retain owned process handles until actual exit is observed. At an observed token-budget crossing, UAM holds continuation and requests cancellation of the owned turn. A provider step can finish beyond the remaining allowance before its usage event arrives: this is an observed-step enforcement boundary, not a native hard token cap. Hard pre-generation budget enforcement remains an external CLI-contract dependency. Pause/clear/replacement controls stop the matching owned goal turn after their durable receipt and preserve held authored input. Direct service Pause, Clear and replacement controls now require their saved control intent before cancellation. A failed save restores the prior goal fields, retains the pending usage witness and suppresses continuation so the same control can be retried. The CEF path uses its existing asynchronous FULL receipt rather than an extra synchronous save. The process-stop fallback retains and durably holds unrelated queued input, so stopping a native goal turn cannot dispatch or discard it. Fallback steering preserves its separate dispatch authority after cancellation rather than inheriting the goal-control queue hold. Process-stop pending/failure remains runtime state, not a native goal cancellation receipt.
