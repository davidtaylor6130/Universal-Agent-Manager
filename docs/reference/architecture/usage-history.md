# Usage history

> Engineering reference updated from `uam/v5-improvements` (`e28ba717`, 2026-10-16). This records implementation detail and historical verification, not full feature acceptance. Start with the [feature guide](../../README.md); its agreements and [documented corrections](../../documentation-review.md) take precedence over stale claims here.

Usage history combines provider-native logs, transcript scans and UAM's own ledger into host-scoped summaries. The UI requests bounded pages and assembles them for display; it can show local, remote or all-machine results.

## Flow and invariants

Collectors and scanners write normalized records to the usage store. `MultiHostHistory` gathers host results; the CEF handler serves a snapshot and continuations. The frontend validates each page's host, time window, snapshot and offset before assembly. Keep a page set on one immutable snapshot, reject stale continuations and preserve the distinction between observed usage and estimated prices.

Large history must remain paged across the bridge. Avoid changing response shapes without updating both native transport and frontend assembly. Price overrides do not rewrite collected token counts.

The Limits view reads an independent account-allowance service separately from historical accounting and chat activity. At application startup, bounded read-only workers acquire Codex account/rateLimits/read, Claude OAuth account usage, Copilot SDK account.getQuota and available Gemini/Antigravity account quotas without creating chats or sending model prompts. The native service restores scoped persisted snapshots before refresh, serves queries without waiting for network I/O, coalesces refreshes, retains good values on failures and rejects results from replaced provider commands. Local acquisition is distinct from remote hosts, whose unavailable feeds never inherit local account values. Chat snapshots remain the source of per-chat context and token consumption only. Codex supplies account allowance updates, and Claude declared `rate_limit_event` snapshots project finite 0–1 utilisation for generic five-hour and weekly windows under native session identity checks. Status-only events do not invent percentages, model-specific weekly buckets do not replace the generic weekly window, and native-session changes discard the prior allowance snapshot. Other providers may expose native quota APIs or callbacks without those acquisition paths being integrated into UAM; missing telemetry does not imply a zero balance or a particular allowance period. A shared local clock updates display freshness without collecting provider history. Historical cost amounts combine reported charges and estimates, while missing prices remain visible as excluded unpriced tokens.

Page size and snapshot expiry are transport implementation details in source. No user-visible latency target is recorded; keep paging bounded and avoid loading all records into one bridge message.

## Accounting reuse

The background multi-host worker retains per-peer and combined disk-backed receipt stores using ordered source identities. Metadata-only refreshes reuse immutable ledger projections within the same 30-second clock interval; subsequent intervals recalculate rolling windows and future accounting witnesses. Changed facts, source order, host connection scope or lifetime coverage invalidate the applicable cache. Cached individual-host results retain available totals while marking collection incomplete. Full wire fingerprints continue to identify immutable exports separately from internal fact identities.

These caches reduce repeated work; they do not eliminate periodic lifetime scans or prove a reduction in the installed app’s CPU use. Native Windows and authenticated provider acceptance remain separate checks.

## Independent account allowances

`getProviderAllowances` returns cached provider rows immediately, with loading/error state and actual observation times; the UI warms this cache during startup and polls active refreshes without starting a chat. Provider commands scope disk snapshots in `<data-root>/usage/account-allowances-v1.json`, and each response row carries an opaque scope so the frontend cannot restore values from a replaced command. Only normalized presentation fields are saved; credentials and raw provider responses are excluded. Account readers accept standard provider launchers and the default Codex presentation flag; custom arguments and wrappers remain unavailable instead of risking prompt execution or reading the wrong account. Claude reads existing credentials without an OAuth or login prompt, sends the bearer through a normal stdin pipe to a fixed verified HTTPS endpoint, and does not perform login or token refresh. Its OAuth usage endpoint reports percentages, unlike fractional `rate_limit_event` utilization. Unsupported provider connections stay explicitly unavailable.

macOS account access runs in a cancellable system helper using a Security.framework query. Automatic reads disable Keychain interaction, because `kSecUseAuthenticationUIFail` alone does not suppress login-keychain access dialogs; only an explicit Refresh may show the macOS permission dialog, since provider CLIs rewriting their Keychain items can discard an earlier Always Allow. Account access has up to 120 seconds, separately from the 10-second HTTPS deadline. This allows existing Keychain unlock activity to settle without blocking the desktop process or mislabelling it as a network timeout. Authentication or entitlement failure clears cached account values and suppresses automatic retry until a manual refresh, configuration change or restart; transient network failure retains known values. Manual refreshes are coalesced and limited to one per provider every 30 seconds; automatic reads do not start that cooldown, and a refresh during an automatic read queues one prompt-capable read after it; `refreshAfterMs` reports the earliest next eligible read so the UI can show and expire the cooldown. Remote sections explicitly report unavailable acquisition without a local Refresh control or recurring poll. Per-model quota windows retain every validated bucket, with two initially visible and the remaining models expandable.

Gemini CLI resolves an already entitled account project through `loadCodeAssist` before `retrieveUserQuota`; Antigravity uses its existing account project and production `retrieveUserQuotaSummary` response, retaining all groups and buckets. Expired existing Google grants may refresh in memory without changing credential files or requesting new scopes. Unsupported-client, account or entitlement responses remain explicit unavailable states; acquisition never performs onboarding, accepts project trust or substitutes an Antigravity quota for Gemini CLI eligibility. This configured OpenCode setup has local/self-hosted credentials and no hosted subscription identity to query. OpenCode also offers free models, but no supported independent free-quota reader was found in the current public API documentation; its previously public limiter uses server-held counters keyed by public IP, and the request for remaining-quota headers is still open. Connecting free models therefore does not establish a readable account balance, and local request counts would be incomplete estimates. OpenCode account allowances remain explicitly unavailable independently of historical token accounting; this does not imply that OpenCode Go or its upstream providers have no limits.
