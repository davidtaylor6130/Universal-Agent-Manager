# Model catalogue scope

UAM stores each provider's discovered models per provider, execution host and workspace. Startup discovery (see [Models](../providers/models.md#startup-refresh)) asks a provider once per computer when its model list cannot depend on the workspace, and shares the answer with that provider's other workspaces on the same computer. A provider whose discovery request carries the workspace, or whose stored answer includes a workspace's own current model, is asked per workspace. The runtime interface states the classification with `ModelListIsAccountWide` in [provider_runtime.h](../../src/common/provider/provider_runtime.h); the startup service is [model_discovery_service.cpp](../../src/app/model_discovery_service.cpp).

| Provider | Scope | Evidence in the runtime code | Status | Note |
|---|---|---|---|---|
| Codex | Account-wide | Discovery sends `model/list` with only a pagination cursor (`BuildModelListRequest` in [the Codex adapter](../../src/common/provider/codex/cli/codex_cli_provider_runtime.cpp)) right after `initialize`; a discovery-only session returns before `thread/start`, the only request that carries a `cwd` (`SendSessionSetupIfReady` in [the ACP lifecycle](../../src/common/runtime/acp/acp_session_lifecycle.cpp)). The fallback local catalogue reads the global `CODEX_HOME` models cache. One install produced 263 identical local Codex catalogues. | Needs verification | Implemented as account-wide; whether a trusted project's Codex configuration can change the list through the process working directory is unverified. |
| Claude Code | Account-wide | Models come from the `initialize` control response (`OnAcpInitializeResult` in [the Claude adapter](../../src/common/provider/claude/cli/claude_cli_provider_runtime.cpp)); the request carries no workspace and no current-model field is stored. The same install returned the same list in every workspace. | Needs verification | Implemented as account-wide; the discovery process starts in the workspace and may load that project's Claude settings, and whether they can change the advertised list is unverified. |
| GitHub Copilot | Account-wide | Discovery sends `models.list` with empty parameters from `OnAcpInitializeResult` in [the Copilot protocol](../../src/common/provider/copilot/cli/copilot_native_protocol.cpp); `workingDirectory` is sent only by `session.create`, which a discovery-only session never reaches. Errors refer to account model access. | Implemented | |
| Gemini | Per workspace | Models and configuration options come from ACP `session/new`, whose request carries `cwd` (`BuildNewSessionRequest` in [the request builders](../../src/common/runtime/acp/acp_request_builders.cpp)); the response's current model and option values can differ by workspace and are stored with the list. | Implemented | Per workspace by caution; whether the list itself varies is unverified. |
| OpenCode | Per workspace | V2 asks `GET /api/model?location[directory]=<cwd>` and the per-directory default model ([V2 session](../../src/common/provider/opencode/v2/opencode_v2_session.cpp)); V1 uses ACP `session/new` with `cwd`. A project `opencode.json` can add providers and models. Issue #1027 keeps chat worktrees as their own discovery scopes. | Implemented | |
| Antigravity | Per workspace | `agy models` runs in the workspace, then `-p /model` reads the workspace's current model, which is stored as `isDefault` and moved to the top of the list, and `-p /effort` reads its reasoning options (`StartAntigravityModelDiscovery` in [the catalogue service](../../src/app/provider_model_catalog_service.cpp)). Sharing would copy one workspace's current model to another. | Implemented | Per workspace because the stored default is per workspace. |

A shared copy keeps the source's refresh time and CLI version, so every workspace of an account-wide provider becomes due again together and one process refreshes them all. The share skips a workspace with its own discovery in flight or its own result at least as new from the same CLI version. A failed or empty discovery shares nothing; startup then tries another due workspace as the source, preferring the newest cache, up to three sources per provider and computer in one run, so one broken workspace cannot keep the rest stale. Model requests the UI makes by itself, and Refresh or Retry in a workspace, keep their per-workspace behaviour; only startup groups workspaces.

The focused native cases are in [model_discovery_startup_tests.cpp](../../tests/model_discovery_startup_tests.cpp): `StartupModelDiscoveryAsksAccountWideProvidersOncePerHostForManyWorkspaces` counts launches for 60 workspaces (40 local, 20 over SSH) with Codex, Claude and Gemini chats in each. The code before this change launched one discovery per scope, 180 in that fixture. It now launches 64 on the first start (Codex and Claude once per computer, Gemini once per workspace), none on a restart within seven days with unchanged CLI versions, and one after a local Codex update. `StartupModelDiscoveryTriesAnotherSourceWhenOneWorkspaceFails` and `StartupModelDiscoverySharesNothingWhenTheAccountWideDiscoveryFails` cover a failing source.
