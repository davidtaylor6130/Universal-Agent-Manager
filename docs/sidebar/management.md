# Chat and workspace actions

Chat rows offer rename, regenerate/cancel title generation, copy details, pinning, snooze, collections and explicit deletion; actions target the chosen chat or disclosed branch family, not whichever row becomes selected during background work. A title worker changes only the title and must not overwrite a newer manual rename. Multi-selection, drag/drop and ordering change organisation while preserving conversation identity. Workspace menus separately offer naming, host/directory choices and native-session review; memory lives in [Settings → Memory Store](../memory/store.md). Deletion confirms affected chats/families/workspace entries, reports real cleanup progress and retains failures; deleting a workspace entry does not delete the user's underlying directory. Reusing an existing owned worktree for a new chat is distinct from creating another isolated worktree.

A Shift-click multi-selection of chat rows or workspace headers turns the row menu and the Delete key into actions on every selected row. Chats support deletion, pinning or unpinning, title regeneration, icons, copying names/IDs/paths/branches/native session IDs, snooze/wake and collection moves; workspaces support collection moves, icons and deletion. Actions with a single target—rename, a new chat in a worktree or workspace, project memory, native-chat review and host icons—stay visible but unavailable, keyboard reachable and described as “Not available for multiple selection — select a single chat” (or workspace); they never act on just the clicked row. Deletion asks once, counting selected rows and their branches. Each chat row's branch family or workspace is admitted separately: refused rows keep their running-runtime, saving and ownership safeguards and stay selected, the rest proceed, and every refusal or failure is reported by name through the shared notification path.
