# Activity status

Status distinguishes running work, waiting for permission or input, completion, interruption, failure and unknown activity. Use actual runtime evidence; Connected must not pretend to mean Ready or Busy when a native terminal cannot expose that distinction. Working indicators explain real work and settle when it ends, while attention indicators remain available until acknowledged or snoozed. A chat held for automation approval shows Waiting for approval, and Working once the user has started it, while its worktree and provider come up. New-work detection compares a chat's last update with its last open as instants, so native imports stamped in UTC and selections stamped in local time do not count as new work.

Each chat row's accessible name says what its status icon shows (running; waiting, with the reason such as permission needed; waiting for approval; watching pull request; done, unread), merged across its branch family as the row shows it, so the state never depends on colour or an icon alone. No row is a live region. The sidebar's single polite status region announces an Active chat whose spoken status changes to waiting or done, by name (“Build fixes: waiting, permission needed”), worked out exactly as the row's name is. Starting work, a pull request watch, clearing a search, the first render and chats the sidebar had not listed before (newly created or reloaded) announce nothing, except a newly created chat held for automation approval; the same region also reports keyboard reordering. Sidebar rows do not currently show provider errors, so no row reports a failure; see [known gaps](../../documentation-review.md#known-gaps-retained).
