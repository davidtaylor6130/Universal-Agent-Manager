# Workspace folders

Workspace folders group chats around user-selected working directories, with one level of grouping in this release. Display organisation is separate from the actual provider working directory, native session identity and managed Git worktree. Imported linked worktrees should remain associated with their canonical workspace without rewriting the directory in which their provider actually runs. A directory inside a UAM-managed worktree keeps that association after the worktree has been removed, because its location still names the source workspace. Moving a chat must wait for any pending final terminal history under its existing workspace; a blocked move retains grouping and settings and provides an explicit retry. See [terminal continuity](../../providers/terminal-view/session-continuity.md). Changing a remote folder's directory starts a new native session for the chats using that directory and closes their idle CLI View terminals, which still belong to the old session, and the change is refused if one cannot be stopped, keeping the folder and chat settings while any terminals already stopped stay closed; chats in the folder using another directory, such as a worktree, are unaffected. A chat holding queued, unsent or uncertain not-sent input refuses the move or directory change with the specific reason, naming the chat for a directory change, until that input is resolved. An uncertain not-sent row or held input with no control has nothing of its own to clear it, so the way out is to wait for the turn to settle or to [change the provider](../../providers/resuming.md) and accept its warning; a queue-storage problem stays refused.
