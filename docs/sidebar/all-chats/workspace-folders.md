# Workspace folders

Workspace folders group chats around user-selected working directories, with one level of grouping in this release. Display organisation is separate from the actual provider working directory, native session identity and managed Git worktree. Imported linked worktrees should remain associated with their canonical workspace without rewriting the directory in which their provider actually runs. A directory inside a UAM-managed worktree keeps that association after the worktree has been removed, because its location still names the source workspace. Moving a chat must wait for any pending final terminal history under its existing workspace; a blocked move retains grouping and settings and provides an explicit retry. See [terminal continuity](../../providers/terminal-view/session-continuity.md). Changing a folder's directory re-points only the chats in that folder whose recorded directory is the old directory or inside it, keeping any subdirectory below the new one; a chat already at or inside the new directory keeps it. When one directory contains the other, only chats at the old directory itself follow, so narrowing or widening a folder never invents a nested path and moving it back reverses the change. A managed-worktree chat keeps its worktree and its source directory follows the folder the same way. No other chat is rewritten or saved, so an unrelated chat that cannot be saved never blocks the change. Other chats in the folder recorded under another directory, including a worktree chat whose source directory is elsewhere, keep it and are counted in one line of the save status. If a re-pointed chat cannot be saved the change is refused naming that chat, the re-pointed chats already saved are written back and the folder keeps its directory. Chats that earlier versions left recording an old directory are not migrated automatically, and a local chat re-pointed this way keeps its native session, a known gap. **Implementation: Needs verification.** Native cases for subdirectory re-pointing, nested roots, worktree chats, an unsaveable unrelated chat and rollback have been syntax-checked but not yet compiled into the test binary or run on any platform. Changing a remote folder's directory starts a new native session for the chats it re-points and closes their idle CLI View terminals, which still belong to the old session, and the change is refused if one cannot be stopped, keeping the folder and chat settings while any terminals already stopped stay closed; chats in the folder using another directory, such as a worktree, are unaffected. A chat holding queued, unsent or uncertain not-sent input refuses the move or directory change with the specific reason, naming the chat for a directory change, until that input is resolved. An uncertain not-sent row or held input with no control has nothing of its own to clear it, so the way out is to wait for the turn to settle or to [change the provider](../../providers/resuming.md) and accept its warning; a queue-storage problem stays refused.

Workspaces are reordered by dragging their header within the same list (the top level or one collection); a press becomes a drag only after a few pixels of movement, so a click still expands or collapses the workspace. The other workspaces move aside to show where it will land, the sidebar scrolls when the pointer nears its edge, and Escape cancels. The pointer's position, not the lifted block's centre, picks the slot, so an expanded workspace moves as soon as its header passes a neighbour. A refused save, or one that has not answered after five seconds, glides the workspace back to where it was. Dropping onto another collection moves the workspace into it, with that collection highlighted while hovered, and dropping a grouped workspace outside every collection removes it from its collection, like the menu's Remove from collection. The keyboard path is Arrow Up/Down on a focused workspace header, which moves it one place and keeps focus on it; a polite status announces each pickup, cancellation and new position. Chats inside a workspace keep their time order and stay with their workspace; dragging one still opens it in a split pane. [Pinned](../pinned/pinned.md) and [Active](../active/active.md) chats can be put in a manual order the same way.
