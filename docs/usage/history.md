# Usage history

Historical usage offers Cost and Tokens views for a selected time window, this computer, a specific host or All machines. Provider filters affect the shown totals, chart and model/time breakdown together; changing them must not mix incompatible snapshots. Token categories remain distinct where reported, models and service tiers retain their identity, and the Time view identifies its time basis. Refresh preserves usable prior data while loading and discloses stale, incomplete, unavailable or failed machine collection. Missing sources are not zero usage, duplicate/fork records must not inflate totals, and diagnostics should explain known coverage gaps. Provider totals list every provider the build includes with its tokens and cost: a provider fully read with nothing in the range says No usage, one still being read or with read errors says so, one whose history cannot be read says Usage history unavailable, and none of them shows a zero cost. Totals still being collected are marked as figures so far, and amounts awaiting prices read Pricing… rather than claiming no known price. Reopening Usage or returning to a period shows the last answer for that machine, period and prices at once while a fresh answer loads in the background; refresh progress sits in the header beside a Refresh control that stays usable, and a previous period’s figures dim only when the new answer is noticeably slow. Limits is a separate account view and does not acquire historical meaning from the selected history period.
