# Account allowances

Limits reads account allowances independently of chats, without creating a conversation or sending a model prompt. Show scoped cached values immediately and keep known values during transient refresh failures; changed provider commands must not inherit old account values, and authentication or entitlement failure clears them. Distinguish loading, unavailable feeds, errors and a ready account that reported no window: a provider or computer without an independent reader shows its not-available explanation in neutral text, while failed reads keep the warning tone. Use provider-reported periods only; otherwise retain Primary/Secondary labels and unknown percentages. Freshness and reset labels advance on one shared local clock without requesting history, describe past resets according to provider evidence and never announce future resets as passed. Offer local Refresh allowances with visible cooldown feedback, initially show two model buckets with expansion for the rest, and format credits with grouped numbers and at most two decimals while retaining original text on hover. Remote feeds remain explicitly unavailable without a local Refresh control or repeated polling. Like a build-excluded provider, a provider disabled on a computer is not shown in that computer's Limits and no new account read starts there (a read already running finishes and is discarded); Settings is where it is turned back on.

Limits opens with one sentence of what matters: the provider closest to its limit (or the highest use when all have room) with its reset, or a calm explanation when no allowance is readable, followed by the selected period's token total. Below it, one Allowances card holds one compact row per provider: logo, name, plan, the provider's tokens for the selected period from the same history the Tokens tab reads, and its most-used window as percent used with that window's name and reset. The row's background fills to that share in the accent tint, turning to the warning or error tint from 80% and 95%; while the first read runs and no share is known the row sweeps. An unreadable allowance shows a short reason (Not signed in, Couldn't read, Needs access, Login expired, Not offered by the provider) with a warning status mark for failed reads and neutral text for unsupported feeds; the full native message stays in its tooltip and in the row details. Expanding a row shows freshness, the full message, every window as its own filled row (model buckets beyond the first two behind a further disclosure), spend limit, credits, the period token count and the latest chat's context and tokens, which stay collapsed. When Codex reports a Pro plan without a secondary window, show the requested 5-hour Unlimited row; a reported secondary window takes precedence.

Allowances belong to accounts and only this computer reads them, so Limits has no machine headings: All machines shows the allowances read here once, with tokens summed across machines. Selecting a remote computer explains once that allowances are read on this computer only and shows that computer's tokens, with no per-row not-available line. The column matches the Cost and Tokens tabs.

**Implementation: Partial.** Independent local readers exist for Codex, Claude, Copilot and Antigravity; Gemini requires an eligible existing account and can report provider denial. OpenCode has no integrated independent account-quota reader. Custom commands and remote acquisition remain unavailable. Google account reads reuse valid existing access tokens; expired grants can refresh only when the same credential profile provides its OAuth registration, otherwise refresh the login in the provider CLI. UAM embeds no Google OAuth registration values. Existing credentials must not trigger interactive login, project trust, onboarding or expanded access. On macOS, automatic reads never show a Keychain dialog; when access needs approval the row asks for Refresh allowances, and only that explicit refresh may show the macOS permission prompt. A phone refresh may prompt only when [Phone Access settings](../settings/phone-access.md) allow Keychain prompts from the phone. Historical token accounting and per-chat context remain separate.
