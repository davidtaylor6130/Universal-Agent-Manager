# Account allowances

Limits reads account allowances independently of chats, without creating a conversation or sending a model prompt. Show scoped cached values immediately and keep known values during transient refresh failures; changed provider commands must not inherit old account values, and authentication or entitlement failure clears them. Distinguish loading, unavailable feeds, errors and a ready account that reported no window. Use provider-reported periods only; otherwise retain Primary/Secondary labels and unknown percentages. Freshness and reset labels advance on one shared local clock without requesting history, describe past resets according to provider evidence and never announce future resets as passed. Offer local Refresh allowances with visible cooldown feedback, initially show two model buckets with expansion for the rest, and format credits with grouped numbers and at most two decimals while retaining original text on hover. Remote feeds remain explicitly unavailable without a local Refresh control or repeated polling.

**Implementation: Partial.** Independent local readers exist for Codex, Claude, Copilot and Antigravity; Gemini requires an eligible existing account and can report provider denial. OpenCode has no integrated independent account-quota reader. Custom commands and remote acquisition remain unavailable. Existing credentials must not trigger interactive login, project trust, onboarding or expanded access. Historical token accounting and per-chat context remain separate.
