# Permissions and notifications

Structured permission handling maps native provider decisions and UAM review to the four shared user choices while retaining Plan/read-only and managed restrictions. Claude native auto and confirmed Codex native auto-review coexist with UAM reviewer handling; residual prompts stay user decisions, and an opaque terminal is provider-controlled. UI notices use the shared product notification agreement; current implementation gaps remain explicit.

Captured agent-read and goal-review policy belongs to the runtime, independently of mutable chat defaults. Provider adapters identify the native operation, typed command and decision authority; display text and reasons cannot substitute for a missing command. The shared response boundary applies the same ceiling to manual decisions, automatic approvals, saved-response replay and frontend option projection. Only supported one-time reads, recognized non-action questions, denial and cancellation remain available; persistent grants cannot widen the ceiling. Filtering never rewrites native pending offers or request identity, and the backend revalidates replies. Unknown native shapes retain a safe denial or Cancel rather than an inferred approval.

Recovery requires a fresh normalized native request before a saved response can be reused. A stale approval cannot bypass a newly captured ceiling. Replacing it with a fresh safe denial or cancellation is a save-before-delivery transaction: save failure restores the old receipt and retains the pending request, without wire delivery. The captured boundary, typed command provenance, decoded replay, atomic safe-answer replacement and OpenCode question distinction are implemented with protocol verification and scoped source review. Desktop choice and journey acceptance remains inconclusive, and live-provider, Windows, SSH and user acceptance remain pending. Broader provider and environment coverage retains its existing limits. The literal command filter, including admitted Git forms, trusts the executable, repository configuration and environment, including pager, index-refresh and filesystem-monitor behavior; it does not provide operating-system isolation.

Copilot native plan decisions persist before delivery, retain the Plan ceiling and exact request and turn ownership until native mode confirmation, and save the confirmed policy before publishing the transition. OpenCode child approvals use the authenticated server belonging to the same provider process, validate ancestry, distinguish the native repeated-call question from a same-name MCP action and preserve uncertain decisions until a confirmed reply or complete pending-request snapshot settles them; an unrelated ACP output acknowledgment cannot settle HTTP delivery.
