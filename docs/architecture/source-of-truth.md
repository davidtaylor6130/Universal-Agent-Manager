# Source of truth

UAM owns its saved product state in the resolved data root; a provider's native history is an external session source, not authority to overwrite UAM organisation, authored intent or recovery records. Native services reconcile durable records into runtime models and React projections. Authority is field-specific: never choose whichever file, timestamp, cache or screen looks newest without the repository's revision and ownership rules. Keep [existing storage routing](app-state-persistence.md) and user data in place.

| Record | Authority and boundary |
|---|---|
| `chats/<chat-id>.json` | Canonical saved UAM conversation and chat metadata, including native session links and persisted control state; load through ChatRepository and supported migrations. A UAM ID, provider session ID and process ID are distinct. |
| `chat-summaries/<chat-id>.json` | Lightweight transcript-derived fields **and durable metadata overlays**, including attention, snooze and recency values that may be newer than the primary. Preserve valid overlays when hydrating or regenerating; do not bulk-delete these as disposable caches. |
| `queue-outboxes/<chat-id>.json` | Revision-bound queued-input journals reconciled with the primary full-save revision. Retain authored input and delivery/recovery ownership; an arbitrary newest-file merge or missing process does not prove input was never delivered. |
| Chat message-page indexes | Derived navigation into a specific primary transcript. Stale or invalid indexes can be regenerated through repository validation; they do not replace message content. |
| `legacy-data-imports.json` | Copied and declined ("Brand new") earlier-release data roots and the chat/folder IDs they imported. Recorded sources and IDs are never offered or imported again, so user choices and deletions hold; it is not a cache. |
| `.bak` companions | Validated recovery candidates, not competing live primaries. Use supported backup validation and publication rather than manually choosing by modification time. |
| `settings.txt`, `folders.txt`, `resource_collections.json` and their owning stores | Persisted configuration, environment overrides and organisation. Use the relevant serializers/services, including collection/reference storage, rather than reconstructing them from visible sidebar rows. |
| Default-root `.data-folder-control/selection.json` and `intent.json` | Native bootstrap folder-choice record and retained publication receipt, serialized under an independent control lock. Version 1 stages/cancels a preference only; pending or uncertain publication never selects a destination, transfers queue ownership or authorizes restart. An external startup override bypasses these records. |
| Bootstrap `transition.json`, `transition-intent.json`, phase archives and root `.uam-data-folder/receipt.json` with its `receipt-intent.json` acknowledgement | Version 2 stopped-transfer authority, with exact write-ahead acknowledgement, root identities, logical inventory digests and physical object witnesses; pending selection never substitutes for it, unknown publication/startup holds both roots, and active destination writes never authorize rollback to an older source. Historical source locks and snapshots remain retained through later choices. Root receipts carry the bootstrap locator but never independently grant writes: helpers/control writers must verify the matching final acknowledged transaction, root identity and digests under their shared writer lease, including after a failed manager exits. Root fences must precede uncertain staging, and an armed follow-up cancellation must acknowledge the current root consistently before restoring independent writes. Startup and later arming must validate the exact current restored-source receipt and acknowledgement too; an older receipt cannot substitute, and only a proven first plain cancellation permits no receipt. Retained directory witnesses and IO handles must refer to the same filesystem object. Preserve exact owner-significant modification times as well as bytes; summary freshness and queue base revisions retain their existing owner rules. Receipt and acknowledgement reads must stay bound to the same retained metadata directory through combined admission. Bootstrap primary/acknowledgement witnesses must also stay current through startup, reopening and independent-writer admission; readable earlier primary bytes never authorize a missing or replaced current primary. Independently retained remote-delivery and interaction-response authority, including the owning decoder's legacy singular-field fallback, must settle in the source before transfer. Any queued managed-turn key, including a null identity, retains the repository's unresolved managed-input hold rather than proving settlement. New destinations cannot overlap the bootstrap/default directory or any retained source/passive snapshot in either ancestor direction; selection, arming and stopped activation revalidate that exclusion by directory identity. |
| Agent/skill/instruction and memory files | User-managed resources with their own global/workspace scope. Referencing or indexing a file does not authorize overwriting it; memory and instructions are not recovered from arbitrary chat prose. |
| Agent-run ledgers, deletion intents and workspace/remote recovery receipts | Durable execution, cleanup and ownership evidence. They are not caches; preserve unresolved work and tombstones until the owning service settles them. |
| Usage ledgers, imported receipts and account snapshots | History facts and identity witnesses are distinct from derived aggregates; quota snapshots record an account observation, not the present balance. Consult the usage service before removing retained state. |
| React/Zustand state and browser preferences | Native-backed values are projections/drafts until native acknowledgement. Some appearance and usage-price preferences are deliberately local to the frontend; they are not substitutes for native settings or chat files. |
| Provider transcripts, logs and terminal output | External conversation evidence or diagnostics. Import/refresh must preserve native identity, tombstones, UAM-only metadata and newer owned work. Logs and terminal text do not authorize replay, deletion or execution. |

Per-input identities belong to the authored message or retained input; a recorded full-write observation belongs to the authored message. An originating action identity correlates a bridge request, not idempotency or retry permission. A completed local write records the captured input sink accepting all bytes, not remote consumption or provider parsing. Saved facts remain historical data after execution ownership ends. Editing authored text, attachments or captured skills invalidates the previous full-write observation for that changed input; an unchanged edit preserves it. Native import and refresh must retain those facts with the canonical history or refuse an ambiguous replacement; matching text, time or position cannot relocate them to another input. Missing or false observations do not prove that delivery never occurred.

Data-folder transfer refuses duplicate-key structured records rather than letting differing parser precedence change execution or reference authority. On disagreement, stop the affected mutation, retain evidence and use the owning service's guarded reconciliation. A save failure must retain the draft or restore the previous authoritative state; success is reported only after the relevant commit acknowledgement. A passive export or test-profile copy must not acquire live queue, agent-run or remote-control authority.

Saved SSH host installation authority includes `runnerInstallUnresolved` and the pending `runnerInstallNonce`/`runnerInstallIdentity` binding. The owning controller saves this fence after target-lock acquisition and before authorising recovery or activation. Failed or unknown transaction outcomes preserve this fence across reload; a successful runtime handshake or health observation cannot clear it or promote the host to Ready. Only confirmed commit or verified restoration of the previous installation settles that authority; uncertain replies cannot substitute for either. Installed manifest/checksum facts remain separate from resident process identity and owned runtime handshake evidence.
After an unconfirmed native refresh, a passive saved-primary history read is a display observation. Recheck its owner and physical revision before returning a bounded page; reading it does not acknowledge originals, adopt the uncertain candidate into the live runtime or grant another publication attempt. Image and tool detail reads carry the displayed history digest and must match that observation’s physical revision and exact detail identity. Selection recency and validated eviction permit a fresh read witness while publication authority remains unchanged. Derived message-page indexes retain their existing cache role.

Memory-setting actions distinguish native commit receipts from primary-only settings observations. An app-instance publication revision fences stamped requests before mutation and advances on settings save/load attempts; it is not a durable file revision, cross-process compare-and-swap or replay permission. Unknown memory writes require primary validation before another settings save republishes those fields, and a recovery backup alone does not establish current-primary authority.

A lost memory-save acknowledgement does not prove that the live runtime or primary file stayed unchanged. The uncertain candidate may remain effective until guarded primary reconciliation resolves it. Current React clients fence their explicit field changes and reconcile all covered fields from a committed receipt; existing unstamped phone clients retain arrival-time write behavior and are outside that stale-request guarantee.
