# Provider sessions

Provider adapters translate ACP, Codex app-server, Copilot SDK server and native stream-JSON protocols into one UAM lifecycle and message model. Native terminals use a separate PTY path. Shared UAM services provide product features across providers, while adapters own launch/protocol handling and native session identity. Start, cancel, exit, resume and permission results must stay with the owning chat, including concurrent and remote instances.

Shared [goal](../chat/goals.md) resume and restart consult the provider adapter before changing goal state, preparing a workspace or allocating a runtime; an unsupported native control must fail there instead of becoming an ordinary prompt or an inferred lifecycle acknowledgement.

Antigravity's UAM goal workers preserve the chat's native conversation while private reviewers clear it from launch arguments and retain Plan. Adapter-bound observed usage and durable pending-usage markers fence budgeted continuation across interruption; goal controls reach owned process cancellation only after their saved receipt. A direct service control restores prior goal intent and leaves the owned turn uncancelled on save failure; the CEF path keeps its existing asynchronous full-save receipt. Active local metered retirement retains its owned process and Restart fence until exit is observed; bounded reviewer repairs retain their private native identity. These are UAM lifecycle decisions, not native Goal RPC receipts or managed execution-policy attestation.

OpenCode supplements ACP with an authenticated permission relay to the HTTP server in that same process; native Terminal View uses a separate server owned by its TUI launch. Endpoint credentials and exact native ancestry fence each request, and Plan restrictions are retained where native children cannot inherit them. The [OpenCode workspace agreement](../providers/opencode/opencode.md#workspace-identity) permits only ordinary DOS separator spelling differences on SSH Windows hosts without changing native identities or widening permission authority.

SSH history uses bounded immutable native snapshots from the execution host, then the existing guarded history publication path. Parent-owned child journals are read-only UAM records, distinct from provider resume IDs; saved protocol identity also prevents an old Copilot ACP process from being reused as an SDK server.

Terminal-history workers remain application-owned after their terminal closes. A captured launch identity permits guarded history import, never provider execution; original preparation and retirement stay on bounded workers, while the application revalidates the current owner and saved revision before publication and adoption. Confirmed process exit precedes final source loading, and shutdown explicitly settles or cancels outstanding work before releasing application state. Metadata-only changes use a fresh saved baseline while original authored content and identity remain guarded; unloaded owners retain their original primary until reconciliation settles. Periodic history loading yields to pending final reconciliation. Periodic parsers use separate bounded lifetime capacity so retained snapshots cannot occupy unrelated preparation slots, and completed results retire after their last bound terminal stops.

Managed child runs retain separate ledger and transcript identities. Listing reads durable metadata off the UI thread and revalidates the originating owner before publication; individual stops remain bound to their admitted subtree through deferred persistence. Recorded terminal epochs provide durations for new outcomes, while older records retain unknown duration. Compact thread cards use the owned child’s provider, bounded output preview and recorded timing; saved and live tool projections retain this metadata independently of deferred full details, and private task definitions and diagnostics are not summary fallbacks. Native child identities remain separate from managed run IDs and never authorize a hidden transcript as an executable chat.

Committed managed-run changes publish an ephemeral revision on the owning visible root to trigger discovery, including when no parent provider turn runs. This signal survives same-chat hydration but is neither persisted execution authority nor a substitute for validated ledger reads. Live observation never repairs a ledger backup; startup recovery retains that separate responsibility.

The versioned continuation ledger retains exact per-turn ownership and saved policy while startup records remain outside execution inventory. Within the current controller lifetime, the child conversation can explicitly continue local named-Claude UserRoot children and read-only named OpenAI Codex and GitHub Copilot UserRoot children from their owned completed-session witnesses. Codex revalidates its exact native resume before adopting returned identity and holds input until authoritative effective Plan settings arrive; contradictions revoke that attempt through final delivery and witness retention. Broader provider or principal coverage remains incomplete, and unsupported queued input stays held rather than being replayed or replaced by ordinary backup recovery. A validated consumed queue revision does not import stale managed authority into a later canonical save. Persisted records alone establish neither submission permission nor a provider resume witness. Initial managed execution can retain a controller-observed native session, selected model and saved child configuration after confirmed completion and process reaping; missing or contradictory observations leave that binding absent. Saved inspection strips private execution configuration from display metadata and revalidates the original canonical binding without restoring execution ownership.

Managed setup admits an exact queued task through the existing row and save pipeline before negotiating native policy; setup readiness and the existing input gates still control delivery. The scheduler owns immutable run/turn/process/birth correlation, actual-input and saved-generation receipts, and completed/reaped continuation witnesses; the provider adapter owns native compatibility, restrictions and readback. [Copilot](../providers/copilot/copilot.md#managed-continuation) injects its native read policy on create and exact resume and gathers fresh current-process evidence. Granting new proof requires the strict current owner and admitted row; retaining already observed proof through ordinary completion, save and stop still checks current policy without granting new authority. Drift revocation follows the same immutable transaction even when configuration changes, preventing later restoration from reviving a rejected observation. Missing initial proof leaves a truthful unbound one-shot; missing or conflicting resumed proof refuses input. Broader runtime, platform and acceptance gates remain explicit.

Native-child catalogue lineage uses separate UAM parent display metadata and the parent’s creation time, independently of provider resume IDs and branch relationships. React validates that display relationship before nesting or returning to a parent; supported child runtime controls continue to use the child’s own existing authority. Managed transcript panes retain their validated run/transcript route and do not become ordinary executable sessions.

Live native model options remain adapter-owned observations of an existing structured session. Controls bind to that observed session lifetime, preserve native eligibility and confirm changes through provider replies or events; request acceptance does not establish an effective preference. Resume refreshes the native observation without replaying a stale UI choice or changing another chat’s defaults.

Explicit saved-image Retry uses invocation-only permission from the selected current user row; persisted attachment metadata alone grants no input authority. The adapter-supported worker reads originals under the final chat owner; explicit supported SSH Retry binds that read to the same existing remote native process and captured connection rather than granting ordinary Send or replacement-process authority, and the shared runtime rechecks that same permission through the durable save receipt and final delivery. Native adapters capture effective model and policy before preparation and bind the final request to its actual allocated identity through delivery. Stop, changed ownership, declarations, saved native binding or native settings revoke the permission without changing the saved originals or ordinary Send validation.

Copilot obtains saved-image admission evidence through owned read-only native queries before reading originals. Accepted running-version, model and image restrictions stay bound to that invocation through preparation and final delivery; timeout, conflicting observations or changed ownership refuse it without a replacement attempt. OpenCode obtains its corresponding current-model evidence through the authenticated companion belonging to the same ACP process and workspace; its image checks have separate bounded work and cannot change native permission decisions.

New built-in agent captures use versioned definitions that permit primary selection and delegation. Historical captures retain their original mode, instructions, permission ceiling and definition identity during recovery; decoding a saved definition does not upgrade its execution authority.

The shared [active-turn child wait](../chat/subagents.md#active-turn-result-wait) binds one deferred read to the original capability, MCP connection, native turn and owned descendant. Its terminal status is sealed once and published only after the existing full-save pipeline acknowledges the matching audit record; queue-only or generic save callbacks grant no response authority. Cancellation and owner changes retire the read without mutating the child. The stdio proxy retains sequential dispatch and bounded input buffering while observing cancellation and EOF; platform services own pipe readiness. This source implementation does not establish native CLI View support, ended-turn wake, provider deadline compatibility or live SSH acceptance.

The source-integrated [same-live parent continuation candidate](../chat/subagents.md#same-live-parent-result-continuation) separates retained delivery DATA from an invocation-derived runtime lease. Shared admission owns the exact root, process, policy and authored boundary; the opted-in adapter owns normal completion and the exact native RPC acknowledgement. Existing repository publication receipts fence both admission phases, and a potentially written input is never automatically replayed. No lease is decoded after restart, and child-result bookkeeping is not native consumption evidence. Parent-owned immutable per-input receipt DATA survives later batches, child-ledger removal and native-history reconciliation; it classifies only exact scoped native inputs and never restores execution authority.
