# Chats and workspaces

Chat services own conversation creation, selection, organisation, branching and deletion; workspace services own working directories and optional repository preparation. Native imports link an external session to the correct UAM chat without duplicating or discarding supported history. Display folders, native identities and worktree ownership must remain separate so a failed import or cleanup cannot damage unrelated work.

Local passive child originals use the owning provider adapter’s explicit capability and the actual scoped native reader before shared prepared-media publication. The bridge revalidates parent, child, request and saved revisions before adoption, and original acknowledgement remains background work; a passive reference grants no resumable session or execution ownership.

Supported remote saved-owner history refresh keeps executing-host provenance while the controller prepares, publishes and acknowledges original files under the exact UAM owner. Revalidate host/profile, live conversation and saved revisions before publication; a history read grants no new runtime or input-delivery authority, and uncertain confirmation after commit retains the saved conversation and originals.
