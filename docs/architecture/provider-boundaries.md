# Provider boundaries

Provider-specific launch arguments, wire formats, native session identities, model capabilities, permission mappings and history parsing belong in provider adapters behind the runtime contract. Shared UAM services own product behaviour such as chat organisation, authored input, branching and fallback decisions; they consume normalized events and advertised capabilities rather than testing provider names throughout the UI. Add explicit adapter support when protocols differ, preserve provider-specific restrictions and use UAM equivalents where the shared agreement requires them. A native limitation must not silently redefine the common feature.

**Current structure:** [runtime interfaces and registry](../../src/common/provider/provider_runtime.h) connect the six adapters under `src/common/provider/` with common ACP and terminal machinery. Native app-server and stream JSON remain valid routes. Existing provider branches are not proof of complete modular isolation; new work should respect the boundary and document any required exception. Update the [shared requirements and provider checklist](../providers/providers.md) in the same change.

**CLI View handoff staging:** the [terminal launcher](../../src/common/runtime/terminal/terminal_provider_cli.cpp) owns the shared steps (choosing and claiming the private context folder, writing `conversation.md`, recording cleanup and the remote handoff channel), then asks the runtime's `StageCliHandoffContext` to make that provider load the snapshot. Claude Code adds `--append-system-prompt-file`, Copilot writes `.github/instructions/handoff.instructions.md` and Gemini writes `GEMINI.md` with `--include-directories`; Codex (imported into native thread history) and OpenCode (read through its configuration environment) keep the empty default, and Antigravity writes `AGENTS.md` with `--add-dir`, which only a custom agent's instructions reach because its terminal refuses another provider's conversation earlier. Launch options go ahead of any positional `--`. The launcher no longer branches on provider id for these files; an id that is not an exact included provider keeps the refusal it always had. Remaining known exceptions: provider environment setup in [`provider_native_context.h`](../../src/common/provider/provider_native_context.h) still branches on provider id, and the launcher keeps the Codex rule that a handoff already imported into the bound native thread is not replayed (one named check; the remote launch in [`terminal_launch.h`](../../src/common/runtime/terminal/terminal_launch.h) still spells it out for the launch profile) and the early Antigravity refusal.
