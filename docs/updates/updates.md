# Updates

Updates distinguishes the desktop application, provider CLIs and remote helpers, including installed/latest version, available action and failed checks. Users can check manually or enable automatic checks; checking is not installation. Provider updates must disclose running sessions and require the appropriate stop decision rather than disrupting work silently. After installation, the observed version must satisfy the requested update: exact selections remain exact, while a package manager that installs its current latest may install a newer version but must not report the requested numeric update achieved below that version. Application releases may open a release/download or manual instructions rather than promise in-place installation. Remote helper activation retains its own compatibility and active-work checks. Surface failures and uncertain versions, retain release information and distinguish dismissing an update notice from cancelling or completing installation.

Available UAM and managed provider updates show a collapsed release-note excerpt when the checked release supplies one. Excerpts are bounded to 500 characters, presented as plain text and tied to the displayed version and installation method, including a selected remote computer's provider update. Expanding an excerpt does not install or dismiss an update; a different available version starts collapsed. Missing notes add no placeholder or invented summary, and release links and installation actions remain available under their existing rules.

Like a build-excluded provider, a provider disabled on a computer in [Provider settings](../settings/providers.md) is not offered, version-swept or automatically updated there; turning it back on checks its installed version again.
