# Notifications

Chat lifecycle notices belong in the transcript; app-wide failures, warnings, completed system actions and update notices belong in the bell panel with one shared transient alert surface. Features must report through the shared path rather than adding independent popup systems. This is the agreed product direction recorded in the [decision record](../architecture/decisions.md); review and user testing remain pending in the V5 log.

- Chat status notices (refreshing history, compacting, waiting on subagents, stopped/timeout and response interrupted) are inline transcript dividers, never composer-docked or tagged on a message.
- The compacting divider shows its existing scene, label and elapsed time without a context-fill meter; verified summary text stays hidden during generation and appears only inside the collapsed completed or interrupted summary.
- Direct input keeps its stable message position in the transcript, with pending or definitely undelivered input shown as a muted dotted message with an accessible explanation and guarded recovery actions; direct startup or restart input must not be labelled as future queued work. Legacy rows retain original message positions and offer Retry only when native recovery permits it. A real future queue entry referring to the same input replaces the duplicate recovery row. Partial-output or uncertain-delivery turns remain in the transcript with an interruption divider.
- One notifications panel (the bell rail) holds every app-wide message: failures, warnings, completed system actions and available updates.
- One shared transient alert (`TransientAlertSurface` in `AppShell`) uses one persistent, initially empty polite announcement region for each retained notice, without duplicate live announcements from the visible surface or no-fit description, and briefly shows each new message at the GUI viewport’s bottom edge while preserving its existing horizontal alignment beside the right-hand notification/update rail. The shared popup may cover the composer, including Send; composer growth and first-send movement keep the same bottom-edge anchor. Available height stays below pane headers and window controls; long text scrolls in a keyboard-accessible region while actions stay visible. If the viewport cannot hold a readable message and its actions, a polite announcement directs users to the retained notification through the bell, which exposes that description and keeps its unread count. The alert auto-dismisses while idle, pauses while hovered or keyboard-focused, and leaves the message in the panel. An open right-side panel suppresses the popup while each newly retained notice still announces once; closing the panel does not resurface or repeat it. The panel replaces the transient surface so it cannot cover that panel’s controls; focused dismissal or loss of usable space returns focus to the bell.
- No feature-specific popups or toasts. Features report failures through `reportAppFailure` (`utils/appFailure.ts`).
- Organisation operations offer no undo toast or organisation-undo shortcut; ordinary text-editor undo remains available. Failed changes are reported through the shared path.

The no-undo agreement concerns organization operations; it does not remove ordinary text-editor undo. [Sending](../chat/sending.md) and [compaction](../providers/compaction.md) own their behaviour; the notes here specify presentation. Do not describe the target notification system as universally shipped until the pending work is resolved.

The panel exposes unread state/counts, mark-all-read and individual dismissal; these change notification state without stopping the underlying task, deleting chat history or declaring a failed operation fixed. Actionable entries retain their relevant details and current confirmation rules.

Every panel entry shows a relative age as its accessible name, with its full local date and time supplied once through the tooltip description on keyboard focus or hover. Timestamps use the shared visible keyboard focus indicator. UAM records when the running shell first observes each notice identity, using a valid recorded failure time when available; reopening the panel, marking read and unrelated state updates do not reset that time. These times are local session metadata, not a durable notification history or a provider event time: resolving a source ends its retained timestamp, and a later recurrence or app restart is observed anew. The panel groups notices into Today and Earlier at local midnight, newest first within each group, while preserving warning/error cues and focused controls. Relative ages and groups refresh when the panel opens, every 30 seconds while the nonempty panel is open and when the window regains focus or visibility, without repeating announcements or changing unread state. A future recorded time displays Just now until the local clock catches up and stays out of Earlier.
