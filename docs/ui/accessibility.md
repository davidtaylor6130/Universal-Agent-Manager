# Accessibility

Every control is keyboard reachable with visible focus and an accessible name; icon-only actions need meaningful labels and tooltips. Dialogs and menus must manage focus so actions reach the intended surface and returning preserves the user’s place. Loading, errors, progress and selection must remain understandable to assistive technology and without colour alone; state differences use an icon plus colour rather than extra words, and custom themes let users choose semantic status colours (error/stop/cancel, success, warning) so colour-blind users can tell them apart. Honour reduced motion without hiding working state, and keep text legible in every built-in theme.

The focus ring is one outline, `outline: var(--focus-ring)` from `UI-V2/src/index.css`, so it follows the focused element’s own border-radius. It sits `--focus-offset` (2px) outside the shape by default. Rows, menu and option items, tabs and tree items flush inside scrolling or clipping containers use `--focus-inset` (-2px) instead, so a scroll area never cuts the ring. When the visible shape is a wrapper around an inner button, such as a context chip or the composer goal tab, the wrapper draws the ring through `:has(:focus-visible)` and the inner button draws none. Text-entry fields (input, textarea, select, NumberField, search fields) and MenuSelect triggers always use `--focus-inset`, applied globally, so a dialog body, settings scroll area or Swap can never cut them; their own border does not change colour on focus. Containers that clip only for motion or horizontal scrolling (the sidebar collapse, the composer status-chip strip and a busy indeterminate ProgressFill row) set `--focus-inset` for everything inside, and Swap keeps a 4px `overflow-clip-margin` so an outside ring survives its clip. Components do not draw their own focus shadows or border changes, and they do not use Tailwind `focus-visible:ring`/`outline` classes; they only pick the offset.

Settings rows expose their consequence description and status line to their control (or control group) through `aria-describedby`; pending saves mark the save button busy and announce the pending label in a polite live region. Text and icons on an accent fill use `--on-accent`, one of the theme’s own colours chosen to reach WCAG AA 4.5:1, rather than fixed white. Interactive elements are never nested inside another interactive role, and controls revealed on hover are also revealed while keyboard focus is in their row; workspace headers stay in the Tab order while searching and in the phone view. Custom themes let users choose semantic status colours — error/stop/cancel, success, warning — so colour-blind users can adjust them; success and failure share one colour with a tick/cross icon.

Known allowance values, including zero, use numeric meter semantics; unknown tracks are decorative and must not announce a fabricated number. Reset announcements distinguish future, provider-reported past and stale cached values. [Allowance behaviour](../usage/allowances.md) owns the display rules.

Preserve existing roles, labels and test intent when reorganising a surface. An intentional wording change can update a matching assertion, but removing an assertion does not make an inaccessible control acceptable. [Primitives](primitives.md), [motion](motion.md) and [UI review](review.md) apply to each state.
