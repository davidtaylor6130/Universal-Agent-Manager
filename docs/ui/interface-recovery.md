# Interface recovery

An interface or lazy-panel failure should remain contained so unrelated chats stay available and owned provider work is not silently stopped. The recovery surface distinguishes dismissing a failed panel from reloading the interface, warns about unsaved draft loss and moves focus to usable recovery actions. Reload refreshes the UI; it is not permission to replay prompts, restart a provider or discard durable recovery state. Loading, unavailable native bridge and network disconnection must not masquerade as a successful empty workspace: until the startup state first loads, the sidebar shows a shimmering loading list (motionless under reduced motion or Motion Off) instead of an empty chat tree. If the startup state cannot be loaded, because the backend reports an error, returns an invalid state or keeps answering with a state older than live updates, a persistent error notice above the chat panes shows that reason and offers Retry. Retry stays focused and busy while it runs, a Retry that fails again adds a numbered "Retry failed" line so the alert is announced again, and the notice clears as soon as a full startup state loads.
