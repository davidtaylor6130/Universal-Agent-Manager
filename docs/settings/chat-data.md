# Chat Data settings

Chat Data exports saved conversations as a portable bundle into a new or empty folder and imports bundles without overwriting existing chat identities; collisions receive new IDs. Preserve supported history and organisation while reporting skipped or failed items. Imported bundles are passive read-only transcripts until explicit supported reconnection: saved runtime IDs, queued input, goals and remote cleanup metadata must not start work merely because files were imported. Export is not a live transactional backup of running provider processes or every application setting. Earlier-release data found beside the executable or in the old default folder is not a bundle: a startup prompt offers to copy it as if upgraded in place, keeping chat IDs and provider session links and skipping IDs already stored ([persistence](../architecture/app-state-persistence.md)).

## Native provider histories

Chat Data also provides explicit system-wide native history discovery/import for all six supported providers, separately from portable bundles. Discovery reads the current user's provider history stores on this computer and stages eligible conversations for review; importing requires an explicit selection. Show supported scope from the desktop provider catalogue, eligible/imported counts and discovery failures with omitted-issue totals, preserve existing UAM chats, tombstones and native ownership, and prevent duplicates across repeated scans. Discovery does not resume sessions, delete provider history or migrate UAM data; SSH discovery remains a separate execution-host scope, and an explicit local rescan retains settled remote candidates. OpenCode discovery is scoped to the current project's directory because its `session list` command is per-project; sessions in other projects are not listed, and the all-projects `session.list` API route is identified but not yet adopted.

Histories with an absolute native workspace outside the registered catalogue remain in review. Assign workspace stages a name for that original local directory, shared by histories with the exact same source path; aliases and verified linked worktrees reuse their resolved staged owner, while conflicting assignments are refused before import; it does not relocate native history, create a filesystem directory or save catalogue entries. A selected import requires assignment first. Assignment retains the review page, filter and current selection; Escape cancels the name draft before closing review. Staging or cancelling assignment returns keyboard focus to the affected history; closing review returns to its initiating control when available. New UAM workspace entries publish through the guarded folder save with selected chats, and failed/empty imports retain existing cleanup behavior. Changes to ownership, tombstones or the captured workspace catalogue can invalidate publication; discovery and assignment never authorize resuming a provider turn.

All six providers now have source-integrated local readers feeding assignment and selected publication; OpenCode requires its configured CLI. Antigravity reads bounded, settled native CLI SQLite snapshots and authenticated legacy protobuf histories under the [observed storage contract](../reference/antigravity-native-history-decision.md), preserving original identity/workspace and rejecting changing, nested, malformed or unrecognised histories rather than importing a prefix. Its storage-version coverage remains Partial, and runtime, platform and UI acceptance remain unverified; see [open import scope](../documentation-review.md#system-wide-native-import).
