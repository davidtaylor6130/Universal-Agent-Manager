# Compute Pools

Compute Pools limit how many chats may use a provider or model at the same time, for hosts that can only serve a few turns at once. With no pools configured, nothing changes: every turn is sent as soon as it is ready. A pool has a name, a limit from 1 to 64 and one or more provider-and-model members; a member with All models covers every model of that provider. Pools are global and cover every computer a chat runs on.

A turn is checked when UAM is about to send it, after its provider is ready, and it counts for every pool it matches: chat turns, sub-agents, goal iterations and automation chats alike. A chat on its provider's default model matches a model-specific member only once the provider has reported that model, and some providers never report one, so a pool meant to cover default-model chats needs All models. It runs only when every matching pool has room; otherwise it stays in its chat with the visible status “Waiting for <pool> slot (n/m)” and starts by itself when a slot frees. A turn never takes a slot an older waiter could claim, so a turn in overlapping pools can wait behind an older one even while its own pool has room, and a chat's queued input stays in order behind its held turn. A held turn whose provider process restarts rejoins the line at the back. Stop removes a held turn from the line without contacting its provider, and the status disappears as soon as the turn is admitted.

Slots are counted from running turns each time, so a turn that completes, fails or is cancelled, a provider process that dies and a deleted chat all free their slot with no separate release. An unstopped turn on a remote computer keeps its slot while UAM reconnects to it, because it is still running there; pressing Stop frees it. A chat waiting in `agent_wait` for its own child does not hold a slot, otherwise a pool shared by parent and child could never progress; the parent can briefly take the count over the limit when its child is still running and it resumes. A turn waiting for a permission answer keeps its slot. Time spent held does not count against a turn's inactivity limit or a sub-agent's 30-minute run limit.

Steer needs a turn that has reached the provider, so a held turn refuses Steer and the composer sends a new message to the queue instead. A steer that interrupts a running turn starts a new turn, which waits in line like any other. Managed sub-agent results delivered to a parent, manual compaction, native mid-turn steering and the first turn of a Codex native goal are not held, because they continue work already running; they do count towards use.

The Compute Pools page lists each pool with its members and its current in-use and waiting counts. Machine-wide pools, a per-chat pool picker and restoring a wait across an app restart are deferred: after a restart the message stays in its chat for Retry, as any undelivered message does, and is checked again like a new turn. CLI View input is typed straight into the provider's terminal and is not held.
