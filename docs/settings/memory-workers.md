# Memory workers and budgets

Memory Settings maps each conversation provider to a supported extraction worker provider/model; this can differ from the model answering the chat. Changing worker provider clears an incompatible model selection. Idle delay controls when eligible chat memory is processed, and recall budget bounds how much saved memory is added to a prompt; neither setting expands the memory policy or authorizes a manual scan. Last run, worker status and bounded diagnostic output describe an observed extraction attempt, not proof that valid memory was saved. Failures must retain actionable state without exposing sensitive conversation or memory contents in routine logs.

Side work (memory extraction, chat titles, commit messages and the AI Review permission reviewer) runs as an isolated tool-free worker. A worker with no chosen model uses the provider's low-cost model: Haiku for Claude Code, Flash Lite for Gemini and GPT-5.4 Mini for Codex. OpenCode and Copilot have no stable low-cost model name, so they keep the provider default. A model the user chose always wins. Claude workers load no user or project settings (hooks, plugins, `CLAUDE.md`), MCP servers or skills, like Codex's `--ignore-user-config`; Gemini workers load no extensions or MCP servers but still read the user's `GEMINI.md` and hooks, which Gemini CLI cannot switch off per run. Each message sent to the extraction worker is cut to its first and last 2 KiB when longer than 4 KiB, with a note of the omitted size, so a pasted log cannot make one scan expensive.
