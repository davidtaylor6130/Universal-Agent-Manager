# Provider settings

Provider pages configure CLI availability, launch preferences and supported provider-specific choices for the selected execution environment. Installed/running/version state is observed status, not a saved preference. Refresh and installation target the chosen computer and should not switch an existing conversation’s model merely because discovery finishes. Build-excluded providers must not appear as configurable choices.

OpenCode exposes **Progressive MCP discovery** as an immediate-save, native-backed launch preference for the selected computer. Its current implementation controls UAM's automatic V1 Code Mode opt-in, defaults to enabled when unset, and retains the checked executing-host version gate and explicit native environment precedence. Switching it off removes UAM's automatic opt-in; it does not disable MCP server registration or overwrite an explicit CLI environment choice or native configuration. Discovery preferences remain independent from configured server overrides even when their identifiers match. Existing processes retain their captured setup. As with the provider connection controls, All environments targets this computer here; selecting an SSH computer saves only that host's OpenCode choice. Failed or unconfirmed replies must not display the requested value as saved, and an unavailable setting remains visibly unknown and disabled. Pending saves belong to their exact computer, provider and control type regardless of punctuation in server identifiers; an older reply cannot clear a newer save indicator. This preference does not establish V2 discovery support or configure its session/location MCP registration. [OpenCode compatibility](../providers/opencode/opencode.md#progressive-mcp-discovery).
