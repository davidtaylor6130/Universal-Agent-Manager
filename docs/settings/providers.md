# Provider settings

Provider pages configure CLI availability, launch preferences and supported provider-specific choices for the selected execution environment. Installed/running/version state is observed status, not a saved preference. Refresh and installation target the chosen computer and should not switch an existing conversation’s model merely because discovery finishes. Build-excluded providers must not appear as configurable choices. The CLI manager's Last output shows only the CLI's own output: UAM's internal probe marker lines (CLI path, running state, process IDs, npm maintenance status and interactive-update markers) are removed when it is sent to the UI, while the stored remote probe keeps them for update identity checks.

On Windows, provider CLI checks and launches on the desktop and through the SSH helper also search user and machine PATH entries added since that process started, so a CLI, Node.js or PowerShell 7 installed while UAM is open is found without signing out. npm `.cmd` shims run through `cmd.exe`.

OpenCode exposes **Progressive MCP discovery** as an immediate-save, native-backed launch preference for the selected computer. Its current implementation controls UAM's automatic V1 Code Mode opt-in, defaults to enabled when unset, and retains the checked executing-host version gate and explicit native environment precedence. Switching it off removes UAM's automatic opt-in; it does not disable MCP server registration or overwrite an explicit CLI environment choice or native configuration. Discovery preferences remain independent from configured server overrides even when their identifiers match. Existing processes retain their captured setup. As with the provider connection controls, All environments targets this computer here; selecting an SSH computer saves only that host's OpenCode choice. Failed or unconfirmed replies must not display the requested value as saved, and an unavailable setting remains visibly unknown and disabled. Pending saves belong to their exact computer, provider and control type regardless of punctuation in server identifiers; an older reply cannot clear a newer save indicator. This preference does not establish V2 discovery support or configure its session/location MCP registration. [OpenCode compatibility](../providers/opencode/opencode.md#progressive-mcp-discovery).

## Custom ACP agent

Builds with the opt-in `UAM_ENABLE_RUNTIME_CUSTOM_ACP` flag add a **Custom ACP agent** page, labelled best effort, instead of the CLI version and connection sections. It holds one agent: a name, a command (a program name or full path), arguments one per line and environment variables one `NAME=value` per line. Arguments are passed exactly as written as separate elements, never through a shell. Saving stores the agent in UAM's own data folder; nothing in a repository or chat can change it. Below the form, **Command to run** shows the exact command and the environment variable names it sets. A saved command that is new, or whose command, arguments or environment changed, must be allowed there before the first launch; renaming keeps the approval. Save, allow and load failures appear in the notifications panel as one line. This page is the only place the agent's launch is configured.
