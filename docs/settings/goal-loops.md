# Goal Loops settings

Goal Loops settings bounds continuing goal work through a maximum iteration count and sets the global token budget for newly created goals. A budget of zero is unlimited. An explicit per-command goal budget can override this default. Existing goals retain their saved budgets. Provider setup inactivity timeout separately limits setup with no progress; turn output limit bounds one provider turn and excludes startup history. Provider turn timeout stops a turn after that long without provider activity; it is adjusted in 15-minute steps and OpenCode also receives it as its provider request timeout (see [OpenCode turn timeout](../providers/opencode/opencode.md#turn-timeout)). A turn stopped by a timeout shows a transcript notice naming the limit and its value with **Restart with +15 min**, which saves the raised value and re-delivers the same user message in place when the turn produced no output. These are different safeguards, not permission to resend delivered input or a guarantee of total response time. Changes must retain valid saved limits and leave failures visible. Current controls offer 1–200 iterations and bounded timeout/output choices; their exact supported values belong in the UI/source rather than duplicated lists throughout the docs.
