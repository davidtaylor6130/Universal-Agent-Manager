# Goal Loops settings

Goal Loops settings bounds continuing goal work through a maximum iteration count and sets the global token budget for newly created goals. A budget of zero is unlimited. An explicit per-command goal budget can override this default. Existing goals retain their saved budgets. Provider setup inactivity timeout separately limits setup with no progress; turn output limit bounds one provider turn and excludes startup history. Provider turn timeout stops a turn after that long without provider activity, which is the [stream watch](../providers/runtime-lifecycle.md#stream-watch) stall threshold; it is adjusted in 15-minute steps and OpenCode also receives it as its provider request timeout (see [OpenCode turn timeout](../providers/opencode/opencode.md#turn-timeout)). A turn stopped by a timeout shows a transcript notice naming the limit and its value with **Restart with +15 min**, which saves the raised value and re-delivers the same user message in place when the turn produced no output, including after the timeout stopped the provider process: the resumed native conversation receives it again. The message stays a delivered message throughout and is never saved as unsent, so nothing replays it later without this request. No output is not proof that the provider did nothing: Restart re-sends a prompt the provider may already have acted on. While the stop is still settling Restart asks to wait, and it is refused while the stopped process has not been seen to exit. A refused restart puts the previous timeout value back. Repeated output limit (Off, 10, 20 or 50; default 20) stops a turn repeating the same tool call, text or reasoning and shows the same notice with an example of the repeated content and Restart, or Continue in new chat when the turn already produced output. These are different safeguards, not permission to resend delivered input or a guarantee of total response time. Changes must retain valid saved limits and leave failures visible. Current controls offer 1–200 iterations and bounded timeout/output choices; their exact supported values belong in the UI/source rather than duplicated lists throughout the docs.
