# Git

Git integration supports explicitly configured workspace isolation, branches, checkpoints and supported commit or port-to-source actions. Preserve user-owned branches, ignored files and unrelated changes; changing a conversation branch does not itself request a new worktree. Git enablement is separate from SVN tracking and local snapshot choices, and remote operations must execute against the intended remote workspace.

[Local snapshots](local-snapshots.md) · [Workspaces](../../workspaces/workspaces.md).

Every Git command UAM runs itself, locally or on an SSH host, turns off repository-configured hooks, file-system monitors, external diff programs and pagers, and its diff and show commands also skip external diff drivers and text conversion. Commits and worktree operations made by UAM therefore do not run the repository's Git hooks. Commands typed by a user or agent are not changed.

Automatic isolation prepares a separate worktree for an eligible new chat. Default base branch is a local existing ref (empty means HEAD). A positively verified local Git repository with no initial commit can use the enabled plain-folder snapshot policy to create an initial baseline in UAM-owned storage and isolate from that baseline; UAM does not commit into or change the original repository. Explicit base choices and snapshot opt-outs remain effective. A uniquely owned interrupted journal can resume preparation when its planned artifacts were never created; changed ownership, occupied targets and partial artifacts must be preserved and reported rather than treated as ready. A journal of the same chat whose creation failed protects nothing once its leftovers are settled: it is set aside and preparation starts again, so a first send that failed can be retried after its cause is fixed, including by changing a Git setting or the starting branch. Leftovers are settled without losing work. A worktree directory that Git never finished creating is removed only when every file in it is identical to the base commit; anything else is moved beside its planned path, never deleted, and the chat's status line says where. A branch still at its base that no worktree uses is deleted, and a half-checked-out worktree is never accepted as ready. A finished worktree, a branch with commits or a managed repository is never set aside; when it was prepared with different settings the refusal names each changed setting and the way out. A journal written by an earlier UAM session that was active within the last minute may belong to a `git worktree add` that is still running, so preparation waits a few seconds for it to finish, adopts it if it does and otherwise asks for a retry instead of creating a second worktree. Automatic isolation is never dropped without the user's knowledge: on an SSH host whose helper predates protocol 3 the first send is refused with a message naming the host and the helper update that clears it, and the chat keeps its isolation request.

Pull before first chat conditionally fast-forwards a clean upstream-tracked source. A verified local branch without an upstream continues locally without pulling. Tracked or staged changes and an in-progress Git operation skip this optional pull and allow isolation from a verified committed base, with a non-blocking warning; source changes and operation state remain in the source and are not copied into that committed-base worktree. Dirty source isolation also warns when pulling is disabled or there is no upstream. Failed or uncertain Git validation, invalid explicit bases and other unsafe configured-upstream pulls still report their unresolved step; UAM never configures an upstream or fetches/resets unconditionally. Port methods Merge and Squash stage changes for explicit later commit; Patch applies the exported patch without pretending an upstream publication. Failed preparation/porting preserves unrelated work.
