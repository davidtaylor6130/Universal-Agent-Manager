# Local snapshots

UAM can use local Git files to snapshot plain folders and SVN workspaces without making them upstream Git projects. The No VCS “Enable local Git files” switch and SVN “Local snapshot Git” switch are separate and default on. Turning either off affects future automatic local preparation for that workspace kind and does not delete existing worktrees or change remote Git operations. A positively verified local Git repository without an initial commit may use the enabled plain-folder snapshot policy for a UAM-owned baseline without modifying the original repository. An empty `.git` folder above a plain workspace, such as one left in a home folder, is ignored as Git ignores it; a non-empty but unreadable or broken one still blocks the snapshot. Only a uniquely owned journal with no created artifacts may resume preparation; damaged, occupied or ambiguous preparation must report its state rather than silently falling back.

Both snapshot preferences remain editable and save independently when Git or SVN integration is disabled. They use the Version Control page's explicit Save/Discard flow; a failed save retains the draft. Editing these preferences does not enable integration or override native worktree-preparation prerequisites.

SVN snapshots skip items that `svn:ignore` or global ignores exclude and keep them untracked in the managed copy; when those rules cannot be read, no snapshot is created rather than copying ignored content. SVN does not report ignored items inside new unversioned folders, so those are still copied. Snapshot preparation honors the source Git repository’s ignore rules, including its local and global Git exclusions, so ignored dependency and build caches do not block an unborn-repository baseline. Relative symbolic links that remain inside the source workspace are preserved as links in the isolated copy, including dangling internal links; preparation does not copy their target contents through the link. Absolute or escaping links still require an explicit resolution because preserving them would leave the isolated workspace pointing elsewhere. Source files and links remain unchanged. Windows link creation still requires OS permission; an unavailable link capability is reported rather than replaced with a regular text file.
