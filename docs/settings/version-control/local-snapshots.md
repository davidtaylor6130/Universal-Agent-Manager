# Local snapshots

UAM can use local Git files to snapshot plain folders and SVN workspaces without making them upstream Git projects. The No VCS “Enable local Git files” switch and SVN “Local snapshot Git” switch are separate and default on. Turning either off affects future automatic local preparation for that workspace kind and does not delete existing worktrees or change remote Git operations. A positively verified local Git repository without an initial commit may use the enabled plain-folder snapshot policy for a UAM-owned baseline without modifying the original repository. An empty `.git` folder above a plain workspace, such as one left in a home folder, is ignored as Git ignores it; a non-empty but unreadable or broken one still blocks the snapshot. Only a uniquely owned journal with no created artifacts may resume preparation; damaged, occupied or ambiguous preparation must report its state rather than silently falling back.

Both snapshot preferences remain editable and save independently when Git or SVN integration is disabled. They use the Version Control page's explicit Save/Discard flow; a failed save retains the draft. Editing these preferences does not enable integration or override native worktree-preparation prerequisites.

SVN snapshots skip items that `svn:ignore` or global ignores exclude and keep them untracked in the managed copy; when those rules cannot be read, no snapshot is created rather than copying ignored content. SVN does not report ignored items inside new unversioned folders, so those are still copied. Snapshot preparation honors the source Git repository’s ignore rules, including its local and global Git exclusions, so ignored dependency and build caches do not block an unborn-repository baseline. A plain folder that contains its own Git repositories likewise skips what each nested repository ignores, such as a `.venv` or `node_modules`; the copied ignore files keep those paths untracked in the managed copy. A nested folder that Git cannot read as a repository, such as a broken or foreign-owned one, is copied whole as before with a warning naming it. Relative symbolic links that remain inside the source workspace are preserved as links in the isolated copy, including dangling internal links; preparation does not copy their target contents through the link. Absolute or escaping links are never recreated, because they would leave the isolated workspace pointing elsewhere: preparation leaves them out of the copy and shows a status warning naming them when the chat starts, instead of failing the whole snapshot. A linked parent folder still stops preparation. Source files and links remain unchanged. Windows link creation still requires OS permission; an unavailable link capability is reported rather than replaced with a regular text file.

## Porting back and the commit panel

A snapshot is a hidden Git copy with no history shared with its source, so porting back always applies the chat's changes to the source as a patch: committed and uncommitted changes since the snapshot's baseline, checked to apply cleanly first. When the Git port method is Merge or Squash, every result, including a refusal, adds a one-line notice that local snapshots port back as a patch; nothing is staged in Git or recorded as a merge. A snapshot is recognised by its UAM-owned repository, the same rule that created it, so an unborn repository or a folder below an empty `.git` folder counts. For an SVN source the ported changes are ordinary working-copy edits, published only by an explicit [SVN commit](svn.md) afterwards.

For a chat in a snapshot, the [commit panel](../../changes/commits.md#history-and-update) shows the hidden copy as **Local snapshot (Git)** with a short note: its commits stay in the copy, and for an SVN source, publishing to SVN happens after porting back. With SVN enabled, an SVN source's **SVN history** and **Update SVN** run against the source working copy, not the copy; updating it does not refresh the snapshot, and porting back still refuses chat changes that conflict with the updated source. A plain-folder or unborn-repository snapshot shows the label and note only, and the note mentions SVN history and Update only while they are offered. The goal reviewer of a snapshot chat works in the copy and therefore uses Git reads ([goals](../../chat/goals.md)).
