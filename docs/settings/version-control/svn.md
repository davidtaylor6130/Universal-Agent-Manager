# SVN

SVN integration is distinct from UAM’s local Git snapshots. “Update before new chat” defaults off and requests an update for an eligible new working-copy chat, not a commit or an update of every resumed conversation. Updates must surface conflicts or uncertain outcomes before provider work proceeds. Explicit SVN publication must respect the selected paths and preserve unselected descendants, locally and on SSH hosts alike. Selecting a new folder publishes its contents that SVN does not ignore; after a failed commit those scheduled contents appear as their own rows and must be selected with the folder; paths inside externals are refused rather than published to another repository. An interrupted update may be retried once fresh status shows no conflicts or working-copy locks; a locked checkout still needs `svn cleanup`.

Composer selection uses an explicit repository-relative parent to discover existing child directories; no repository layout is assumed and no branch is created. Eligible local full working copies can switch only after explicit target confirmation, clean-state and exclusive-workspace checks, unchanged URL/UUID/revisions and the normal runtime-stop barrier. Retained source and active worktree references both count as other workspace users. Recursive working-copy inventory refuses sparse or excluded descendants without expanding them; it must verify within 128 KiB and 4,096 entries. Discovery is bounded to 256 entries and 128 KiB per reply; a switch pins the discovered repository revision and retains SVN’s ancestry validation. Unsupported/uncertain results retain the working copy for inspection. The [composer agreement](../../chat/composer/workspace-actions.md) owns the interaction and limits; mapping is per selection, not a new global SVN default.

SVN working-copy changes in Chat changes and the commit panel count added and removed lines for versioned files and open each file's diff. Names containing `@` are compared literally on current and older SVN clients. An unversioned file is shown as entirely added, with every line counted; a binary one is marked binary, and one larger than 4 MB is listed without a line count or diff. An unversioned folder stays one row without a line count or file diff until it is added. On a remote host, unversioned-file counts and diffs use the host's Git, so an SVN-only host shows them without counts.

The commit panel shows an SVN working copy's history and can update it ([commit panel](../../changes/commits.md#history-and-update)). History lists the revisions that changed the workspace's repository path, newest first, with author, date, message and changed paths; it follows the path back through the copy that created a branch, and includes revisions newer than the working copy, marked as not updated yet. Each changed file opens the patch that revision applied, including a file the revision deleted. Trunk, branch and tag names come from the repository's layout for display only, and nothing is inferred for an action. The layout is `trunk`/`branches`/`tags` unless **SVN repository layouts** in Settings names other folders for that repository, matched by its root URL or UUID; folders are repository-relative, may be more than one folder deep (`lines/dev`) and may sit under a project folder. A path the layout does not recognise is shown as the path itself, and its tooltip gives the repository root to enter. An incomplete, duplicate or out-of-repository entry cannot be saved. Update runs `svn update` for the workspace with conflicts postponed: it never commits, reverts or resolves, reports the revision reached and says when conflicts were left. Both need **SVN** enabled and work on local and SSH workspaces, using the host's own `svn`. A chat in a [local snapshot](local-snapshots.md#porting-back-and-the-commit-panel) has them as **SVN history** and **Update SVN**, run against the working copy the snapshot came from. For a working copy that was copied from another path (a branch or tag), History names the copy point and can draw the branch beside its origin as a [graph](../../changes/commits.md#history-and-update). A renamed branch keeps its origin: the copy point is the copy that started the line, found back through any renames. The origin's rail lists the origin revisions SVN's merge tracking would still merge into the branch. Those rows say they are only on the origin when a merge from the origin is recorded on the branch; when none is recorded, or merge tracking cannot be read and the origin's log since the copy is used instead, they are shown as the origin's revisions with no claim about whether the branch has them. The graph reads committed state at the newest revision of both paths, not uncommitted work. **Implementation note:** ahead and behind counts, a diff against the origin, merging from the origin, drawing merges in the graph, blame, revert, properties, locks, changelists and a branch or tag switcher in the panel are not built; branch-equivalent selection stays in the composer.

Every svn command UAM runs on this machine uses a UTF-8 locale, so a working copy whose path has non-ASCII characters works however UAM was launched (a Finder launch sets no locale). svn+ssh runs ssh in batch mode (`SVN_SSH="ssh -o BatchMode=yes"`) unless the user has set `SVN_SSH` or chosen their own `[tunnels]` ssh command in their Subversion config, so a missing key or unknown host key fails instead of waiting on a prompt nobody can answer. SVN failures in the commit panel, Chat changes, History, Update and composer folder selection read as one plain line. When svn could not get credentials or the server refused them, the line asks the user to run `svn info <url>` once in a terminal to save them, then retry; the same advice appears when updating before a new chat fails for that reason. An account that is signed in but has no access to the path gets svn's own "Authorization failed" line instead. A commit refused because a file is out of date names the file and says to update, then commit again; a commit a hook refused shows the hook's first line of explanation. Otherwise the line is svn's most specific error; in the commit panel and Chat changes, paths inside the workspace are shown relative to it. Only svn's own error lines reach the [diagnostic log](../../engineering/logging.md), never command output, with home paths and URL user names removed and a repeated failure logged once every five minutes. **Implementation note:** on SSH hosts the host's own `SVN_SSH` and environment apply apart from the locale, and repository route matching reads SSH hosts without the locale.
