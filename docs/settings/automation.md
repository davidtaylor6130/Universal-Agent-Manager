# Automation settings

Automation shows the [automation API](../automation-api.md) address and its tokens. The address appears once Phone access has one; otherwise the row says to turn Phone access on. New token asks for a name, whether chats start straight away, the most Git access a request may ask for, when it expires (30 days, 90 days or one year; 90 by default) and at least one workspace, and lists no workspace beyond those currently in UAM. The token appears once in that dialog with Copy token, and closing it discards the value. Each token's row lists the workspace IDs requests use and its expiry date, or that it has expired. Regenerate asks for confirmation, then shows the replacement token once in the same dialog; the old one stops working immediately. Revoke asks for confirmation and applies immediately. The page exists only in builds with phone support and is available only on the desktop.

Schedules lists each [automation schedule](../automation-api.md#schedules) with how often it runs, its workspace and whether its chats start straight away or wait for approval, then its next run and its last run with the result, a failure reason or how many missed runs it skipped. A switch on each row pauses or resumes the schedule; Edit opens the same dialog as New schedule, and Delete asks for confirmation and keeps the chats it already started. The dialog asks for a name, the prompt, the workspace, the provider (providers that answer their own permission prompts are not offered), an optional model, how often it repeats (an interval from 15 minutes to 7 days, or chosen days and a time), what to do with runs missed while UAM was closed (skip them or run once), whether chats start straight away, the Git access and the most goal loop iterations per chat. A save that UAM refuses keeps the dialog open with its values and reports the reason as a notification. The list re-reads the last and next runs every 30 seconds while the page is open.
