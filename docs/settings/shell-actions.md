# Shell Actions

Shell Actions defines reusable user-configured actions and their ordered groups for workspace or shell integration. Editing, grouping and collapsing must retain drafts; Save applies valid changes and Discard restores saved configuration. Running an action uses its intended workspace, host and selected chat options rather than guessing from the visible folder. Installing an OS integration is distinct from saving an action and must report its actual result.

[Workspace actions](../chat/composer/workspace-actions.md) · [UI settings](../ui/settings.md) · [Source map](../reference/source-map.md).

Each action chooses its name/group, enabled state, provider/model, accepted file/folder inputs and whether to open a workspace or launch selected skill work. Group changes do not rewrite those execution choices. OS registration/installation must use the saved definition and show actual availability/failure; it is distinct from merely editing the action list.

Explorer shows groups as nested submenus, so a label need only be unique within its group. Finder lists Quick Actions in one flat menu, so each installed Finder name carries its group path (`Version Control › GitHub › Review`), and Save refuses enabled actions whose Finder names would still match, ignoring ASCII letter case. Action and group names cannot contain line breaks or other control characters.

A saved action that fails validation when loaded (other than an excluded provider's, which stays hidden as [build flags](../build-flags.md) describe), whether from a wrong-typed field, a missing input type, an unsupported provider or model, or an id another saved action already uses, is never dropped. It stays in its place, disabled and read-only, with a one-line reason on its row, and startup shows a one-line notice naming how many there are. Saving the list writes each one back as it was saved, but disabled, so a later fix never installs it unasked; only deleting it removes it. A saved file that cannot be read or parsed is copied aside beside it before the next save replaces it. While it cannot be read, Apply is refused so installed Finder and Explorer items are not removed.

Choosing an installed action from the Explorer or Finder menu opens a new chat in the selected folder, or the selected file's folder, with the action's provider, model and skill prompt, whether or not UAM is already running. A running UAM handles the click itself and comes to the front. Only the selected paths count as the action's input: options UAM adds to its own launch, such as the crash supervisor's, never reach the action. A file name is untrusted text that reaches an unattended skill run, so UAM refuses a selection whose path contains a line break or other control character (including Unicode line separators) before it creates a workspace or chat, and the skill prompt gives each path as a quoted, escaped JSON string marked as data, never as instructions. Choosing a kept invalid action reports why it is disabled.
