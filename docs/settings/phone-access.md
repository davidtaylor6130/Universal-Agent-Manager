# Phone Access settings

Phone Access turns publication of the controller’s shared companion interface on or off and configures its connection and authentication options. Show the actual serving/connection state independently of the saved enablement setting; turning it off must stop access rather than just hiding the address. The browser requires no phone application install, while the native iPhone client installs separately and uses the same connection. Build-excluded phone support leaves no phone settings or published interface.

[Phone access](../phone-access.md) · [Build flags](../build-flags.md).

Copy URL and Copy token expose distinct connection values; neither implies the browser is connected. A changed network address must report the current published route and preserve authentication rather than silently claiming the old URL still works.

Phone access changes apply to the running connection without restarting provider work. Enabling, disabling, retrying and repairing an address return the same observed status: saved intent, starting/ready/failed state and the effective route remain distinct. Pairing and Copy URL become available only after both the local interface and secure listener are ready. Failures keep Retry phone access, current-address repair choices and Restart Universal Agent Manager beside their explanation; successful status refreshes clear recovered load errors without erasing a failed user action; restart-required changes also expose that inline application action. Network repair replaces the local interface and proxy together before advertising the new route.

Pair iPhone deliberately reveals a locally generated QR containing the ready HTTPS address, existing companion credential and, for the managed private-certificate proxy, its public root certificate. It requests the credential only after Show pairing code is pressed, clears it when publication/address changes or the page is hidden, and hides it after two minutes. Hiding the display does not revoke the persistent credential. The phone uses a scanned public root only for that saved HTTPS origin, retaining chain, hostname and validity checks; manual entry requires an already trusted certificate or a root previously paired for the same origin. The phone must still have network reachability. The companion cannot retrieve its own credential through this desktop-only action.
