# Native iPhone companion

The native iOS client uses the same authenticated companion connection as the phone browser. The main UAM computer owns providers, chat history, durable memory, shared setup and downstream SSH execution; the phone owns its navigation, saved connection credentials, appearance and unsent drafts. Switching or leaving a phone chat does not select another chat on the desktop. The native client targets iOS 26 and later, with an adaptive iPad layout, and remains separate from the desktop React/CEF interface.

## Home and conversations

Home places the UAM identity at the top left, settings and search at the top right, a compact computer selector and project filter underneath, and Active/Chats navigation plus New chat at the bottom. Active follows the desktop’s [family activity rules](sidebar/active/active.md): running work and requests for input take priority, while settlement, interaction recency and the root’s snooze determine whether quiet or completed work remains listed. A pinned or unread chat does not bypass those rules; unread markers remain independent of settlement. Active includes a separate collapsible Snoozed Chats section instead of a settled-history list. Chats follows the desktop organisation: Pinned Chats is a flat list without branch dropdowns, and only All Chats nests collections, their referenced workspaces, ungrouped workspaces and Unsorted chats. Pinned and snoozed conversations remain in All Chats. Collection and workspace order comes from the main computer; phone disclosures do not change its saved layout. Empty groups remain visible outside search, and long workspaces initially show five chats with Show more. Search and project selection narrow the current main-computer catalogue while preserving a matching child’s real family root, its collection/workspace ancestors and activity destination. Browse root rows open that root; matching child links remain directly available within All Chats search results, while Active opens the family member requiring attention. Blank search whitespace is ignored. Snooze expiry advances on the phone’s local clock even when the computer cannot refresh. A new chat chooses a real configured project and provider/model rather than inventing a workspace on the phone.

Saved branch alternatives use previous/next controls and a position counter beside the user message where they diverged, following desktop ordering and absolute history indexes; there is no global Related chats chooser. Switching alternatives loads contiguous bounded history pages back to that message, shows cancellable progress and keeps unrelated transcript controls usable. Subagent cards still open their own histories, with Return to parent chat available for non-message children when the parent remains in the catalogue. The compact computer selector retains full saved names and current selection in its menu and accessibility value, with labelled computer/project icons at accessibility text sizes.

Conversations use a centred reading column capped at 720 points on wide screens, selectable Markdown and code, subdued tool activity, original message order, expandable output and compact child navigation. Tool rows show a nonempty command/title summary, using an activity fallback when an older deferred record has no title; empty subagent metadata cannot hide ordinary commands, bounded previews do not modify original detail content, and deferred summaries do not fetch output per row. Opening full tool details derives its title from explicitly labelled arguments already loaded with that output. Code and tables expose horizontal overflow with native indicators, a measured cue and accessible scroll-position feedback; fitting content adds no cue. Earlier messages load in bounded pages; reconnects must not create silent gaps or overwrite newer transcript revisions. Work status, stop controls and pending permissions/questions remain tied to the real provider state. The main computer continues working while iOS suspends the phone app; foregrounding refreshes state rather than replaying input. Opening and closing chats must remain responsive with a large saved catalogue; date normalization and family ordering must not be repeated inside sort comparisons. A failed catalogue read retains the last accepted snapshot and shows connection-specific recovery beside touch-sized Retry and, for credential, trust or address failures, Pair again; a later successful read clears that connection problem without erasing unrelated draft or send errors. An unloaded catalogue shows connecting or unavailable instead of claiming that all chats are quiet. Optional capability discovery cannot invalidate an accepted snapshot.

## Composer and drafts

The phone composer expands when editing and sits above the native keyboard. It supports multiline text, model/agent controls, files, photo-library selections and camera capture when the device permits it. Native dictation requires microphone/speech permission and on-device recognition; it stops on navigation, backgrounding or interruption, preserves typed text and never sends automatically. The keyboard remains available when on-device recognition is unavailable. HEIC/HEIF imports retain the byte-exact original as a file and add a bounded, upright JPEG for provider compatibility; both are visible before sending and count toward the eight-file/20 MB limit. Photo-library data and file bytes are staged through the main computer before sending, retaining the existing attachment/history authority. File limits are shown through recoverable errors, and failed staging or uncertain send results retain the draft. Successful acknowledgements settle only the exact submitted draft revision in its original connection/chat, preserving edits made while sending. New-chat drafts are also persisted per connection and project. Protected per-context attachment blobs are written once, while text edits update a small atomic manifest; unreadable drafts are retained and blocked from sending or being overwritten until a successful reload or explicitly confirmed local discard. Retry and discard controls belong to the original connection and draft; discarding an unreadable draft never deletes computer history or another chat’s draft. An attachment import completing after navigation must never attach to another conversation.

## Connections and settings

Users can scan the desktop Phone Access QR or enter its published HTTPS address and access token manually. The QR carries the existing shared companion credential and is not a new account or a short-lived per-device credential. The desktop reveals it only on request; hiding the QR does not revoke access. Re-pairing the same HTTPS origin updates its saved credential while retaining local draft identity; a different main-computer origin gets a separate identity. Native credentials belong in Keychain, with drafts in protected app storage. A valid scan or manual confirmation immediately opens a dedicated connection-checking step, followed by a persistent connected or failed result. Root navigation has one sheet owner: incoming pairing links wait for an existing settings or project sheet to finish dismissing, while an already open pairing page handles them within its current attempt. Close remains visible; failed checks offer Edit details with the original input retained, and cancellation cannot save a late result. Dismissal retains the current result during its animation, and returning to edit never submits a pairing link received during another attempt. Pairing validates and activates one initial-state snapshot before saving, rather than reporting success ahead of a second connection attempt. Errors describe the failed setup check without suggesting that pairing sent a chat action. Certificate and hostname verification remain enabled. A QR may include the managed proxy’s public root certificate, which is saved for that HTTPS origin only and must pass certificate-chain, hostname and validity checks. Editing the origin discards scanned trust; manual entry otherwise requires system trust or a previously paired root for that same origin. Saved environments are main UAM instances, and their downstream execution hosts remain under the selected main computer. Saved environments use explicit QR/manual pairing. Automatic LAN discovery, embedded Tailscale, cloud relay and push delivery are separate future capabilities.

Native settings group environments, usage/limits, phone appearance/input and main-computer configuration. Explicit Save/Discard editors cover scoped provider defaults, exact-case model identifiers, memory defaults/workers, retention and agent favorites; configured provider/MCP switches use the same main-computer handlers. Forms retain their original connection identity, and older hosts expose a clear capability gate. Per-chat provider/model options, UAM agents/tools, memory and permissions act through the existing controller. Credential, installation and shared-definition operations remain desktop-managed. Queued prompts can be inspected, explicitly steered or removed with revision guards; held queues retain the main computer's resume requirement.

Copilot Auto routing presents the controller's advertised choices, descriptions and disabled reasons as readable settings text, preserving exact identifiers and an explicit provider Default; a non-Auto model explains why choosing a preference is disabled. Effective, pending and activating preferences remain distinct from request acceptance. The preference menu exposes a full-width label with a minimum 44-point touch target. Choosing or refreshing requires an advertised companion action and the current writable, idle native chat/session/host/lifetime; a changed phone context or owner retires the control without replay. **Implementation: Implemented**, with simulator-hosted application verification; live-provider, visual and physical-iPhone acceptance are pending. Model/reasoning edits use the existing companion handlers and retain exact-case identifiers, the original phone context and the selected provider/host/workspace catalogue; a saved reasoning value alone does not advertise a supported choice. An open model picker retains its original chat snapshot; host, workspace, project or root-incarnation changes retire its selection and model/reasoning submissions rather than applying them to a replacement context. Catalogue lookup accepts the controller’s equivalent Windows separators and trailing slashes while preserving POSIX case, exact provider/host scope and opaque model identifiers; this spelling comparison does not relax action identity checks or resolve a main computer’s home directory on the phone. These local checks add no companion payload fields.

## Managed subagents

The conversation’s Subagents action opens a bounded parent-scoped catalogue with individually scoped Stop and stored-conversation navigation. Each catalogue row opens from its full touch area; Stop and paging buttons have independent actions and minimum 44-point touch targets, as do the reader’s follow-up controls. Return to parent chat dismisses the reader without changing the desktop selection or parent composer; All subagents returns to the catalogue. The reader shows the selected child’s name in its content so narrow toolbar layouts cannot hide that identity. Stored messages use the shared phone renderer with available reasoning, plans and tool output, while stored attachment names remain readable without borrowing the parent’s attachment or runtime authority. A child’s reading position and independent text draft remain separate from the parent and other children. Foreground read recovery retains accepted content; failed or historical reads are labelled last reported and cannot authorize controls.

Follow-up appears only for the exact run/transcript and current listing capability returned by the controller, with its current turn and control scope. The existing runtime restrictions remain decisive; read-only roots and historical children cannot gain input or Stop permission from navigation. App-lifetime draft storage retains text, validation feedback and pending or uncertain requests across hiding input, parent return and visits to other children, and refuses new drafts when protected capacity is full. Confirmed empty drafts can be recycled while authored text, validation feedback and unresolved requests remain protected. Explicit Retry same request retains its original text, client request ID and originating turn, while newer draft edits remain independent. Reads and navigation never replay mutations, and only a matching acceptance receipt settles the submitted draft revision. Stop acknowledgement means a request was accepted; the child’s separately reported state determines termination. A fresh validated read retires an acknowledged Stop, and each later explicit Stop still requires the current returned capability; pending and uncertain state remains retained. Inactive readers with unconfirmed Stop requests remain protected when the bounded reader cache is full; opening another root refuses with bounded names from the current computer’s available parent catalogue and guidance to return to an existing reader rather than silently discarding those requests. **Implementation: Implemented**, with simulator-hosted application and focused shared verification; live-provider, visual, physical-iPhone, Claude and user acceptance remain pending.

**Implementation: Partial.** Earlier native work is integrated into V5; branch follow-ups and acceptance are pending. Native source, shared protocol extensions and simulator journeys are present; builds, the failing full native gate, required review and real iPhone acceptance are tracked separately in the [V5 log](<../V5 Improvement Change log.md>). No App Store/TestFlight delivery, physical camera acceptance or embedded Tailscale support is claimed.
