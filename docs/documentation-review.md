## Helper build identity source

Open, pending David: [#627](https://github.com/davidtaylor6130/Universal-Agent-Manager/issues/627) asks Updates to compare the packaged helper's checksum with the installed helper's published remote metadata. The current implementation compares it with a local install receipt: the SHA-256 this computer verified and published at installation, saved on the host as `runnerSha256`. That receipt cannot see a different build installed on the same host by another computer, or files changed on the host afterwards. Should UAM instead read the remote `uam-runner.sha256` (or a helper-reported checksum) at the handshake or status probe, at the cost of an extra remote read and a protocol or probe change? Until decided, keep the local receipt, treat a missing receipt as unknown and offer a reinstall, and do not describe it as remote verification. See the [Updates agreement](updates/updates.md) and the [execution-host reference](reference/architecture/execution-hosts.md#transactional-installed-metadata).

## Managed restart history

Startup leaves recognizable managed-continuation records inert and excludes them from runtime admission, so queued or running records retained on disk do not themselves consume restarted execution capacity. A bounded read-only catalogue now retains witnessed initial-run relationships for sidebar discovery and stored conversation inspection after canonical source revalidation. These records retain last-reported status without restoring an execution owner, replaying input or inferring that an external provider stopped; unfinished saved runs expose no live animation, timer or Stop. Focused startup and public UI verification covers this initial-run slice, and the initial CEF producer is enabled with connected native verification; full native gates and the interrupted native review remain pending. Same-child continuation and broader saved-run shapes remain separate gaps; the existing no-replay and native-identity agreements remain unchanged.

Changed 2026-11-10 (subagent stability, awaiting David's acceptance): the ledger loader still leaves these records unchanged and outside runtime admission, but the application's startup step now closes them. A record left queued or running is marked interrupted with `manager_restarted`, and a recent terminal record that never wrote its result card delivers it once; see [results across restart](chat/subagents.md#results-across-restart). This replaces "retain last-reported status" for unfinished records only: a real install had accumulated 36 records that stayed "running" on disk indefinitely. The no-relaunch, no-replay and no-inference rules above are unchanged; "interrupted" states that UAM lost ownership, not that the provider process ended. Startup also attempts to stop what such a run launched, only where saved state proves ownership: a child conversation on a configured remote host with a saved helper process control token is attached solely to be stopped through the ordinary remote Stop path, in the background, for at most two minutes. Local processes are never killed at startup, and `@agent` (version-2) runs are not stopped because they have no runtime owner after a restart; both remain known gaps on macOS, Linux and SSH hosts respectively. The remote stop is source-integrated with a selection test only; it has not been exercised against a real SSH host. Open for David: whether a crash-interrupted run should add an "interrupted" card to its parent (it does when the run was active within seven days), and the seven-day, 90-day and 5,000-record limits. Mac-only restart tests that assert the unchanged loader behaviour were not rerun for this change.
