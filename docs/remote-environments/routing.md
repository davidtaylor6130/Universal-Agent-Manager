# Execution routing

Routing chooses where work executes while retaining its provider, workspace and authored request. Automatic rules must respect availability and configured confirmation, and explicit choices must remain understandable rather than silently moving work after a failure. Changes to host identity or material configuration require revalidation. A disconnected or busy environment must not cause duplicate provider work or an unauthorized local fallback.

[Remote settings](../settings/remote-hosts.md) · [Execution reference](../reference/architecture/execution-hosts.md).

Automatic routing requires enabled candidate computers, capacity, current provider sign-in/configuration confirmation and valid local-to-remote folder/repository mappings. An explicit user destination is separate from the automatic candidate policy; changed connections/configurations invalidate old confirmations. No available route must remain an honest blocked/choice state rather than an unauthorized fallback.

The SSH routing page (and the New chat routing dialog) lists each computer as one collapsible row with its status box and Use this computer switch; expanding it shows concurrent sessions and provider sign-in confirmations. Folders are grouped by local workspace, with one row per computer the workspace is mapped to: the remote path, a Same repository (automatic repository match) or Chosen (manual override, which wins) tag, and any problem with that mapping inline (folder no longer exists, folder on another computer, workspace folder moved). These row problems use the same checks as the page validation that blocks Save. Workspaces with a problem come first and start open; workspaces without a mapping share one Not mapped group. Map folder… opens a chooser built like Import chats: pick a computer, filter, tick workspaces and choose a registered remote folder for each, then Map N. A row's Map… or Choose… opens it with that workspace and computer preselected. Mapping only stages changes in the unsaved routing draft, so Save routing, Discard, validation and the unsaved-changes guard are unchanged. In the New chat routing dialog the chooser is an in-place step of the same panel, and Escape returns to the routing list. The chooser lists only folders already registered on that computer.
