# Tools and message content

Conversation content distinguishes authored text, assistant Markdown/code, reasoning, plans, tool calls/results, images and related subagent activity. Expand/collapse controls change disclosure without hiding pending questions or permissions; tool details keep their request identity, execution state and supported file/terminal/result representation. Copying code, messages or patches preserves the corresponding content, while external links and file/path chips retain their own destination and inspection rules. Historical tool output is evidence of an operation, not a new command to execute. Message navigation, loading earlier history and scrolling to latest must retain the correct raw message position and disclose incomplete history.

An initial history read refused because saved history changed, or invalidated only by an idle-timer or diagnostics update, may discard that response and make one fresh read while the same chat still owns an unloaded history. Both triggers share one additional-read budget. The replacement must pass the normal history and recovery checks; a further conflict remains visible and retryable. Reading history never resubmits authored input. A loading indicator represents only current owned history work, including its selection prerequisite, not merely absent saved history. A silent selection prerequisite or initial read ends in a visible retryable failure after 30 seconds; late or superseded replies cannot settle a newer read. Retained outgoing or unsent input remains visible without a replacement loading skeleton, while a confirmed empty history shows the empty chat state; unavailable history is not presented as successfully empty.

The message-navigation rail has its own padded gutter whenever it is present, including narrow split panes; expanded marks, previews and focus rings must not collide with message content or controls. Preview width follows its pane, and focus exposes the same loaded snippet or unloaded-history explanation as hover. A focused target stays selected when the pointer leaves, until focus, navigation or pointer hover changes it; the preview remains centred on its mark after the entrance animation. Every user message currently on screen lights its mark, so several can be lit at once, and the selected mark is the first visible user message, or the final one once the end of the transcript, not merely of an older loaded page, is on screen. Rows behind the floating composer are not on screen. A mark the reader chooses stays selected until they scroll or its message has been shown and left the screen. Visibility comes from observing message rows rather than measuring them on each scroll. Hovering the rail reveals previous/next buttons above and below the marks, which step one user message from the selected mark and keep keyboard focus while a jump loads; a fixed hairline to the right of the resting marks never moves. Choosing a mark scrolls smoothly to it unless Motion is Off or reduced motion is requested.
