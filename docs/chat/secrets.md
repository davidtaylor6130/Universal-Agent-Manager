# Secure secret entry

An agent that needs a secret (API key, token, password, PIN, sudo password or pairing code) asks for it with the UAM tool `secret_request {label, reason, placeholder?, url?, delivery?}` instead of asking in chat text. The user types it into a masked card; the value never reaches the model, the chat history or transcript, UAM's diagnostic log, memory extraction, chat titles or summaries, exported bundles or the phone. The agent receives only a path to a read-once handoff on the computer where it runs, and reads it inside the one command that uses it, such as `cmd --token "$(cat PATH)"` or `sudo -S -p '' cmd < PATH`. Delivery is file-only in this version; an opaque reference and a UAM-run `secret_exec` wait for a consumer that needs them. [Tool connection](../providers/uam-tools.md) · [Questions](questions.md).

## The card

The request shows as its own card above the composer, like other UAM questions, and waits without a countdown until the user submits or cancels, or until its turn stops or its caller stops waiting. It shows the agent's label and reason as plain text attributed to the provider, the computer that will receive the secret (This Mac or the SSH host), and an optional **Get a key** button that opens the agent's https link in the system browser with its host visible first. The field is masked, single-line and can be revealed; Enter submits and Escape never cancels. A value under 6 characters is accepted with a warning that it cannot be hidden if the agent prints it. A failed delivery keeps the typed value in the card for Retry; Cancel discards it and tells the agent the user cancelled. Once answered, only the tool call remains in the transcript, summarised as the label and outcome, never the value or the path. In CLI View the same card shows above the terminal; UAM never types into the terminal. A provider that runs without the UAM tool connection has no card and falls back to its own prompt, which UAM does not mediate. Requests from subagents appear in the root chat the user is working in, and the secret goes to the subagent's own computer. The phone shows "Answer it on the computer": it can decline the request or give the Plan-mode Allow once, but never enter or receive the value.

## Who can ask

Read-only agents, goal-review turns, side chats and automation-API chats are refused with no card. A chat in Plan mode shows a blocked card that needs **Allow once** before the field appears; the chat stays in Plan. YOLO never answers a secret card. Subagents inherit their parent's read-only ceiling. The tool carries no read-only hint, so a provider in Plan mode may ask before calling it.

## Delivery and storage

On macOS and Linux, including SSH hosts, the path is a named pipe in a private owner-only folder (0700, pipe 0600): it serves the value once to the first reader and is removed, or removed unread after 10 minutes, and the value is never written to disk. Windows cannot detect a read, so there it is a file only the user's account can read, deleted after 60 seconds (David accepted this on 2026-11-12). Over SSH the value travels through the SSH connection to the UAM helper's `secret.drop` request and is never placed in a command line or environment; an older helper is refused with a request to update it. Values stay in memory only. **Save in Keychain** (off by default, macOS only, and only when the agent runs on this Mac) keeps the value in the macOS Keychain under the workspace and label; a later request with the same label offers **Use saved secret** and **Forget saved**. UAM writes the item itself, so another program, including an agent's shell, gets the system prompt before it can read it. UAM keeps only the saved names, never values, in `<data-root>/secrets/`. Windows does not offer saving and refuses a save request: Windows Credential Manager lets any program running as the user read a saved value, so every Windows secret is one-time (David decided this on 2026-11-12).

## If the agent echoes it anyway

Every submitted value of 6 or more characters is registered for the rest of the app session, with its JSON-escaped and percent-encoded forms and its base64 forms where at least 8 characters are fixed. Exact matches are replaced with `[redacted secret]` in every string of provider output as UAM parses it (numbers and JSON structure stay intact), in the newest transcript entries after every provider line (catching a value split across streamed text), in streamed tokens, in CLI View terminal output before its replay buffer, the window or the phone sees it, in every state push to the window and in the diagnostic log. The provider's own native history files and its model context are outside UAM: a command that prints the secret can still reach the model in that turn, which is why the tool tells agents to read the path only inside the command that uses it. Registered values are forgotten when UAM quits, so an echo imported later from a provider's native history is not scrubbed; David accepted this limit on 2026-11-12.
