# Workspace actions

Workspace actions operate on the current chat’s workspace, including opening a configured editor or file manager and running configured shell actions. They must use the intended workspace and environment, and unavailable remote actions must be clear. Their available choices are configured under [Editors](../../settings/editors.md) and [Shell Actions](../../settings/shell-actions.md); this menu does not define separate editor or command settings.

The composer identifies the source workspace first, then its VCS branch or supported equivalent, consistently with the sidebar. A managed worktree uses the source workspace’s name on the same execution host; its actual working directory remains inspectable and is still the target of workspace actions. Branch selection must reflect the current workspace’s supported operations rather than a global bridge capability or saved branch label alone.

A pending switch can outlast the open picker. Its refusal or inspection error remains available beside the branch control after the picker closes, including when runtime activity disables the trigger; the error is announced and can be read by keyboard focus or hover without implying a confirmed revision change.

Keyboard selection of an SVN target moves focus to its explicit confirmation, without switching. Cancel or Escape returns to folder search, changing the search clears a pending confirmation, and moving keyboard focus out of the picker closes it. Errors wrap in full rather than relying on a hover title. A successful confirmation returns to the branch control when focus remains in the picker; focus moved elsewhere during the request is preserved. Folder options use the search field’s arrow navigation rather than adding a Tab stop for every child.

If a pending switch refuses after the picker closes, focus deliberately moved to another control stays there while the inspection warning remains available. A failed background dispatch releases the chat’s busy marker and existing request lease so a later attempt is possible, without sending a second failure response.

The Git picker supports validated editable local UAM-owned Git worktrees; a managed Git snapshot of an SVN source does not switch that source and directs SVN selection to the actual working copy; native ownership, runtime and save checks remain authoritative. Creating a Git branch in a chat with no user message is never blocked in the picker: the name is validated, saved on the chat as pending and shown in the composer, and Git creates it from the same HEAD when the chat starts: the first message, a goal, or the CLI View terminal starting. A chat that is never used therefore leaves no branch behind. Creating a branch keeps uncommitted files as they are, so attachments or edits never block it; switching to an existing branch still needs a clean worktree. Choosing the checked-out branch withdraws the pending name without running Git, and an empty chat can always switch to an existing branch. If creation fails when the chat starts, the request is not sent and the error names the branch. A plain local SVN working copy instead offers repository-folder selection: enter an explicit repository-relative parent (for example `^/product/lines` or `^/`), discover its immediate child directories and confirm the chosen target before switching. The composer shows the current repository-relative path when verified, alongside its revision. A working copy at the repository root shows `^/`. This mapping is explicit input for the selection and is not an inferred `trunk`/`branches` convention or a repository creation action.

SVN selection requires the complete working-copy root to match its local workspace folder and have no other chat using that directory or an overlapping path, including retained source directories and separate worktrees. Workspace-directory remapping waits for an ongoing switch so another chat cannot begin sharing the working copy mid-switch. Dirty, ignored/untracked, conflicted, external, switched-child or changed working copies refuse switching. Full-copy verification includes sparse or excluded descendants; an incomplete or unverifiable bounded inventory refuses without expanding the copy. Stale discovery, repository identity changes and unsupported paths fail without an implicit checkout.

The native route stops an eligible idle runtime, takes the existing exclusive workspace lease, pins the discovered revision, preserves SVN’s ancestry check and verifies the final URL, revision, full inventory and clean state. Failed or uncertain operations report that the working copy needs inspection; they never force changes or attempt an automatic rollback. Remote, read-only, managed-run/goal and side-chat contexts retain their existing mutation limits. The separate [New chat](../new-chat.md) page owns the branch-creation selector; selected-worktree reuse already exists. See [SVN](../../settings/version-control/svn.md).
