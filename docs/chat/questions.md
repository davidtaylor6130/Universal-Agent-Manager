# Questions and permissions

Provider questions present the requested choices or supported free-text answers against the correct pending request; permission prompts separately ask whether an action may proceed under the selected safety policy. Do not treat an unanswered question, a closed dialog or expired request as consent. Submitted answers retain their request/chat identity, and a late response must not answer a replacement request or restart unrelated work. Native terminal prompts remain inside the CLI rather than acquiring structured-dialog guarantees. Stopping a structured turn settles its pending provider question and declines any pending UAM question, Computer Use, goal or chat creation request from that session's [UAM tool connection](../providers/uam-tools.md), so the abandoned request is no longer answerable.

A question the running turn is blocked on (the provider's own pending user input) replaces the composer body: a Question tab joins the right of the composer tab row, left of any Editing or side-chat tab, and the question, its option rows and any free-text answer use the composer's own frame, while the composer send button submits and Cancel turn stays beside it. Any other pending question, such as an asynchronous UAM control question, floats as its own card above a composer that stays usable, with its own Submit, and collapses to a compact pill. Both forms number the options 1–9 for direct choice, move between rows with ↑ and ↓, and advance or submit with Enter; several questions step with Back and Next. If the question moves between the two forms while it is pending (for example a permission request arrives, or a queued prompt is edited), its chosen answers, current step and any submission in flight carry over. Answering restores the normal composer, and a draft typed before the question remains.
