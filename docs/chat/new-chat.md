# New chat

New chat chooses a workspace, provider and supported execution environment, using the applicable defaults while preserving explicit choices. Workspace selection and model discovery must not launch a conversation turn; the first authored send begins provider work through the normal guarded path. A chosen existing worktree remains distinct from requesting new isolation, and unavailable providers/hosts produce a clear choice or error rather than an unnoticed fallback. Cancelling creation leaves existing chats and workspaces untouched.

## Starting branch

For an explicitly selected local workspace with Git and automatic worktrees enabled, the desktop dialog offers the configured default, the current branch (HEAD), or an existing local branch as the new chat's starting base. Local branches are listed newest commit first (furthest ahead); branches checked out by other chats' UAM worktrees are listed last and never preselected, so a new chat does not stack on another agent's live work. Entries that would repeat the default are omitted: the default branch itself, and the current branch when no default is configured or it is the default. The first completed read preselects the furthest-ahead branch and a separate helper line says so until the user picks a branch themselves; the configured default, or HEAD when no default is configured, stays selected when it points at the same commit. Refreshing never replaces the user's choice. Long branch labels wrap within the menu without widening it or shortening the saved ref. Choosing a branch preserves the workspace and does not check out a branch, create a worktree or start provider work; native preparation validates the saved choice at the existing send or CLI-launch gate and prepares isolation. A selected existing worktree keeps its current branch and is passed through without a base override. Changing workspace or execution context clears the prior branch choice; changing provider does not change its workspace choice.

Branch choice is optional and never blocks creation. Detached HEAD, an unborn repository, a repository with no readable branches and a failed branch read do not offer a Git base override, show no error or retry, and neither disable nor delay Create chat: the field shows one neutral line and the chat uses the configured default or current branch under the existing preparation policy. With automatic worktrees on, the first send in a repository with no commits starts from a UAM-owned snapshot baseline. A configured default branch that does not exist stops that send with a message naming the branch until the setting is cleared or the branch exists, and turning off plain-folder snapshots stops it with a message saying so; see [Git](../settings/version-control/git.md). No enabled Git repository and SVN also offer no override. Explicit base selection is unavailable for remote or automatically routed creation and when automatic worktrees are disabled. Where branches were listed, Refresh branches keeps keyboard focus during loading and completion, and a completed read does not pull focus back after the user moves elsewhere. Refresh keeps the chosen starting policy visible while loading; a refresh that cannot read branches keeps the list already shown, and a completed read that no longer contains the choice clears its override and visibly returns to the configured default.

## Create chat availability

A version check that failed, timed out or is still running does not show that a provider's CLI cannot run, so it never disables Create chat or turns the chat into a terminal chat; the dialog notes a failed check neutrally and launch applies its normal version gate. A failed check on this computer does not stop a launch; structured OpenCode and a named Gemini thinking level in Chat retry it first. The version then stays unknown, a named Gemini thinking level launches as Default and the chat says so, and OpenCode takes the version from its running process and stops before input if that process does not report a supported one. Over SSH, a failed check still stops a launch of structured OpenCode or a named Gemini thinking level with the check's error. Create chat is disabled only for a confirmed cause, such as a CLI confirmed missing, an incompatible version with no terminal fallback, an unavailable computer or a missing workspace, and the dialog footer names that cause beside the button.
