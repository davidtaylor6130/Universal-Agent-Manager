# HTML views

An HTML view is a self-contained page an agent publishes into the current turn: a chart, table, diagram, mockup or small interactive view shown as a sandboxed card in the conversation, above the agent's text reply. Every structured provider chat can publish one through the built-in [UAM tool connection](../providers/uam-tools.md) when UAM Control is enabled for the chat, locally or over SSH; the tool runs in UAM, not on the execution host.

## Publishing

`html_view_publish {title, html}` publishes one page into the active turn. The title is one line of at most 120 bytes; the page is a complete document of at most 131,072 bytes (128 KiB) with every style, script, image and data inlined. UAM rejects an empty page, a NUL byte, an oversized page or title, a request outside an active turn, a ninth view in the same turn and a CLI View session with an error the agent can read; a rejected request changes nothing. `html_view_preview {title, html}` publishes nothing and returns whether the page is publishable, its size, validation errors and warnings about content the sandbox will block, such as remote resources, network APIs, storage, frames loaded from a URL, forms and pop-ups. Both tools carry the read-only hint because they only add a display card to this chat's own transcript, bounded by the per-turn limit. The preview does not render the page or capture a screenshot.

## Sandbox

The card loads a UAM frame host in an `iframe` sandboxed with `allow-scripts` only, so the page has an opaque origin and no same-origin access to UAM. The frame host is served with its own policy: `default-src 'none'`, inline scripts and styles only, `data:`/`blob:` images, fonts and media, and no connections, frames loaded from a URL, workers, objects, form submission or base URL. An inline `srcdoc` child frame can still be created and inherits all of this. That policy does not cover WebRTC, `<link rel="preconnect">` or `<link rel="dns-prefetch">`, and this Chromium ignores the `webrtc` policy directive, so UAM natively removes `RTCPeerConnection`, `webkitRTCPeerConnection` and `RTCIceTransport` from every frame before its script runs and turns Chromium network prediction off. The page cannot reach the UAM bridge, app storage, cookies, the parent document or the file system, cannot open pop-ups or navigate the app, and cannot load anything from the network. The app's own policy allows framing only that host page, and the native bridge binds only in the trusted top-level UI document. Native navigation checks allow the main frame to load only the UI index and a subframe to load only the frame host; a blocked subframe navigation never opens the system browser. UAM sends the page text into the frame once and never accepts messages back; Chromium refuses every attempt by the page to reload or navigate its own frame, so the page stays in place. The page runs in a separate renderer process, so a script that never yields does not freeze the app; it holds one CPU core and blocks other HTML views from rendering until no view is on screen and that process ends.

## Card

The card shows the title, renders inline at a fixed height and scrolls inside the frame. Expand grows it to fill the pane and Collapse returns it. Copy HTML source copies the page exactly. On the desktop, Open in browser writes a copy to a temporary file with the same no-network policy placed before any page content (after a leading doctype only) and opens it with the system default browser; the policy blocks ordinary network requests there, but the WebRTC removal and the network prediction setting apply only inside UAM, so a page opened this way can still reach the network through them and can navigate its browser tab, including to remote sites, and Save as HTML file asks for a folder and writes the exact page under a name derived from the title, never overwriting an existing file and avoiding Windows device names such as `NUL`. Temporary copies older than 24 hours are deleted when a new copy is written. The frame follows the app's light or dark scheme through `color-scheme`; when Motion is Off or reduced motion is requested, CSS animations and transitions in the page stop. Changing the scheme or motion setting reloads the page so the change applies, and the page also reloads once when its turn ends and the live card is replaced by the saved one, so page script state does not survive either. Script-driven animation remains the page's own responsibility. Actions are labelled icon buttons reachable from the keyboard, and the frame itself is focusable.

## History

The page is saved as a dedicated `html_view` message block with its title and identity, in the position where it was published, reloads with the chat after restart and on remote chats, and stays when native history is synced, since native transcripts never contain it. It keeps its own message, else takes the first reply of its turn, the first later reply however many turns away, or the last earlier reply, never adding a row. A card moved off its turn does not return if its own reply appears later. While native has no reply at all, UAM keeps the local history and withholds the native rows. Local chat export carries the block with the rest of the saved chat. The [native iPhone client](../phone-native.md) and the [browser companion](../phone-browser.md) show the title with a "view on desktop" placeholder instead of rendering the page.

**Implementation: Needs verification.** Source routes for both tools, the stored block, the card, the frame host policy, the phone placeholder and the desktop actions exist with focused native and frontend tests, including the native navigation decision that lets the frame host load as a subframe. The sandbox isolation itself has no automated browser test; UI-V2 has no browser test tooling. A one-off headless Chromium probe on 2026-11-02, serving the frame host over HTTP with its policy header rather than through CEF's `uam://` scheme, found parent document, parent bridge, storage, cookie, top-navigation and `fetch` access all blocked. In the built macOS app with a separate data folder, Claude Code published views through `html_view_publish`, and the frame host loaded and the cards rendered, expanded and opened in the browser. A one-off probe in that app on 2026-11-05 (CEF 146, local listener only) saw STUN and TURN traffic and a preconnect connection reach the listener before the removal and none after, including from a `srcdoc` child frame; a local multicast DNS observer saw a `dns-prefetch` name queried with network prediction at its default and no query with it off. Live invocation by the other five providers, an installed release package, SSH chat reload, Windows, the iPhone build, DNS-only WebRTC lookups and visual acceptance remain unverified; the screenshot preview is not implemented.
