# Subagents

## Experience reference

David specified T3 alpha 0.1.0’s subagent experience on 2026-10-16 as the interaction reference for UAM. UAM should retain its own design language while providing the same parent/child workflow: a collapsible group in the parent turn shows the child count and aggregate progress, with a named row for every child showing its status and elapsed time. Opening a row displays that child’s full conversation and ongoing activity; a clear parent breadcrumb or “Subagent of” link returns to the originating chat. Related-chat lineage remains available in both directions, and each running child has an individual Stop control. Several children from one native tool must all be reachable rather than silently selecting the first.

## Thread cards

Each child appears in the parent thread as the compact T3 card David supplied on 2026-10-16: a small filled rounded rectangle with the actual provider icon on the left, title and status on the first line, one truncated summary line below, and time plus an opening chevron on the right. Working children use UAM’s blue dashed spinning circle; there is no green status dot, and finished children do not keep spinning. Preserve supported elapsed time and make missing timing explicit rather than estimating it from parent activity. Opening the card follows the same child-only navigation as All Chats.

## Catalogue and navigation

Child conversations use the same canonical conversation rendering as normal main-thread history: user and assistant blocks, Markdown and code, reasoning, tools, status, typography, spacing and normal disclosure behaviour. Child-only history, scoped read-only restrictions, the fixed parent return control and independent drafts remain intact; shared rendering grants no parent mutation or delivery authority. Collapsed traces retain recorded launch groups in their original message positions across main and child histories, with the same grouping and disclosure; absent child-safe scope cannot authorize new reads or controls. Shared source rendering and focused route regressions are implemented; composed builds, final Claude review, visual verification and user acceptance remain pending.

Child conversations have one fixed header with Back, parent context and title, plus child-scoped Refresh conversation on the right; there is no separate Close X or extra mode header. Back returns to the available parent, or uses the existing view-exit action as Back to chats when the parent is unavailable; an unavailable destination stays disabled without inventing a parent. The canonical transcript, message navigation rail and continuous earlier-history reading remain available, with independent child reading position and parent draft preservation. Eligible writable children open their existing input through Follow up rather than a standing composer; hiding input preserves its draft, resources and uncertain request, and does not send, retry or stop work. Existing permission, queue and recovery controls retain their authority boundaries. Open and Back use the shared motion preference, including an immediate reduced-motion or Motion Off path.

A distant message-rail mark reads a bounded page from that child’s own available history, without selecting another runtime, changing the parent’s search or borrowing its input authority. Reading in either direction preserves the visible message and position; Show latest returns to the actual end of the child’s history. Available messages remain readable when a read is refused or changes; recovery offers a valid explicit read retry or selection of an available child-rail mark. Returning to the parent and reopening the child never sends or replays input. A loaded history without a full-history catalogue retains its existing reading-position behaviour; missing catalogue evidence cannot authorize wider reads.

Subagent families in All Chats start collapsed per parent, with an explicit expand/collapse control; expanded children are ordinary single-line rows with a robot icon instead of the provider icon. Their bounded first-line or first-sentence title describes the task’s purpose, with the agent definition as secondary metadata and the existing fallback for a blank title. This title is presentation metadata: it grants no run existence, Open or Stop authority, which remain bound to the scoped child read. Collapse suppresses catalogue reads; reopening catches up without replaying a mutation. Children do not appear separately in Active Chats. Selecting a child shows only its conversation in the selected pane, with a fixed parent return control; returning preserves the parent’s draft, scroll position and pane. Reopening a child retains its own message page and reading position while refreshing available history, independently of other children and panes. The child inspector’s Refresh conversation action remains separate. Source is integrated; native compilation, fresh Claude Review, visual verification and user acceptance remain pending.

Sidebar and inline child lists update automatically within the selected parent’s scope, without a manual Refresh subagents control. Failed reads retain available rows as last reported without a working indicator, advancing clock or Stop control; automatic read-only recovery never relaunches work or repeats a control request. The child conversation inspector’s separate Refresh conversation action reloads that conversation without sending input.

## Launch placement

David clarified on 2026-10-19 that child activity belongs inline at its triggering launch tool call. Group only consecutive launch calls; intervening text, reasoning, plans, questions, permissions, result events and other tools preserve their positions. A completed delegation tool confirms acceptance, while the linked child’s separately reported state determines progress and outcome. Unanchored historical children remain reachable through the child catalogue; missing launch correlation does not authorize a permanent transcript-bottom list or guessing from titles, timestamps or nearby messages. Inline placement is source-implemented; wider native and visual verification, required Claude Review and user acceptance remain pending.

## Control and results

A child is delegated work linked to its parent, with its actual provider, model, execution host and workspace retained. UAM and the parent agent can create and inspect supported children, receive questions, activity and results, send follow-up work or messages, and stop the selected child through the supported runtime. The parent can continue independent work while children run; child completion and questions update the parent without requiring repeated manual polling. Opening a child preserves the parent’s draft, scroll position and selected pane, and follow-up work remains attached to the same child relationship rather than appearing as an unrelated conversation. Controls reflect the provider’s actual abilities and permissions; native children without a messaging or cancellation API expose that limitation clearly. Eligible children offer text follow-up in their own conversation. A lost submission response retains the original request and draft for explicit same-request retry; reads, returning to the parent and reopening a pane never resend it automatically.

## Active-turn result wait

A supported `agent_wait` read lets a still-active parent wait for one owned managed child instead of repeatedly asking for status. It returns the exact child status and result; a child still queued or running at the bounded wait slice returns `timedOut: true`, so the parent may explicitly wait again on that same run without delegating replacement work. Cancelling or losing the wait retires only that read, preserves the child, and does not start a parent turn. This cooperative route does not provide unsolicited wake after the parent turn has ended.

**Implementation: source integrated; canonical verification pending.** The source candidate has focused private native verification of an eight-second child result and cancellation/ownership controls; canonical verification, all-six-provider tool-call deadlines, native CLI View, live local/SSH behavior and acceptance remain pending. The semantic slice is 80 seconds; the proxy owns a separate 100-second cooperative transport budget with a bounded cancellation receipt attempt, which does not promise a hard wall-clock deadline across filesystem, scheduler or SSH delays. See [UAM tool connection](../providers/uam-tools.md) and the source-implemented [OpenCode app-server budget](../providers/opencode/opencode.md#uam-tool-deadline); provider-effective deadlines and acceptance remain separate.

## Same-live parent result continuation

An accepted direct-root delegation may return its bounded child result to the same still-live local Codex parent after the originating turn completes normally, without a manual status loop. This continues the original request with unchanged permissions and preserves the independent composer draft. Internal result input remains machine data when native history provides its exact saved turn and payload provenance; copied human text and unknown provenance remain readable user history. New human input takes priority; Stop, changed ownership, held input or uncertain storage/delivery prevent automatic continuation. Results can be coalesced, but synthetic continuations cannot create an endless chain of fresh parent turns.

**Implementation: source integrated; native verification pending.** The proposed route is limited to an existing local Codex structured session; it never starts, reconnects or restarts a parent, and saved intent cannot restore execution authority. Other providers, SSH, CLI View and recovery of uncertain input remain outside this candidate. The active-turn `agent_wait` contract remains separate and unchanged; broader native delivery and acceptance gaps remain open.

## Native boundaries

Provider-native subagents retain exact native identities and are distinct from UAM-managed delegated chats and user-created [side chats](../providers/side-chats.md). Missing correlation or transcript export must not produce invented child conversations or misleading control buttons. Read-only native journals can show the complete available transcript without being advertised as resumable or messageable. Saved activity is labelled as last reported rather than presented as current work; provider events without a conversation are counted separately. Loading, empty, failure, waiting, running, stopped and completed states remain explicit, keyboard accessible and consistent with [UAM interaction](../ui/interaction.md).

An already-owned writable local Antigravity conversation can open as a child using its exact native conversation identity, retain its own model and workspace, and accept follow-up through the existing native resume route. Its native display parent is separate from any saved message-branch ancestry. A missing or foreign-host conversation does not authorize creating an invented child transcript, and this route supplies no native journal exporter or control over the originally spawned child process.

Nested All Chats, child-only panes and fixed parent return are source-implemented with frontend unit verification, while durable native display links have focused native verification and still require complete bridge and platform verification. Compact thread cards are source-implemented with recorded managed timing and output summaries; their isolated packaged saved-card opening and parent-draft return are verified, with the deferred-result source correction reviewed by Claude; wider acceptance remains pending. Eligible local named-Claude UserRoot children and read-only named OpenAI Codex and GitHub Copilot UserRoot children have scoped text follow-up through the same native conversation within the current controller lifetime. The reference is the requested outcome, not evidence of delivery or David’s acceptance.

## Authored initial launches

For an initial named-agent request, show an owned managed child immediately after the authored user message that triggered it. An optional saved run-ID annotation is presentation correlation only: it cannot establish that a child exists or enable Open, Stop or a status. Only an exact run returned by the existing root-scoped managed list supplies that evidence. Invalid, unknown or unmatched annotations leave the authored message readable and unchanged. The existing unique authored-user remap preserves the annotation across native row regrouping only when the nonempty created-at value and authored content identify exactly one user row in each history. Older unannotated runs and ambiguous or replaced row identities remain unbound with Sidebar catalogue fallback; do not infer placement from names or nearby messages or add a permanent bottom group.
