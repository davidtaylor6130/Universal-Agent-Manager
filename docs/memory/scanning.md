# Memory scans

A manual memory scan lets the user select saved conversations as candidates for extraction; it is separate from normal background extraction and from merely browsing the library. Memory settings opens the chooser with Scan chats under Memory defaults. Show eligible scope, selection, progress, cancellation and partial failure without starting provider work on behalf of unselected chats. A failed eligible-chat list, or one with no answer after 30 seconds, is shown in the chooser as a load failure with Try again, not as an empty list or a scan that did not run; a list reply for a chooser that was closed or reopened is ignored. Starting the scan is not retried automatically. Results must pass the current memory policy, destination ownership and content validation before publication. Retrying a scan must not overwrite user-authored memories or duplicate already accepted output, and cancellation must not be presented as successful completion.

A scan must prepare its complete selected input before starting extraction; it must not silently replace a requested range with a shorter tail or advance progress after incomplete preparation. If the input exceeds supported memory limits or cannot be read safely, report the failure and retain the scan intent and previous progress. Saved conversations, queued input and recovery records remain unchanged. An unexpected failure while reading saved history or processing worker output stops only that chat's extraction the same way and must not end the app; the developer log records a bounded reason without raw worker or remote error text. Large-history extraction beyond the current input limit remains an implementation gap, not a successful empty result.

Background extraction, including the step that records a chat's new messages as needing no extraction, waits while that chat has a turn in progress. A turn whose provider is still being started counts: memory must not record progress for a message the provider has not received, and its bookkeeping must not make the launch give the message back as unsent.

A worker that keeps running after repeated provider failures, such as OpenCode retrying a usage or rate limit, is stopped at once and counted as that failure rather than waiting out the worker timeout. A worker failure pauses background extraction for 30 seconds to five minutes only for that execution host and worker provider. Chats on another host or provider keep extracting. A manual scan clears the pause for the host and provider of each chat it selects, so other chats sharing that pair can retry too.
