# Workspace-folder recovery

Rebuild workspace folders reviews saved chats and their known workspace/host identities to reconstruct missing catalogue grouping without inventing directories or changing provider working paths. Preview ready groups separately from chats needing attention, and allow deliberate recovery only against current saved state. A chat whose saved workspace ID matches no saved workspace is Unsorted, exactly like a chat with no workspace: All Chats lists it there and this recovery can regroup it, and showing it never rewrites the chat's saved ID. Startup writes one diagnostic line with the number of such chats and their missing workspace IDs, without paths or titles. Recovery and the startup split of mixed-machine workspaces save the workspace list before the chats they move, so stopping between or during those writes never leaves a saved chat naming a workspace that was not saved; the next run reuses the workspace already saved. If chats cannot all be saved, recovery puts back the ones that moved and keeps any workspace a chat still names. Copying an earlier release's data also saves its workspaces before its chats and copies no chats when that save fails. Missing/unavailable workspaces remain visible as problems; deleting unavailable chats is a separate explicit destructive choice, not a side effect of recovery. Removing a workspace entry and its chats must describe that scope while leaving the user's actual directory on disk unless a different supported owned-worktree action was explicitly requested.
