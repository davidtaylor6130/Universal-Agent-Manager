# Workspaces

A workspace identifies the files a chat works on, on the local computer or a selected execution environment. Its display folder, actual working directory, repository identity and optional managed worktree must remain distinct. UAM may prepare isolated work when explicitly configured, but side chats and conversation branches do not automatically request a new worktree. Source files and user-owned branches survive failed preparation, switching and cleanup.

A managed worktree must stay on its own branch. When it was switched to another branch or a detached HEAD, for example by the agent, opening or resuming the chat stops with an error that names the folder, the current and the expected branch, and the `git switch` that restores it. UAM does not adopt the other branch, because worktree cleanup removes the worktree's own branch. **Implementation: Partial.** SSH worktrees report this, with a native test against a stand-in SSH helper on macOS and Linux; local worktrees and a live SSH host are not checked. Stop always works: a turn restored after a restart whose worktree fails this check is stopped on the host without validating the workspace, which a native test covers; the next send reports the branch error until it is restored. Until it is stopped or the branch is restored, the restored turn keeps its recovery.

[Native history import](../settings/chat-data.md#native-provider-histories) can stage an unregistered local source workspace for explicit review. Assignment names its original path without relocating history or creating directories; only selected import publishes the UAM workspace definition through the guarded folder-save path.

Parent Port back (Patch) and Discard may clean up a shared managed-worktree family only when exact managed-run lineage and transcript identity establish ownership and every captured UAM execution, input, save, stop and recovery claim has settled. Terminal run status alone does not establish settlement: a retained child runtime must complete ordinary Stop. The operation fences the parent and admitted children against delegation and input until completion, checks saved identities and revisions again before cleanup, and preserves child history and native session bindings. A finished child whose run record has expired joins the family by its [saved root link](../chat/subagents.md#saved-root-link) on the same terms, including a v2 child, since no follow-up authority outlives its record. Unrelated references, and children saved without that link, still block cleanup; this admission does not apply to branch switching, unused-branch removal or rollback. **Implementation: Partial, verification and acceptance pending.** The local candidate covers v1 managed descendants, including one nested level. V2 native follow-up families whose run records remain are still refused because their retained follow-up authority needs a separate retirement transaction; cleanup never rebinds that history to the source workspace. Absence of current UAM execution authority makes no claim about all OS processes.

Git cleanup and chat saving are separate steps. A known failure to retain the original saved association refuses worktree and branch removal. Until cleanup finishes, the saved isolation association remains the recovery record. Cancellation or a failed final save can therefore leave a missing worktree or an already deleted owned branch with that association still present; an explicit Discard can finish the remaining cleanup. Inspect source changes before retrying Port back, since a patch may already have been applied. A metadata commit that was acknowledged before query withdrawal still updates the same live conversation's workspace fields; it never updates a replacement conversation. A managed snapshot repository is retired only after that commit, using the existing retention tombstone route. These recovery paths remain unverified in the local candidate.

An SSH chat revalidates its saved worktree once per UAM session, since a helper reinstall or host reboot can change the remote checkout. Revalidation and creation refuse while another chat still uses the worktree, and the error names those chats. A delegated child of the same chat does not count once its run ledger shows it finished and it holds no queued input, runtime, save or helper process. Once that child's run record has [expired](../chat/subagents.md#results-across-restart), the [root link saved at its birth](../chat/subagents.md#saved-root-link) stands in for the ledger, but only when the ledger read itself was complete. Unknown, active or unrelated chats still refuse, as does a child saved before that link existed whose run record has expired. Remote preparation is cancelled after five minutes without an answer from the helper and reports a retryable error. Input held during preparation shows that preparation's failure or readiness, never an indefinite wait. **Implementation: Needs verification.** Focused native tests cover these paths; live SSH, host-reboot verification and David's acceptance remain pending.
